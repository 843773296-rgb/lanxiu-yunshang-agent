# 再做一个知识库

- **谁提的**:业务(2026-09-16)
- **什么时候**:2026-09-16

- **要解决什么**:

  ⚠️ **这一栏现在填不完整,因为「哪一类知识库」还没定** —— 见下面那道待定题。
  先把它登记下来,**不替业务猜**:猜错的话做出来的是一套没人用的文档,
  而它和一套有用的在目录里长得一模一样。

  现有的这套(`knowledge/` 12 篇 + README)是**工艺知识库**:
  形制、面料、工艺、配饰、颜色、相容矩阵、工期成本、量体版型、养护售后、
  版型库、物料 BOM、成长生命周期。它的特点是:

  - **结构化**(有编号、有条目、有表格),所以用的是**结构化查询 + 白名单读正文**,
    不是向量检索 —— 这个选择在第 12 版报告里核过,是对的
  - 每条带**来源等级**(public / scale / demo),而且有检查盯着
    「声称可溯源的,得真的溯得了源」
  - **被引用**:相容矩阵接进了 `kb_combo`、工期接进了 `kb_lead`、
    售后判定表接进了 `liability.judge` —— **一份没被引用的知识库 = 一份不存在的知识库**

- **做哪一类:2026-09-16 业务定了 —— 四个都做**,已拆成四份独立 intent:

  | | 知识库 | 谁写内容 | 文件 |
  |---|---|---|---|
  | A | 销售话术 | **业务**(我搭结构和工具) | `intent/kb-a-sales-script.md` |
  | B | 运营 SOP | **我**(大部分已在代码里,抽出来) | `intent/kb-b-ops-sop.md` |
  | C | 电商运营 | 行业做法我写(标 demo),**决定业务给** | `intent/kb-c-ecommerce.md` |
  | D | 竞品与行业 | 我查,**边界要 A/C 先定** | `intent/kb-d-competitor.md` |
  | **E** | **把现有知识库扩容到 20 万 token** | 业务 + **版师本人** | `intent/kb-e-staff-training.md` |

  ⚠️ **E 不是新建一份,是扩容现有的那 13 篇。**
  我第一版理解成「另建一个讲解层引用现有事实层」,**业务当场纠正**。
  纠正得对:再建一份就是**同一个事实两份**,而这个项目为
  「同一个事实两个来源」栽过好几次 —— 改一份不改另一份就开始漂,且漂了不报错。

  **拆成四份而不是一份**,理由:它们的读者、格式、谁来写完全不同。
  合成一条的话它会变成一个**永远做不完的条目** ——
  而一个永远做不完的待办,和一个没人做的待办,在清单上长得一模一样。

  ⚠️ **建议的顺序是 B → E → C → D → A**,理由不是重要性,是**能不能接进工具**:
  E 排第二是因为它扩的是**已经接好线的那个库**(相容矩阵、工期、判定表都在被工具读),
  扩进去的内容天然就有出口;
  B 的内容已经在项目里(抽出来就行),C 有现成的接口等着它(补货点、渠道口径),
  D 是 A 和 C 的原料,而 **A 的内容一个字都不在项目里**,等业务给。

- **明确不做什么**(这几条和方向无关,先定下来):

  - **不做成一份没被引用的文档。** 现有知识库的价值全在「它被工具读」——
    相容矩阵接进了 `kb_combo`、判定表接进了 `judge`。
    **新知识库必须同时回答「哪个工具会读它」**,答不上来就先别建。
  - **不用向量检索**,除非新知识库真的是**散文形态**。
    现有这套是结构化的,所以走结构化查询 —— 「**不该用 RAG 的地方用了 RAG**」
    是这一层最常见的错。
  - **不许没有来源等级。** 每一条都要标 public / scale / demo,
    而且 `backend/source_check.py` 会立刻把新欠的账算进去
    (现在溯不了源的上限是 39,**只许降不许涨**)。
  - **不许和现有 12 篇重叠。** 重叠的两份知识,改一份不改另一份就开始漂,
    而漂了不报错。

- **怎么算做完**:

  ① 选定方向,并在这份文件里写明**为什么是它、不是另外三个**
  ② 至少一个工具会读它,而且那个工具进了 `SHOP_SCHEMAS` / `KB_SCHEMAS`
  ③ 每条带来源等级,`backend/source_check.py` 的欠账上限**没有涨**
  ④ 有一道评测题覆盖「模型该引用这份知识而不是自己编」

- **状态**:`进行中` —— 方向定了(四个都做),已拆成四份。
  这份文件从此是**总纲**:管四条共用约束和顺序,不管具体哪一份的进度。
