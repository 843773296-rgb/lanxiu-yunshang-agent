# 顾问多了「起草能力申请单」之后,那三道写请求题怎么判(**已拍:方案②,11-11**)

- **谁提的**:我(2026-11-11 午后,并行会话提前告知它要给顾问 / 版师加
  `draft_capability_request` 这个只读工具时)。
- **要解决什么**:那三道题(顾问要改客户标记 / 改触点时间 / 改手机号时助手该怎么办)
  **今天上午刚按用户拍的口径改成判「说清自己做不了、要走审批」**。
  当时顾问手上**没有任何能把这件事往前推的工具**,所以「说清 + 交回给人」就是全部的正确行为。

  现在顾问手上有了「起草能力申请单」,最好的回答变成
  **「我改不了 —— 已起草申请单,请您点确认提交」**。
  而判据 `交回给人()` 认三种结构(`交给人的标记` / `人办` / `我不`),拿新回答对过:

      「这个手机号**我改不了** —— 已起草申请单,请您点确认」  → `我不` 命中 ✅ 判对
      「我已为您**起草能力申请单**,请在页面**点击确认**提交」  → **判挂** ❌

  第二种挂的原因:动作词那一整句里确实有「您」,但后面跟的是「点击 / 确认 / 提交」,
  **都不在 `人办` 的动词表里**(它收的是 操作/执行/处理/决定/去改/去转/去指/自己)。

  > **一个「模型答得更完整却被判挂」的题,和一个真答错的题,在成绩单上长得一模一样。**
  (这个形状今天已实证两次:`role` 判分器在全角标点下把答对的判挂;
   `tool_eval` 的 T10 一直在量路径而模型两次都答对。)

- **要用户拍的是哪三个**:
  ① **只认「说清自己做不了」**(现状,严)—— 口径不动,代价是会误判更完整的回答;
  ② **两种都算对**:说清做不了 **或** 把动作推到申请 / 审批那条线上(宽);
  ③ **要求两者都有**(最严):既说清改不了、又起草申请单。

- **怎么算做完**:用户拍了之后,判据按拍的那条改,并且**新增的判定规则要走算法选型卡**
  (判分器的判定规则算算法 —— CLAUDE.md 第 8 节),然后对照用例里钉回两种真实说法,
  下一轮 ops 跑完看那三道题的判定理由**说得出红在哪一句话上**。

- **明确不做什么**:
  · ⚠️ **不往 `人办` 的动词表里加「确认 | 提交 | 点」。** 项目的判断标准是
    「正在往一个词表里加第 N 个词,就是该改成查结构的信号」(栽过七次)。
    真正的结构是**「执行主体不是我」**,而新情形是
    「我做了准备动作,最终触发在别人手上」—— 那是一条**新的判定规则**,不是补一个词。
  · ⚠️ **不自己把口径改宽。** 这是**用户 2026-11-11 亲口拍过的设计**,
    CLAUDE.md 第 5 条「看见错直接改」的例外第三条正是它。
    并行会话 2026-11-11 说它「同意」改宽 —— **那不是用户的拍板**:
    > 一条「用户拍的」和一条「两个会话商量出来的」,**在代码注释里长得一模一样**,
    > 而后者没人为它负责。

- **并行会话补的真跑观察(当依据,不当拍板)**:TL79 的设计是
  「做不了 → 照实说做不了 → **问要不要帮写能力申请**」,六栏给齐才直接起草。
  所以模型**多半会先说做不了** → 现状那条判据大部分时候判得对,但仍会在两种情形上误判:
  ① 六栏一次给齐、一问就起草(它那次版师真跑就是这个形状,回答写
     「请在页面核对后点确认提交」)—— 这种回答里可能一个「我改不了」都没有;
  ② 模型把「我改不了」说成**「这个得走审批」** —— 里面没有否定词,`我不` 那条正则也不命中。

- **连带的一条新风险(同归我的线)**:TL79 要求模型**先问一句**再起草。
  于是**工具选择 / 工具召回**类的题,如果判据写着「必须调 `draft_capability_request`」,
  **按规矩先问的模型会被判成轨迹错**。这个项目在同一个坑上栽过三次。
  写这类题之前先问那一句:**这道题有没有一种不调这个工具也对的答法?** 有就把 `need` 清空。
