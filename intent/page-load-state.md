# 管理后台切页:看得出在载入、失败说清原因、不把旧页当新页

- **谁提的**:外部复审(10-19 V2 第 3.5 节「页面加载与服务可用状态需要明确」,现场看到「路由已切而内容仍旧」);
  用户 2026-10-22 晚把一整晚交给主会话,排在今晚第一段
- **什么时候**:2026-10-22
- **要解决什么**:管理后台切页时先改地址栏、再等接口、回来才换内容。等的时候旧页原样摆着;
  接口报错或服务关了,旧页一直留着而地址栏已是新页;连点两页,先点的慢页后回来会盖掉后点那页
  (复现到:地址栏「丙」、内容「乙」)。员工会把上一页的数当成这一页的。
- **怎么算做完**:一点下去旧内容变淡、点不动,300 毫秒还没回就换成「正在载入「某页」…」;
  失败时标明哪一页没载入、分五类说原因(连不上 / 没响应 / 接口报错 / 不是数据 / 页面脚本出错),给重试;
  连点时只认最后一次;30 秒不回算没响应。判据 `backend/page_load_check.mjs` 进门禁(7 种形状 + 对照)。
- **明确不做什么**:不自动重启服务、不清理任何数据(复审验收原话);
  复审同一节后半句「维护入口显示各服务、索引和执行器是否可用及运行版本」**这次没做** ——
  那是一个新入口,要先定放在哪一页、给谁看,归用户挑;智能运维平台(:8770)的页面这次没动。
- **状态**:`做完了` —— 2026-10-22 修前 14 条判据红 11 条(三种现象全复现),修后 14/14;咬合 3 条
  (取数口不看序号 → 红在连点;失败不接 → 红在服务关了;不标载入中 → 红在慢响应)。
