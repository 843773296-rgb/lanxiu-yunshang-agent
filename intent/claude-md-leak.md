# 项目的 CLAUDE.md 不该进产品里那个 agent 的系统提示词

- **谁提的**:我(2026-09-14,跑版师评测时看见模型在答案里引用《CLAUDE.md》)
- **什么时候**:2026-09-14
- **要解决什么**:CLI 从工作目录一路往上找 CLAUDE.md 当项目记忆,而工作目录
  在项目里 —— 那份**工程手册**(安全红线的描述、密钥文件路径、踩过的坑)
  整份进了提示词。两个代价:**评测会失真**(它可以从手册里答题而不是从知识库,
  铁律 TL01「只说知识库里查到的」被架空)、内部信息暴露给模型。
  不是推断,是问出来的:它答「有」并抄出了第一行。
- **怎么算做完**:`backend/boundary_audit.py` 里的 `a_no_project_memory` 攻击 ——
  从运行目录一路走到根,撞见任何 CLAUDE.md 就算破;
  **反面也测**(`.claude/skills` 没了算「隔离住了但 Skill 也没了」)。
  另有 `skills_check.py` 盯着「放开 project 设置源时这个前提还在不在」。
- **明确不做什么**:**不靠关掉 `setting_sources` 来解决。** 那条实测泄露也没了,
  **但 Skill 跟着一起没了** —— 同一句报价问题,设 project 时轨迹里有 `Skill`,
  设空时没有。换成把工作目录挪出项目,两头都拿到。
- **状态**:`做完了`(2026-09-15)。从边界审计的【约定】挪进了【结构】。
