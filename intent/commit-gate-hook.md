# 门禁红着也能提交成功,要有一道机器闸

- **谁提的**:我(2026-09-16),业务当天问「有没有能总结出项目经验的 skill 和 hook」后拍板「做吧」
- **什么时候**:2026-09-16
- **要解决什么**:同一个错在一天里犯了两次 ——

  ```
  ./check.sh | tail -2 && git commit -m "..."
  ```

  管道的退出码来自 `tail`(永远是 0),不是 `check.sh`。于是**门禁红着,提交照样落盘**,
  而屏幕上还印着「❌ 3 项失败」。这属于这个项目反复栽的那一类:
  **两个必须触发相反动作的状态,在表示上一模一样** —— 「门禁绿了」和
  「门禁的退出码被换掉了」,在 `&&` 看来是同一件事。
  人自己看不住:它不报错、不崩溃,失败的那一次和成功的那一次长得完全一样。

- **怎么算做完**:`~/.claude/hooks/commit-gate-exitcode.mjs` 装上并注册进
  `~/.claude/settings.json` 的 `PreToolUse`/`Bash`;拿真 stdin 验过会拦;
  **咬合测试能让它变红**(故意改坏放行判据、改坏 heredoc 剥离、白名单丢掉一项,三条都红)。
  仓库留一份带说明的拷贝在 `tools/hooks/`,并且**那份拷贝的自测进门禁** ——
  `check.sh` 里的「提交闸 · 退出码不许被吞」跑 `tools/hooks/commit-gate-exitcode.mjs --selftest`。
  不进门禁的话那 22 条用例会慢慢烂掉,而**烂掉的样子和好着的样子一模一样**。

- **明确不做什么**:
  - **不禁止管道。** 判据要贴着含义:禁的是「用一个命令的成败当另一个命令的通行证」,
    不是「命令里有管道」。按字面拦会把 `./check.sh | tail -2`(只想看结果、根本没提交)
    也拦下来 —— **而一道会误拦的闸迟早被人关掉,关掉之后它挡的那些错会一起回来**。
  - **不拦裸的 `git commit`。** 门禁可能在上一次工具调用里跑过了,这道闸无从知道。
    宁可漏,不可误。
  - **它自己出错时放行**(fail open)。它防的是手滑,不是攻击者。

- **状态**:`做完了`(2026-09-16)—— 22 条咬合用例(8 拦 / 14 放,其中 6 条专门防误拦)。
  ⚠️ **上线当天它误拦了我一次**:`python3 - <<'PY' ... PY` 里的门禁名和提交命令全在
  heredoc 正文里,是喂给 python 的数据,bash 一个字都不执行 —— 判据读的是命令的字面文本,
  分不出「会被执行的代码」和「作为数据传下去的文本」,**又是它自己要拦的那类错**。
  已改成先剥 heredoc 再判(没有绕过它,是把它修对)。
  另外自测本身两次「整段没跑却退出 0」(相对路径调用、`/tmp` 软链),
  见 [[break-check-skill]] 的第三问。
