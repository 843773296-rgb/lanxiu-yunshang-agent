# intent/ —— 动手之前先把要解决的事写下来

一件事一份文件。**在写代码之前写,不是做完之后补。**

## 为什么加这个目录

2026-09-15 读 Anthropic 的《AI-Native SDLC Playbook》之后建的。
那篇文章的六个阶段里,这个项目**有四个半**:`CLAUDE.md`、Hook、测试反馈循环、
Evals、咬合测试(还比它多一层)。**缺的恰好是最前面那一份。**

而账单是现成的 —— 就在建这个目录的前两天:

| 事故 | 次数 | 根因 |
|---|---|---|
| **题面不自洽** —— 问「该不该退」却没给单号;让改某版型的袖片,而那版型根本没有袖片;问童款却不说是哪个版型 | **4 次** | 动手前没把「要解决什么、边界在哪」定下来 |
| 「22 个形制没录」这条待办在交接文档里挂了很久,**而它早已清零** | 1 次 | 没有一份文件写「这件事怎么算做完」 |
| 「做知识库」要摆四个选项给业务挑才知道做什么 | 1 次 | 正是这份文件该回答的 |

> **代码写得快之后,瓶颈就搬到了前后两头。**
> 这个项目尤其明显:业务方不读代码,所以**审查这一环没有第二双眼睛** ——
> 那就只能把判断前移到「内容还少、他读得懂」的时候。

## 六个字段,一个都不许省

```markdown
# <一句话:要解决什么>

- **谁提的**:
- **什么时候**:
- **要解决什么**:写**问题**,不写方案。写成方案的话,
  下一个人只能照着做,没法判断这个方案还对不对
- **怎么算做完**:**必须是能验的**。最好直接写一条检查的名字
  (`check.sh` 里那一行),或者一个能从库里现读的数
- **明确不做什么**:以及**为什么不做**
- **状态**:`进行中` / `做完了` / `等人的活` / `已否决`
```

### 「明确不做」为什么单独占一栏

**这一栏是这份模板里最值钱的。**

「还没做」和「决定不做」**在代码里长得一模一样**,而它们该触发的动作正好相反:
前者是欠着一件事,下一个人该去补;后者是已经拍过板,下一个人不该去碰。

这个项目已经有好几条「决定不做」,而它们原来**散在代码注释里**,
没有任何地方能把它们列全:

- 外层部位不细分(业务原话「维持可选,客户自己挑」)
- 特体修版量不替它猜(等版师给)
- 童装档差表不替它编(等版师给)
- 会员升档的积分门槛「这条没定义」,不替它猜

> **编一个出来,就是假装业务拍过板。**

## 「怎么算做完」为什么必须能验

`tools/intent_check.py` 会去核它:状态写着 `做完了` 的,
判据里点名的那条检查得真的在 `check.sh` 里。

不核的话会出现两种漂移,而且**两种都不报错**:

- **做完了却还挂着** —— 交接文档里那条「22 个形制没录」就是,它早就清零了
- **挂着其实早做完了** —— 同一件事的另一面,下一个人会重做一遍

## 和交接文档的关系

`HANDOFF.md`「没做完的」里**每一条都要点名一个 intent**(写成 `[intent: 名字]`),
检查会核那个文件在不在。

交接文档回答「现在停在哪」,intent 回答「这件事本身是什么」——
**前者会随时间变,后者不该变**。混在一起的下场是:一件事做完之后,
它的来龙去脉跟着那条待办一起被删掉了。
