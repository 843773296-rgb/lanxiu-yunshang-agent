# 知识库 D:竞品与行业 —— 「别人家怎么做的」

- **谁提的**:业务(2026-09-16,「abcd 都做」)
- **什么时候**:2026-09-16

- **要解决什么**:

  完全空白。而它和另外三份的关系是:**它是 A 和 C 的原料**。

  - 话术里的「别家更便宜怎么答」——**要先知道别家什么价**
  - 电商运营里的「行业通行做法」——**那就是这一份**

  ⚠️ **这一份最容易做成一堆没人看的资料**,所以它的判据要比别的更硬:
  **说不清「哪个工具会读它」,就一条都别录。**

- **明确不做什么**:

  - **不许把二手文章当一手。** 每条必须标来源和抓取日期 ——
    **一条没有日期的行业数据,和一条编的,在文档里长得一模一样**
    (行业数据会过期,而过期不报错)。
  - **不做竞品价格的实时抓取。** 那是另一件事(要维护、会被封、会失效),
    而且**一个停止更新的实时数据源,比没有更危险**:它看起来是新的。
  - **不许拿竞品信息去替业务做定价决定。** 知道别人卖多少 ≠ 我们该卖多少。
- **明确不做什么**(四份知识库共用的四条,`intent/second-knowledge-base.md` 里定的):

  - **不做成一份没被引用的文档。** 现有 12 篇的价值全在「**它被工具读**」——
    相容矩阵接进了 `kb_combo`、判定表接进了 `liability.judge`。
    **答不出「哪个工具会读它」就先别建。**
  - **不用向量检索**,除非这一份真的是**散文形态**。
    「不该用 RAG 的地方用了 RAG」是这一层最常见的错。
  - **不许没有来源等级。** 每条标 public / scale / demo,
    而 `backend/source_check.py` 的欠账上限(39)**只许降不许涨**。
  - **不许和现有 12 篇重叠。** 重叠的两份知识,改一份不改另一份就开始漂,
    **而漂了不报错**。

- **怎么算做完**:

  ① 每条带**来源链接 + 抓取日期**,而且 `tools/verify_sources.py` 核得过
  ② 至少被 A 或 C 引用 —— **它是原料,自己不是成品**
  ③ 有一条检查盯着「**超过 N 个月没更新的条目要自己说出来**」
     (N 由业务定,**不许我编**)

- **状态**:`等人的活` —— **要先定 A 和 C 需要什么,否则这一份没有边界**。
