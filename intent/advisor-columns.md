# 把 `*.advisor` 那七列真正删掉

- **谁提的**:我(做「主数据被引用了没有」那一轮时列出来的)
- **要解决什么**:那七列存的是**顾问的名字**,而名字是别处的事实的副本。
  现在工号是引用、名字是**有检查盯着的缓存** —— 缓存和真相长得一样,
  而漂了不报错。
- **怎么算做完**:`backend/advisor_ref_check.py` 从 check.sh 里**撤掉**
  (它是为这次迁移临时顶着的),同时页面改成 join staff 取名字。

  门禁里盯着它的三条:`backend/advisor_name_check.py`(页面上那一栏有没有名字、
  对不对得上)、`backend/advisor_write_check.py`(写了名字列的 INSERT
  有没有一起写工号)、`backend/page_smoke_check.py`(**每个详情页拿真数据真跑一遍**)。

  ⚠️ 第三条是 2026-09-17 补的,因为前两条都漏了同一类东西:
  **它们查的是「名字对不对」,而漏掉的读点是「页面根本打不开」。**
- **明确不做什么**:**不在页面改完之前删列** —— 删了页面会静默显示空名字。
- **状态**:`做完了`(2026-09-17)。

  删列是 09-16 做的,但**当时没做完** —— 读的一侧漏了四处,而门禁 99 步 + CI 全绿,
  一天多都没人发现。09-17 才补齐:

  | 漏的地方 | 怎么炸的 |
  |---|---|
  | `measure_of`(客户详情) | `v[0]["measured_by"]` → `KeyError` |
  | `aftersale_detail` | SQL 里点名了已删的 `advisor` 列 → `no such column` |
  | `maintain_detail` | 同上 |
  | `appt_detail` | SQL 用 `a.*` **不报错**,取值时才 `KeyError` —— 同一根因,两种长相 |

  ⚠️ **为什么没被发现:`route_check` 只静态查过「这个 handler 存在」,
  而从来没有一条检查真的调用过这九个详情页函数。**
  「handler 存在」和「handler 跑得起来」是两件事,在代码里长得一模一样 ——
  这个项目最贵的那类故障,这次换了个地方出现。
  补的网是 `backend/page_smoke_check.py`,连同「那张对照表自己也要被查」一起。
