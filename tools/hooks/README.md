# 两道 hook:一道拦,一道报

装在 `~/.claude/hooks/`,在 `~/.claude/settings.json` 里注册。仓库里这份是版本管理的副本。
两道的自测都进了 `check.sh`,不进门禁的话用例会慢慢烂掉,**而烂掉的样子和好着的样子一模一样**。

| 文件 | 事件 | 干什么 | 拦不拦 |
|---|---|---|---|
| `commit-gate-exitcode.mjs` | `PreToolUse` / `Bash` | 提交前门禁的退出码不许被吞掉 | **拦** |
| `push-then-ci.mjs` | `PostToolUse` / `Bash` | push 完把 CI 结果推到眼前 | 不拦,只说话 |

---

## 一、`commit-gate-exitcode.mjs` —— 退出码不许被吞掉

### 它拦什么

2026-09-16,同一个错在这个项目里犯了两次:

```
./check.sh | tail -2 && git commit -m "..."
```

管道的退出码来自 `tail`(永远是 0),不是 `check.sh`。于是**门禁红着,提交照样成功**。
屏幕上印着 `❌ 3 项失败`,而提交已经落盘了 —— 这是这个项目反复遇到的那类故障:
**两个必须触发相反动作的状态,在表示上一模一样**。

### 判据贴着含义,不贴着字面

| 判据 | 后果 |
|---|---|
| ❌ 「命令里有没有管道」 | `./check.sh \| tail -2`(只想看结果,没提交)也被拦 → **误拦** → 闸被关掉 |
| ✅ 「门禁的退出码到不到得了 commit」 | 只在同一条命令里既有门禁、又有 commit、且通行证断了时才拦 |

落到 bash 语义上,看门禁后面**第一个**控制符:

| 形状 | 退出码是谁的 | 判定 |
|---|---|---|
| `门禁 && git commit` | 门禁自己的 | 放行 |
| `门禁 \| tail && git commit` | `tail` 的 | **拦** |
| `门禁 ; git commit` | 丢了 | **拦** |
| `门禁 \|\| true && git commit` | 咽下去了 | **拦** |
| `门禁 \|\| exit 1 ; git commit` | 用上了 | 放行 |
| `if 门禁; then git commit; fi` | 用上了(那个 `;` 是语法) | 放行 |
| `set -o pipefail; 门禁 \| tail && git commit` | 管道会传失败 | 放行 |
| `门禁; rc=$?; [ $rc -eq 0 ] && git commit` | 显式接住了 | 放行 |

**宁可漏,不可误**,三处故意不拦:

- 只有 `git commit` 没有门禁 —— 门禁可能在上一次工具调用里跑过了,这道闸无从知道。
- 只有门禁没有 commit —— 看日志是正当的。
- **heredoc 正文里的内容** —— 那是喂给别的程序的数据,bash 一个字都不执行。
  上线当天它就误拦了一条 `python3 - <<'PY' ... PY`。现在先 `stripHeredocs()` 再判。

### 已知的取舍(明着选的)

- `verdict()` 返回 `null` 同时表示「查过了,通行证是通的」和「这个形状我不认识」。
  动作相同(都放行),但**不认识的形状会被静默放过**。收紧就得记日志,那会给 hook
  加一条写文件的失败路径 —— 权衡后没加,写在这里免得它隐形。
- `GATES` 是白名单,必然有漏。目前:`check.sh`、`scan_secrets.sh`、`rebuild.sh`、`pytest`、`*_check.py`。
  加名字前先问:**这个命令的退出码,是不是真的「该不该提交」的判据**。

## 二、`push-then-ci.mjs` —— push 完把 CI 结果推到眼前

### 它报什么

2026-09-17 查出来:GitHub Actions 的 `check` 工作流**连续 30 次全红,一次都没绿过**,
而我一路在说「门禁全绿」—— 说的都是本地。

根因是 CI 的建库那步手抄了配方(只跑 `seed.py`),而配方早已是 5 步。
**本地那份库早就有那两张表,没人会删了重建;CI 每次从零建,所以只有它看得见。**

> **「我跑过了」和「它在别处也跑得起来」是两件事,在开发机上长得一模一样。**

⚠️ 关键在于:这个缺口**不是「不知道怎么修」,是那 30 次红到不了眼前**。
机器补得住的正是后者 —— 所以这道 hook 做的是「把结果送过来」,不是「教怎么修」。

### 什么时候出声

四条全满足才说话,少一条就闭嘴:

1. 命令里真的有 `git push`(heredoc 里的不算 —— 复用上面那道 hook 的 `stripHeredocs`,不抄第二份)
2. push 看起来成功了(没有 `fatal:` / `rejected` / `Everything up-to-date`)
3. 这个仓库真的配了 CI(`.github/workflows/` 下有 yml)
4. 本机有 `gh` 且登录着

**没有 CI 的仓库从不出声。** 一个在不相干的地方反复说话的提醒,迟早被人关掉,
关掉之后它要提醒的那件事一起没了。

### 报的是「现在红绿」,不是「历史红过几次」

第一版这里数的是回看窗口里的失败次数,于是**刚把 CI 修绿的那一刻,它照样报警**,
而同一段话里写着「当前连红 0 次」—— 自相矛盾。那是误报。

现在:最新一次完成的运行是什么结论,现在就是什么状态。

- 绿 → 一行:`上一次是绿的(最近 8 次里红过 7 次,最新这次已经绿了)`,附一条等本次结果的命令
- 红 → 报警:连红几次、最近一次绿是什么时候、**本地从零复现的三行办法**

那三行办法写在报警里而不是做成一份文档,因为**它只在这一刻有用** ——
一份要人记得去加载的文档,和这次栽的跟头是同一个病。

自己出错一律闭嘴(fail silent)。它是提醒不是闸:坏了最多回到今天之前的样子,
而一个会乱报的提醒比没有更糟。

## 咬合测试

```
node tools/hooks/commit-gate-exitcode.mjs --selftest    # 22 条
node tools/hooks/push-then-ci.mjs        --selftest     # 18 条
```

两个都在 `check.sh` 里。**改完判据必须重跑**,而且要**故意改坏、确认它会红** ——
光看自测全绿不算。这两道 hook 在写的过程中,咬合各抓到过真东西:

| 抓到什么 | 教训 |
|---|---|
| 自测两次**整段没跑却退出 0**(相对路径调用、`/tmp` 软链) | 坏了是绿的,比没有自测更糟 |
| 一条用例**通过是因为别的原因**(heredoc 正文以 `#` 开头,正则本来就不匹配) | 碰巧对上 ≠ 真的对上 |
| CI 提醒的「连红几次」**没有任何断言盖到**,改坏它自测照样全绿 | 一处变异没咬住,可能是那个值根本没被测过 |
| 三次「变异其实是等价变换」(`-1 && x`、`"0" || x ? A : B`) | 改坏了没红,先怀疑自己有没有真改坏 |

## 装

拷到 `~/.claude/hooks/`,在 `~/.claude/settings.json` 里注册:

```json
{ "matcher": "Bash", "hooks": [{ "type": "command",
  "command": "node ~/.claude/hooks/commit-gate-exitcode.mjs",
  "timeout": 5, "statusMessage": "提交前门禁退出码检查" }] }        // 放 PreToolUse

{ "matcher": "Bash", "hooks": [{ "type": "command",
  "command": "node ~/.claude/hooks/push-then-ci.mjs",
  "timeout": 20, "statusMessage": "查 CI 结果" }] }                 // 放 PostToolUse
```

⚠️ **仓库这份和 `~/.claude/hooks/` 那份是两份拷贝,改了要一起改。**
两边不一致时,跑的是 `~/.claude/hooks/` 那份,而你看的是仓库这份 ——
又是一个「看着对,跑的不是它」。

## 相关

配套的 skill:`~/.claude/skills/what-does-this-break/`(「这一改会破坏什么」三问体检)。
这两道 hook 都是它第三问「**这条检查坏了的时候,是红的还是绿的**」的自动化实例:
一道管「红了会不会被吞掉」,一道管「红了会不会没人看见」。
