# 提交前门禁的退出码不许被吞掉

## 它拦什么

2026-09-16，同一个错在这个项目里犯了两次：

```
./check.sh | tail -2 && git commit -m "..."
```

管道的退出码来自 `tail`（永远是 0），不是 `check.sh`。于是**门禁红着，提交照样成功**。
屏幕上印着 `❌ 3 项失败`，而提交已经落盘了 —— 这是这个项目反复遇到的那类故障：
**两个必须触发相反动作的状态，在表示上一模一样**。「门禁绿了」和「门禁的退出码被换掉了」，
在 `&&` 看来是同一件事。

## 判据贴着含义，不贴着字面

这道闸最容易犯的错，正是它要拦的那个错。

| 判据 | 后果 |
|---|---|
| ❌ 「命令里有没有管道」 | `./check.sh \| tail -2`（只想看结果，没提交）也被拦 → **误拦** → 闸被关掉 |
| ✅ 「门禁的退出码到不到得了 commit」 | 只在同一条命令里既有门禁、又有 commit、且通行证断了时才拦 |

落到 bash 语义上，就是看门禁后面**第一个**控制符：

| 形状 | 退出码是谁的 | 判定 |
|---|---|---|
| `门禁 && git commit` | 门禁自己的 | 放行 |
| `门禁 \| tail && git commit` | `tail` 的 | **拦** |
| `门禁 ; git commit` | 丢了 | **拦** |
| `门禁 \|\| true && git commit` | 咽下去了 | **拦** |
| `门禁 \|\| exit 1 ; git commit` | 用上了 | 放行 |
| `if 门禁; then git commit; fi` | 用上了（那个 `;` 是语法） | 放行 |
| `set -o pipefail; 门禁 \| tail && git commit` | 管道会传失败 | 放行 |
| `门禁; rc=$?; [ $rc -eq 0 ] && git commit` | 显式接住了 | 放行 |

**宁可漏，不可误**，三处故意不拦：

- 命令里只有 `git commit` 没有门禁 —— 门禁可能在上一次工具调用里跑过了，这道闸无从知道。拦了就是误拦。
- 命令里只有门禁没有 commit —— 看日志是正当的。
- **heredoc 正文里的内容** —— 那是喂给别的程序的数据，bash 一个字都不执行。
  写这个 hook 的当天它就误拦了一条 `python3 - <<'PY' ... PY`：门禁名和 `git commit`
  全在 heredoc 里。判据读的是命令的字面文本，分不出「会被执行的代码」和「作为数据传下去的文本」——
  又是它自己要拦的那类错。现在先 `stripHeredocs()` 再判。

它自己出错时也**放行**（fail open）。它防的是手滑，不是攻击者；
一道会误拦的闸迟早被关掉，关掉之后它挡的那些错会一起回来。

## 已知的取舍（不是 bug，是明着选的）

- **`verdict()` 返回 `null` 同时表示两件事**：「查过了，通行证是通的」和「这个形状我不认识」。
  对这道闸来说两者的动作相同（都放行），所以不构成故障；但**不认识的形状会被静默放过，不留痕迹**。
  真要收紧就得记日志，那会给 hook 加一条写文件的失败路径 —— 权衡后没加。写在这里，免得它隐形。
- **`GATES` 是白名单，必然有漏。** 漏掉的那个门禁，效果和没装一样。
  加名字前先问一句：**这个命令的退出码，是不是真的「该不该提交」的判据**。不是的话别加，加了就是误拦的来源。
  目前：`check.sh`、`scan_secrets.sh`、`rebuild.sh`、`pytest`、`*_check.py`
  （最后一条是因为这个项目有 48 个单项检查脚本、`check.sh` 里调了 55 次，开发时常单独跑某一个再提交）。

## 咬合测试

```
node tools/hooks/commit-gate-exitcode.mjs --selftest
```

22 个用例：8 个该拦（含两个真实案发现场），14 个该放（其中 6 个专门防误拦）。
**改完判据必须重跑** —— 一道证明不了它拦得住什么的闸，等于没装。

光看自测全绿不够，还要**故意改坏、确认它会红**。写这个 hook 的过程里，咬合测试抓到三件事：

1. **自测整段没跑却退出 0**（两次）。原来用 `import.meta.url === \`file://${process.argv[1]}\``
   判断「是不是被直接运行」：相对路径调用时比不上；`/tmp` 软链到 `/private/tmp` 时也比不上。
   两次都是**一行不打、退出码 0** —— 坏了是绿的，比没有自测更糟。
   → 自测现在只认 argv 里的 `--selftest`，不挂在那个判断下面；hook 分支的判断改用 `realpathSync`。
2. **一条用例是假绿的**。测 heredoc 的那条，正文写成 `# ./check.sh | tail ...`，
   开头那个 `#` 让门禁正则本来就匹配不上 —— 它通过是因为别的原因，不是因为剥离生效。
   把剥离改坏，自测**仍然全绿**，这才暴露出来。→ 改成门禁名顶在行首的正文。
3. 三条变异（放行判据失效 / 不剥 heredoc / 白名单丢掉 `_check.py`）现在都能让自测变红。

## 装

拷到 `~/.claude/hooks/`，在 `~/.claude/settings.json` 的 `hooks.PreToolUse` 里加：

```json
{
  "matcher": "Bash",
  "hooks": [{
    "type": "command",
    "command": "/usr/local/bin/node /Users/eureka/.claude/hooks/commit-gate-exitcode.mjs",
    "timeout": 5,
    "statusMessage": "提交前门禁退出码检查"
  }]
}
```

⚠️ **仓库这份和 `~/.claude/hooks/` 那份是两份拷贝，改了要一起改。**
两边不一致时，跑的是 `~/.claude/hooks/` 那份，而你看的是仓库这份 —— 又是一个「看着对，跑的不是它」。
