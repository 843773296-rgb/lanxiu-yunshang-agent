# 澜绣云裳 · 汉服定制门店的 AI 运营平台

[![check](https://github.com/843773296-rgb/lanxiu-yunshang-agent/actions/workflows/check.yml/badge.svg)](https://github.com/843773296-rgb/lanxiu-yunshang-agent/actions/workflows/check.yml)

一家虚构的汉服定制品牌「澜绣云裳」的完整业务系统:
**一个管理后台(数据的家)+ 一个 AI 运营平台(智能体在上面干活、人在上面签字)**。

这是一个 AI 产品经理的学习 / 作品集项目,不是要上线的生产系统 ——
所以它更看重**激进地试新架构、并且诚实地记下试出来的结果**:
同一件事用三代 AI 架构各做一遍、并排比;每个「做完了」都有一条机器检查盯着;
做错过的事写在代码注释和项目日志里,不删。

> 数据全部是模拟的(固定种子确定性生成),但业务规则、状态流转、权限、钱和工期的口径都按真实门店的做法建。

## 它解决什么问题

汉服定制不是买成衣。一件定制单要经过 预约到店 → 量体 → 选形制 / 面料 / 工艺 → 白坯试衣 → 开裁 → 织造刺绣 → 发货 → 签收,
动辄一百多天;中间任何一环出岔子(量错、面料和工艺不相容、工期赶不上婚期、退款卡在渠道),都要有人发现、定因、处理。

| 现在怎么做 | 断在哪 | 代价 |
|---|---|---|
| 退款失败、客户重复建档、差评,系统扫出来扔进一个「待处理」列表 | 列表只有「处理了 / 没处理」,**「AI 判了」「人认了」「升级了」「事情办完了」混成一个「已销账」** | 看着清空了,钱其实没退成 |
| 顾问凭经验回答「这件能不能做、多久能拿到、多少钱」 | 面料 × 工艺相容不相容、哪道工序卡工期,知识在老师傅脑子里 | 答应了做不出来,或者婚礼前交不了货 |
| 同一个人在三家店各建一份档案 | 没有地方「认人」,也没有地方安全地合 | 会员等级、积分、人数统计全算错 |

**怎么解决**:把这些事拆成「AI 能做的那一半」和「必须由人签字的那一半」,两半之间的每一步都留痕、能撤、能查。

## 研判队列:AI 出草稿、人签字、事情真的办完

系统每天扫出要人处理的事(退款失败、疑似重复客户、售后判责、差评),智能体先查数据、给出「根因 + 建议动作 + 证据」的草稿,人来定。

```
扫出事项 ─→ AI 研判(查工具、给草稿、带置信度)─→ 复核:采纳 / 改判 / 升级 ─→ 办结:凭系统单号回执
                                                    │            │
                                     改判进候选,总部审核后才回流成标注   升级到上一级,超时自动退回
```

把原来混成一个「已销账」的四件事分开记 —— **「AI 判了」和「事情办完了」在旧列表里长得一模一样,而它们该触发的动作完全相反**:

- **两段确认**:动钱的事必须经两个人的手 —— 退款是店长复核、财务办结;客户合并是店长认人、总部运营执行(业务拍的:「钱要出门就要两个人」)
- **办结要回执**:退款办结要填定金单号,系统核对那张单真的「已退」;合并办结要有合并记录。没有回执进不了已办结
- **退款最怕重复退**:登记已退必须带渠道退款流水号,同一个流水号不能证明两笔退款(数据库唯一索引,结构上做不到)
- **改判不直接改答案**:人改判的结论先进候选,总部运营审核后才回流成评测标注 —— 防止一次手滑污染标准答案
- **能重开**:复核那一岗或总部运营可以重开;已办结的不重开,改开更正工单,计时接着算
- **客户软合并**:重复档案只标「并入谁」,数据一行不搬、订单积分只关联不相加,**能撤**
- **换提示词先试**:新一版研判提示词先在**遮掉顾客信息的库副本**上跑一批,和现在那版并排比谁答对得多,再决定发不发布
- **上线门槛四个 0**:在真实操作日志上量「越权 / 重复业务执行 / 失败假成功 / 无依据办结」,四个数必须都是 0,门禁每次都量

## 安全边界:分清「做不到」和「不该做」

这个项目踩过最重的一个坑:配置里写了「只允许这些工具」,以为模型碰不到写文件、执行命令 —— **其实那个配置只管「哪些不弹确认」,内置的命令行工具一直都在**,只是当时那个模型碰巧没去用。换了模型,它立刻就用了。

从那以后,每条对外保证都要写清它靠什么成立,清单由代码生成([`安全边界审计.md`](安全边界审计.md)):

| 类别 | 意思 |
|---|---|
| **结构** | 做不到 —— 每一条都有一段代码真的去攻击它一次 |
| **检查** | 做得到,但提交前会被抓 |
| **约定** | 只是「不该做」,违反了什么都不会发生 —— 明着列出来,不假装 |

读 / 写 / 答三层闸具体拦什么,见下文产品说明「4.6 闸」。

## 门禁与夜跑

`./check.sh` 是唯一的验收标准,任何一项红整体就红;每次推送 GitHub Actions **从零建库**再跑一遍。
(检查和咬合的纪律见下文产品说明第 7 节;这里只写那一节没有的。)

- **改坏测试写成可重放的规格**(`tools/bite_specs.json`):改坏哪一处、跑哪个检查、应该红在哪一条,在工作区副本上自动重放 —— 「它红了」和「红的就是那一条」是两件事
- **样本量为 0 不叫通过**:空集合上所有性质都成立
- **判据红不红,不能取决于库里碰巧有什么**:检查自己造它要验的形状。CI 从零建的库和开发机上的库长得不一样,真出过「本地绿、CI 红」
- **夜跑评测**:每晚 0:00–4:55 自动跑全部评测(Claude Haiku 4.5,订阅内不额外花钱),早上结果和报告自动提交进 `agent/nightly/`。
  跑挂了、环境没起来、模型答错、判分器没认出说法 —— 四种情况分开报;混成一个「没过」的话,一晚 5 条红里没有一条是模型答错这种事就看不出来

## 跑起来

```bash
./start.sh       # 两个服务一起起;第一次会先把库从零建全
./check.sh       # 全套检查,任一失败即整体失败
```

| 什么时候 | 敲什么 | 会不会删东西 |
|---|---|---|
| 第一次启动,还没有库 | `./start.sh`(自己会建) | 不会 —— 有库就拒绝重建 |
| 想推倒重来 | `./tools/rebuild.sh` | **会**,先删库,给 3 秒反悔 |

⚠️ 别只跑 `backend/seed.py` —— 它只是建库的第一步。只跑它的库首页照样打得开,但十几张表根本不存在。

**依赖**:管理后台只用 Python 标准库;AI 运营平台要 `claude-agent-sdk`(`agentsite/requirements.txt`,`start.sh` 会自己建 venv 装上)。

**模型**:`LANXIU_PROVIDER=claude` 走 Claude(CLI 登录态,订阅内),开发和评测一律用这个;不设则走 DeepSeek(按量计费,读 `~/.deepseek-key`)。
⚠️ Agent SDK 返回的 `total_cost_usd` 在跨供应商时是错的(拿 Claude 的价目表算 DeepSeek 的 token,实测差 24 倍),成本一律由 `agentsite/sdk.py` 的 `cost_of()` 按实价重算。

## 目录结构

```
backend/        数据的家:SQLite 库 + 管理后台(server.py)+ 状态机(fsm.py)+ 写入规则
                + 研判队列(ops.py)+ 各写口(order_write / measure_write / refund_write …)+ 各项检查
knowledge/      领域知识:手写知识 md(真相源)+ 推导脚本 + 口径模块(口径模块不自己取当前日期)
mcp/            8 个业务领域 MCP 服务(domain_server.py + backend/domains.py)。裸手写 JSON-RPC,没用 SDK
agent/          V1、V2,全部评测集、判分器、调用记录仪;nightly/ 是每晚的评测结果
agentsite/      V3 与 AI 运营平台:Agent SDK 内核、Hook、页面
fakedata/       假数据工厂:给任意库灌「库允许、业务也允许」的测试数据,能回滚
tools/          门禁、改坏重放、夜跑、发布、交接与 README 生成、飞书发布、密钥扫描
intent/         每件事的方案:要解决什么 / 明确不做什么 / 怎么算做完 / 状态
```

## 还没解决的

(产品说明第 8 节「边界与已知代价」之外的:)

- **样本小**:三代对比是 6 条工单;研判队列走正门的真实操作日志只有十几条
- **有一条保证只靠提示词**:写工具动手之前「先跟用户对一遍」只有提示词这么说,模型不问就写,没有东西会拦(列在安全边界审计的「约定」类)
- **研判的效率门槛没定**:方案要求「按真实测量批准」,要试点跑出真实耗时、由业务批,现在不编一个数
- **成交率算不出来**:见 [`澜绣云裳agent-成交率为什么算不出来.md`](澜绣云裳agent-成交率为什么算不出来.md)
- **差评的 AI 辅助默认关着**:专用取数和独立评测没接通之前不开,页面上明示
