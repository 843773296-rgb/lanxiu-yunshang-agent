四个应用

前两个是智能体驱动的,后两个是产品页面,数据来自后台。

Agent SDK · MCP kb 工艺顾问助手 顾问懂客户不懂工艺。用大白话问,它去查工艺知识库,只答查到的,查不到就说查不到。 Agent SDK · MCP task 智能体工作台 拿一道真实人工任务现场跑:它自己决定查什么、查几次,交一份草稿,跑完再对标注答案。 硬约束 · 后台数据 定制方案配置 五项选完构成一个方案。工艺 × 面料有硬约束,选了「不可」的组合保存按钮直接不可点。 验收 · 后台引擎 验收台 91 条从状态机机械推导的异常场景,逐条打到后台引擎上跑,看它到底处理没处理。

这个站和后台是什么关系

两个独立服务。后台是记录系统,这里是交互系统。

为什么工具走 MCP

工具面按用途拆成两个服务(kb / task),各挂各的。 一个服务会让工艺顾问看到 5 个无关的任务工具 —— 给模型的每个多余选择都是自己加的失败模式。

为什么数据不搬过来

搬过来就有两份库,迟早对不上。本站 /api/* 一律反代到后台, 判分和标注答案也留在后台 —— 数据的家只有一个。
