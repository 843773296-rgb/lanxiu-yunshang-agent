# 客户召回名单

## 什么时候用

用户要**一张名单**:接下来该主动联系哪些客户。典型说法:

- 「这周我该联系哪些老客户」「今天该给谁打电话」
- 「哪些老客户该回访了」「帮我列个召回名单」
- 「潜在流失那一档我先联系谁」「名下有没有快流失的客户要跟一下」

## 什么时候不用

- **只问一个人**(「C10001 最近怎么样」「黄青梧该不该联系」)—— 直接用
  `revive_list(customer=…)` / `get_member` / `customer_history` 答这一个人,不出名单。
- **通话里有没有商机、整理一通电话** —— 那是 `call_opportunity` / call-notes 技能,
  看的是客户在电话里说过想要什么,不是该不该打这通电话。
- **下了单没付钱、约了没来的**(未成交挽回)—— 直接用 `recovery_queue`,那是另一份清单。
- **营收、销量、经营报告** —— 不是名单,不走这个技能。
- **用户要按「闲置超过 N 天」筛** —— 不照他的天数筛(见硬规矩 1),
  照这个技能的流程出带由头的名单,并说清为什么不按天数。

## 为什么要一步一步走

顾问拿到名单第一句会问**凭什么是他、凭什么是现在、我打过去说什么**。
只按闲置天数筛的名单答不上来,打过去就是尬聊,也是骚扰;
而「在流失」不等于「现在该打」—— 她在往下走而眼下没由头,该做的是等由头,不是硬打。
所以要两个工具都过:**`revive_list` 管「现在该不该打、说什么」,`churn_watch` 管「她是不是在往下走」。**

## 第一步:定范围

范围**跟登录身份走**,工具自己按身份收窄:顾问 = 自己名下,店长 = 本店,总部运营 = 全部门店。

- **不传 `customer`。** 用户说「我名下」「我们店」时,那是范围,不是客户名。
  ⚠️ 把提问人自己的名字当 customer 传进去会得到「合计 0」,而那不是「名下没人」。
- 回答开头**照抄工具返回的「看的范围」**,让用户知道这份名单是哪一段。
- 用户要看**另一个顾问名下**的 —— 这两个工具不按顾问筛。顾问看不到别人的客户,照实说;
  店长看到的是全店,照实说「工具给的是全店,分不出是谁名下的」,不要自己拼。

## 第二步:拿两份名单

1. `revive_list()` —— **必调**。拿「该联系的」名单(每条带「由头」和「为什么是现在」)、
   「没进名单的」按原因分的计数、「这几个门槛是拍的」。
2. `churn_watch()` —— **必调**,和上一步同一个 `limit`。拿「在往下走」的名单(按严重程度分组)。
3. 按**客户号**把两份对一下:
   - **两份都在** → 有由头、又在往下走,标「同时在流失预警里(严重程度 X)」,放在名单前面。
   - **只在 revive_list** → 有由头,照常列。
   - **只在 churn_watch** → 在往下走,但**眼下没由头**,不进本次联系名单,
     单独列成「在流失、等由头」一小段(带严重程度和走到哪一步)。

⚠️ 两份名单都可能被 `limit` 截断(返回里「还有」不为 0)。**一个人不在截出来的那一页里,
不代表他不在另一份名单里** —— 只说「这一页没对上」,不说「他没在流失」。

## 第三步:给要写详细的人补底

名单前面几位(一般三到五位;用户指定了人数就照他说的)逐个补:

- `get_member(customer=客户号)` —— **生命周期档位**(工具给的「生命周期」和「判定条件」原文)、
  闲置天数、过去 12 个月几单、首单日期。
- `customer_history(customer=客户号)` —— **上次做了什么**:最近一次触点(什么时候、干了什么、谁经手)。

其余的人一行带过:名字、客户号、由头。最后问一句要不要展开别的。

## 第四步:每个人写三件事

| 写什么 | 从哪来 | 不许 |
|---|---|---|
| **为什么是他** | `get_member` 的生命周期档位 + 闲置天数;`churn_watch` 的「走到哪一步」「有多可惜」 | 不许自己判档位、不许把「曾经是忠诚」说成「现在是忠诚」 |
| **为什么是现在** | `revive_list` 那条的「由头」+「为什么是现在」原文 | 不许换成「超过 X 天没来」;门槛带「待校准」的照样标出来 |
| **联系时说什么** | 一两句可以直接说出口的开场,**只引用他自己记录里有的东西**(上一单做完多久、哪件维保没办完、往年这个月来过、生日快到) | 不许编他没做过的事、不许编优惠、不许承诺结果 |

## 第五步:没进名单的也要交代

照 `revive_list` 的「没进名单的」和「没进名单的该做什么」**按原因分开说**,
每种带一句下一步(刚买完别打 / 有售后先办售后 / 刚联系过防骚扰 / 没由头等由头 / 没下过单归拉新)。
**「该联系 0 个」不等于这些客户都不行** —— 多数是「现在不是时候」。

店长看全店时,可以加一句:没人管的客户不会出现在任何顾问的名单里,要看用 `ownerless_list`(不主动调)。

## 第六步:用户说「派」才派

这一步**只有用户明确说「派」「派给 xx」「建任务」时才做**。没说就停在建议,结尾提示一句
「要派回访任务的话告诉我派给谁」。

1. **只有店长及以上能派。** 顾问说「派」—— 照实说派任务要店长做,把名单交给店长,不要尝试调写口。
2. 先调 `task_types()`,从**族 = 客户**的类型里选(要填客户号)。**没有专门叫「回访」的类型**,
   用户没说用哪种就问(列出族 = 客户的那几种名称),不要替他挑。
3. 把**派给谁 / 哪天之前 / 哪个客户 / 备注写什么**(备注里放由头和开场话术)跟用户对一遍,他说可以再派。
4. `assign_task` **一次一条**。返回 `error` 就把原话告诉用户,**不要换参数重试**。
5. 做完照实报:任务号、落到谁头上。没做成的不许说成做成了。

## 硬规矩(不许变通)

1. **不引入任何新门槛。** 多少天算流失、多久算断节奏、谁该进名单 —— **全照工具返回**。
   不许用第三方 RFM 阈值、不许在回答里自己写出「超过多少天算休眠 / 流失」的口径,也不许照用户给的天数筛人。
   **口径不在这份技能里重算** —— 生命周期八档和各档天数只认工具返回(背后是 `knowledge/` 的口径模块)。
   用户问某个门槛为什么是这个数,照工具「这几个门槛是拍的」那一栏说那是**待校准的默认值**,不替它编理由。
2. **数只用工具给的。** 天数、单数、金额、档位、严重程度,每一个都要能在工具返回里找到原文。
   不许估「打完能挽回多少」「回来的概率」。
3. **话术只引用他自己的记录。** 没有的事不说;记录里没有的上次购买内容不编。
4. **只出建议,不自动派。** 用户没说「派」就不调 `assign_task`;**也不许说「已经帮你安排好了」**。
5. **对外动作不在这儿。** 打电话、发微信、发短信是顾问的事 —— 你给的是「找谁、凭什么、说什么」。

## 出错了怎么办

| 情况 | 怎么办 |
|---|---|
| 工具说「不知道现在是谁在问」 | 照实说要先登录,**不要猜一个身份** |
| `revive_list` 返回「合计 0」 | 说清是「这个范围里没有客户」;如果是传了 customer 导致的,去掉 customer 重查 |
| 「该联系的」是 0 | 照「没进名单的」分原因说,别给泄气的结论 |
| `churn_watch` 有「没有档位历史的」 | 说清这些人**说不出在不在流失**,不是「没在流失」 |
| 两个工具的说法对不上(比如 get_member 的闲置天数很长、而接触史里最近刚有过触点) | **两个都照原文写出来,点明对不上**,请顾问核实;不要自己挑一个、也不要编一个解释 |
| `get_member` / `customer_history` 拿不到(没挂、报错、重名) | 这个人只写名单工具给的那几项,档位或上次做了什么写「没查到」,**不要补猜** |
| 用户坚持「把闲置超过 N 天的都列出来」 | 说清系统的口径是**相对他自己的节奏**、没由头的打过去不知道说什么;照流程给带由头的名单 |
| 顾问要派任务 | 说明派任务要店长做,名单可以直接转给店长 |
| `assign_task` 报错 | 原话告诉用户,不重试 |

## 用哪些工具

`revive_list`(必调)· `churn_watch`(必调)· `get_member`(补档位)·
`customer_history`(补上次做了什么)· `ownerless_list`(店长问「有没有没人管的」时)·
`task_types` + `assign_task`(**只在用户说「派」时**)。
