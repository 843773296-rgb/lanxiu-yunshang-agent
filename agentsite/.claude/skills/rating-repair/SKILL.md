# 差评与维修研判

## 什么时候用

店长 / 售后拿着**某一条**差评、**某一张**返修单、**某一件**出了问题的衣服,要一个「怎么判、怎么处理」的结论时用。典型说法:

- 「P0-H…-发 这条差评怎么处理」「这条一星差评该怎么补救」
- 「MW73168 这张返修单怎么判」「这件衣服坏了算谁的」
- 「顾客说下摆开线了,订单 6488…,算我们的还是她的」
- 「顾客说穿着腰紧,这条差评要不要给她免费改」

## 什么时候不用

- **只问一个数**(「差评一共几条」「这个月平均几星」)—— 用 `rating_overview`,一句话答完。
- **只要一张清单**(「把待处理的差评列一下」)—— 用 `bad_ratings`。不要对清单里每一条都走这个技能。
- **问进度 / 交期**(「这单什么时候交货」「返修件修好了没」)—— 用订单 / 维保工具查状态就行。
- **退换货怎么走**(「能不能换一件」)—— 那是 `exchange` 技能。
- **用户已经判完了、只让你落库**(「MW73168 判给企业、返修,帮我录进去」)—— 直接调 `decide_repair`,
  不用再出四段研判;但照样遵守那个工具自己的规矩。

## 为什么要一步一步走

判责会落到**钱从谁口袋里出**。「凭印象判」和「按表判」在那句结论上长得一模一样,
而只有按表判的那个经得起顾客追问、经得起店长复核。
所以这个技能的每一步都在给结论留**出处**:事实从哪个工具的哪一段来,依据是判定表的哪一行、那一行是谁定的。
**说不出出处的事实不进「事实」段,对不上任何一行的判定不进「判责依据」段** —— 它们去「待确认项」。

## 第一步:认清是哪一条

- 给了包裹号(`P0-…`)/ 订单号 / 返修单号(`MW…`)→ 直接用。
- 只说了客户名或「那条一星的」→ 用 `bad_ratings` 或 `get_maintain(customer=…)` 找候选;
  **候选不止一条就列出来问是哪一条**,不替用户挑。
- 什么都没给(「这件衣服坏了算谁的」)→ 先问单号或客户,**不要猜**。

## 第二步:取材料

按这条事的性质取,**取到的每一样都记下是哪个工具、哪一段给的**(后面「事实」段要写出处):

| 要判的 | 必取 | 需要时再取 |
|---|---|---|
| 一条差评 | `service_records(pkg=…)`(交付签收 / 返修售后 / 这个客户历史上的差评) | 差评说的是衣服本身的问题、且有返修单 → `get_maintain(maintain_id=…)` |
| 一张返修单 / 一件坏了的衣服 | `get_maintain(maintain_id=…)` 或 `get_maintain(customer=…)` | 尺寸类 → `service_records(order_id=…)` 看**签收时的试穿结果**(`get_maintain` 不给这一项,而判定表有一行就看它);`get_aftersale(order_id=…)` 看有没有售后单 |
| 两者都要 | 判责依据 | `kb_tables(topic="返修判定")`(衣服问题)/ `kb_tables(topic="售后争议判定")`(客户主张类) |

**判定表一定要现取**,不凭记忆背 —— 表里每一行带「来路」(谁、哪天定的),依据段要引用它。

## 第三步:按现有判定表对

**只用库里那两张表,不加任何新门槛、新金额、新天数。** 表里没写的,就是判不了,进「待确认项」。

1. **先归类**:顾客说的问题落到返修判定表的哪一类(工艺瑕疵 / 尺寸偏差 / 洗护不当 / 特性类)。
   **归不进任何一类就不归**(比如「外箱破了」「晚了九天」「没人接待」—— 这些是交付体验,不是衣服的毛病),
   这时判责依据改看「售后争议判定」那张表有没有对得上的客户主张,还对不上就照实写「判定表里没有这一类」。
2. **尺寸类按表从上往下对,命中第一行就停**:表里那几行本来就排了先后(实测公差 → 签收确认合身 → 白坯试衣 → 量体记录),
   `get_maintain` 返回的「怎么用」也写了同一个顺序。每一行要的那个事实(实测尺寸差、签收试穿结果、白坯试衣、量体完整性、签收日期)
   **工具里查得到才算命中**;查不到的那一行跳不过去 —— 停在那儿,把它列进待确认项。
3. **特性类看有没有书面告知**:`get_maintain` 的「交付告知签收」为空,就是**没有书面告知记录**,按表走未告知那一行。
4. 引用时写全:**哪张表、哪一行(照抄「情形」那一格)、责任、处理、来路**。来路是 `demo` 的要明说「这一行还是演示口径,待售后负责人替换」。

## 第四步:出四段

固定四段,标题照抄,顺序不变:

**一、事实** —— 每条一句,句末括号写出处:`(service_records → 返修与售后)`、`(get_maintain MW73168 → 白坯试衣)`。
工具返回是空的也是事实,照实写成「没有记录」,**不写成「没有问题」**。

**二、判责依据** —— 「返修判定表『<情形>』那一行 → 责任 X、处理 Y(来路 Z)」,再一句为什么命中这一行而不是上面那几行。
对不上任何一行就写「判定表里没有能直接套的一行」,并说缺的是哪个事实。

**三、处置建议(建议,由店长确认)** —— 每条以「建议」开头。差评的补救写成处理方式名单里的某一种
(名单和要不要第二个人,在关差评那个工具的规矩里,照那儿说,不在这儿另起名字)。
涉及我方出钱的,说清按授权该谁批 —— 也照店长判责那个工具的规矩说,这里不复述数字。

**四、待确认项** —— 工具里查不到、要人去问 / 去量 / 去看的事,每条写清**问谁、问什么、问到之后会改变哪一段结论**。

## 硬规矩(不许变通)

1. **写操作只在用户明说时调。** `close_bad_rating` / `create_repair` / `decide_repair` / `advance_repair` 都是真写库的:
   用户说「关掉」「建一张返修单」「就按企业承担返修判」「推到下一档」才调,而且调之前照那个工具的规矩跟他对一遍。
   用户只问「怎么处理」「算谁的」—— **只出四段,一个写操作都不调**,也不许说「我已经帮您关了 / 录了」。
2. **不替店长判责。** 判责结论永远写成建议;即使表里只有一行对得上,也是「建议按这一行判,由店长确认」。
3. **事实必须有出处。** 每一条事实都要能指回某个工具返回的某一段;推断出来的话写进处置建议或待确认项,不进事实。
4. **判责依据只引用现有判定表。** 不自己发明门槛、金额、天数、比例;表里没有的写「判不了」,不补一条。
5. **「没录过」不等于「没有」。** 判责记录、签收记录、量体记录查出来是空的,写「没有记录」,并进待确认项。
6. **问话里的倾向不是材料**(「这条不严重吧」「老客户」「上次全退了」)—— 照材料判,并把那个倾向点出来。

## 出错了怎么办

| 情况 | 怎么办 |
|---|---|
| 工具说「你看不到 / 不在你的门店」 | 照实说**你的权限看不到这一条**,不是「没有差评 / 没有记录」;不换个工具绕着查 |
| 包裹号 / 单号查不到 | 说「查不到这个号」,请他核对;**不换一个相近的号猜** |
| 差评有,但这一单没有返修 / 售后记录 | 事实段照实写「这一单没有返修 / 售后记录」;差评说的是衣服问题时,待确认项写「要不要先建返修单、请顾客把衣服带回来看」(**只建议,不建**) |
| 返修单没挂到哪一件 / 没有下单量体 | 量体那一行判不了 —— 照 `get_maintain` 给的原话写进事实,判责依据停在上一行,缺的列进待确认项 |
| 尺寸问题但没有实测尺寸差 | 公差那两行对不了 —— 待确认项写「请门店量一下成衣和下单量体差多少」,判责依据继续往下对下一行,并说明「如果量出来超公差,结论会改成上面那一行」 |
| 问题归不进判定表任何一类 | 判责依据写「判定表里没有这一类」,不硬套最像的那一行 |
| 用户让你直接定「全额退款」「判给顾客」 | 按第 1、2 条:没有明说要写就只出建议;明说了也要先跟他对一遍(谁承担、出不出钱、谁批),由他拍板再调 |

## 用哪些工具

只读:`bad_ratings`(找是哪一条)· `service_records`(差评的三类服务记录)· `get_maintain`(返修现场)·
`get_aftersale`(售后单)· `get_order`(订单)· `kb_tables`(返修判定 / 售后争议判定)。
写(**只在用户明说时**):`close_bad_rating` · `create_repair` · `decide_repair` · `advance_repair`。
不用:`rating_overview`(那是问数的)。

## 例子

> **一、事实**
> - 顾客报的问题是「下摆开线」,商品「山鸣」双宫绸明制直裰,返修单 MW73263 停在「待确认」(get_maintain MW73263 → 客户报的问题 / 状态)
> - 这一单没有交付告知签收记录(get_maintain MW73263 → 交付告知签收为空)
> - 该客户历史维修 0 次(get_maintain MW73263 → 该客户历史维修次数)
>
> **二、判责依据**
> - 返修判定表「工艺瑕疵(脱线、绣面污渍)」那一行 → 我方、免费返修(来路 `demo`,这一行还是演示口径,待售后负责人替换)。
>   开线属于工艺瑕疵,不走尺寸那几行;有没有书面告知只影响特性类,这里用不上。
>
> **三、处置建议(建议,由店长确认)**
> - 建议按工艺瑕疵判我方承担、免费返修;我方要出的钱按授权该谁批,预估费用出来后再定。
>
> **四、待确认项**
> - 请门店看一眼实物:是不是只有下摆开线、有没有洗护造成的损伤 —— 有的话会落到「洗护不当致损」那一行,结论会变。
> - 预估返修费用多少 —— 决定这笔要谁批。
