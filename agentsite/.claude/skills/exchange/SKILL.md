# 办换货

## 什么时候用

客户要**把买到的这件换成另一件**时用。典型触发:

- 「尺码买小了,能换大一号吗」
- 「颜色和图片不一样,想换个色」
- 「这件不合适,能换别的款吗」

## 什么时候不用

- **已经确认是定制品的** —— 定制品**没有换货这个出口**,直接说清楚并给维保/退款两条路。
  ⚠️ **但客户开口时你还不知道它是不是定制品** —— 那正是第一步要查的事,
  所以「客户说想换」仍然走这个技能,由第一步去判。
  **不要因为猜它可能是定制品就不走流程**:猜对了和猜错了,在开口那一刻长得一模一样。
- **退货退款** —— 客户要的是把钱拿回来,那是另一条路,不走换货。
- **一般性咨询** —— 「你们支持换货吗」直接答口径就行,不必开单。
- **商品坏了要修** —— 走维保,标品定制品都有维保。

## 为什么这件事必须一步一步走

换货是**一条有前后依赖的链**,每一步的结果决定下一步能不能走:

    提交申请 → 审批同意 → 商品寄回 → 已入库 → 差价处理 → 换出发货 → 签收 → 已完成
                  ↘ 审批拒绝(终态)

跳步的代价不对称:

> **先发新的再等寄回**,一旦审批没过或客户不寄,两件都在外面。
> 而「发出去了」和「没发出去」在客户那边是**完全不同的事实**,收不回来。

所以顺序不是流程洁癖,是**不可逆动作的排序**。

---

## 第一步:先判这单能不能换

查 `get_order` 拿到订单类型。

- **定制品订单** → 到此为止。说清楚为什么没有换货,并给出真正的两条路:
  维保(修)或退款(赔)。**不要说「我帮您问问」** —— 这条没有例外。
- **标品订单** → 继续。

同时确认**要换的那件商品确实在这张订单里**(`get_order` 的订单行)。
不在这张单里的商品不能走这张单的换货。

## 第二步:提审批 —— 客户提了不等于成立

**换货要人批。** 用 `apply_adjust` 提单,把理由写清楚。

⚠️ 这一步只是**申请**,不生效。跟客户说的话里不能有「已经给您换了」
—— 那是审批之后的事实,现在说出去就是承诺。

**审批拒绝是终态。** 被拒了就是被拒了,不要换个理由再提一次。

## 第三步:批了,才让客户寄回

**原件必须寄回并入库,之后才发新的。**

跟客户说清楚三件事:寄到哪、什么时候寄、寄回之后多久发新的。
在「已入库」之前,**不要给新件的发货时间** —— 那个时间还不存在。

## 第四步:算差价,走原支付渠道

**多退少补。** 换的那件贵了要补,便宜了要退。

差价走**原支付渠道**,和退款同一条路 —— 不走余额、不走线下、不抹零。

⚠️ 「差价处理」是**独立的一档状态**。它的存在是因为:
不单独留一档的话,「已入库」直接跳「换出发货」时,
**差价在哪一步收/退说不清**,而说不清的钱最后都变成纠纷。

## 第五步:从买的渠道出货

**门店买的从门店出,小程序买的从仓库出。不许跨渠道调货。**

渠道决定了**库存归属和结算对象** —— 跨渠道调货在库里看起来只是换个出库仓,
实际上是把 A 的货算到 B 的账上。

用 `get_stock` 查**买的那个渠道**有没有货。别的渠道有货**不算有货**。

---

## 硬规矩(这五条是业务定的,不许变通)

1. **走审批。** 客户提了不等于成立,要人批。**审批拒绝是终态。**
2. **要寄回。** 原件必须寄回并入库,之后才发新的。
   —— 这条决定了**不能**在原件还在客户手上时就把新的发出去。
3. **从买的渠道出货。** 不许跨渠道调货。
4. **差价多退少补**,走**原支付渠道**。
5. **换货单绑订单,换回来的那件必须是该订单里的商品。**
   换出去的那件不受这条约束(它是新的),**换回来的那件受**。

另外两条:**定制品不出现换货**;**换货和维保是两件事**,别混。

## 出错了怎么办

| 情况 | 怎么办 |
|---|---|
| 审批被拒 | **终态**,照实告诉客户,并说明可走的其他出口(退款/维保)。不要重提 |
| 客户已经把货寄回来了,但审批还没过 | 先收下入库登记,**但不要发新件**。审批没过就走退回,不要自作主张往下走 |
| 想换的那件缺货 | 说清楚缺货,给两个选择:等到货(给日期)或换别的。**不要跨渠道找货** |
| 别的渠道有货、买的这个渠道没货 | **不算有货。** 照上面那条办,不要调货 |
| 客户要换的商品不在这张订单里 | 不能走这张单。查一下是不是另一张订单买的 |
| 这是定制品但客户坚持要换 | 说清楚原因(按尺寸和选料做的,退回来卖不掉也没第二件),给维保和退款两条路 |
| 差价算出来是退钱,但原支付渠道已经失效 | **不要改走别的渠道**,提审批按异常处理,请财务介入 |

## 用哪些工具

`get_order`(判订单类型、核商品在不在这张单里)、`get_aftersale`(看这张单已有的售后)、
`apply_adjust`(提审批单)、`decide_approval`(批,**只有总部运营能走**)、
`get_stock`(查买的那个渠道有没有货)、`check_write`(不确定业务允不允许时先问一句)。

## 例子

> 客户:上周在小程序买的马面裙,M 码小了,能换 L 吗?
>
> ① `get_order` → 标品订单 ✅,订单行里有这条裙子 ✅
> ② 答:「可以申请换货。我先提一张审批单,批下来我通知您寄回;
>    原件入库之后我们从仓库发 L 码给您。」**不说「已经给您换了」**
> ③ `apply_adjust` 提单
> ④ 批了 → 告知寄回地址和时间
> ⑤ 入库 → `get_stock` 查**仓库**(小程序买的)有没有 L 码
> ⑥ 同价 → 无差价;不同价 → 多退少补走原支付渠道
> ⑦ 从仓库发货 → 签收 → 完成
