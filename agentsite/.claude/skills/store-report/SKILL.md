# 经营报告:日报 / 周报 / 月报

## 什么时候用

店长或总部要**一份报告**的时候 —— 不管是日、周、月。典型说法:

- 「出个周报」「生成上周的周报」「九月月报」「昨天的日报写一下」
- 「复盘一下上周」「这周经营怎么样,写个报告」
- 「本周经营报告,顺便列一下下周要改的」

## 什么时候不用

- **只要一个数** —— 「上周营收多少」用 `weekly_revenue`;「九月卖得最好的商品」用 `sales_rank`;
  「下周有哪些单要交付」用 `orders_by_date`。这些不需要一整份报告。
- **只是看以前存过的那一份** —— 「上周那份周报说营收多少」用 `list_reports`,照存下的说,不重新取数。
- **顾问** —— 经营报告给店长和总部看,取数包对顾问会直接拒;顾问问「我这周做得怎么样」是业绩,不是这份报告。

## 为什么一步一步走

报告会被店长拿去开会、被总部拿去比门店。**一个数说错了,后面所有讨论都建在它上面**,而读报告的人没法回头查。
所以每一步都在守「这个数是从哪来的」:数只从取数包来,口径跟着数走,判断标成判断,动作等人点头。

## 第一步:定是哪一期

- 用户说了日 / 周 / 月和哪一天 → 照用。说「九月」就是今年九月(`kind=月`,`date` 填那个月里任意一天)。
- **没说哪一期** → 上一个**完整**的那一期(昨天 / 上周 / 上个月),写的时候第一句就说清是哪一段日期。
- **周是周一到周日,月是自然月**(和取数包同一套)—— 「上周」不是「最近 7 天」。先把起止日期定下来,下一步要拿它去对。
- 说的那一期还没到 / 还没过完 → 取数包会说,照实告诉用户「截到今天」或「还没到」,不要换一期。

## 第二步:先看这一期存过没有

调 `list_reports`。**按起止日期对,不按「看着像上周」对**:列出来那一份的起始日和上一步定的起始日**一样**,才是这一期。
起止对不上的(比如一份起始日不是周一的「周报」)不是这一期 —— 照常往下写,顺带提一句有这么一份。

- 这一期**已经确认过** → 先告诉用户「X 月 X 日那份已经确认了」,给链接,问他是看那份还是重写一版(重写会是新的一版,旧的留着)。
- 有草稿 → 告诉他有一份草稿,问是在草稿上改还是重写。
- 没有 → 往下走。

## 第三步:取一次数

调 `store_report(kind=..., date=...)`,**只调一次**。不要再一个个工具去凑数 —— 取数包里每一项都带出处和口径,凑出来的没有。

## 第四步:照固定结构写

```
# {门店} {周期名}经营报告({起}–{止})

**一句话**:{这一期最要紧的一两件事,只用取数包里的数}

## 期内:这一期发生了什么
{逐项:指标名照取数包 · 数 · 一句口径}
{取数包有「环比」就照抄它算好的比例和上一期区间;它说「不比」就照抄理由,不自己除}
{取数包「并排读时要说清的」那几句,原样放在它说的那两个数旁边 —— 不单开一段(单开的话读的人看到数时看不到那句)}

## 上期定的行动
{照抄取数包「上期定的行动」:做什么 · 谁 · 做完没有 · 盯的那一项上期 / 这期各多少;条数为 0 就照抄它的说明。
 只摆事实,不写「这条行动起了作用 / 没起作用」}

## 存量:截至今天还压着什么
{逐项;每项都写「截至今天」}

## 取不到的
{取数包「取不到的」那一栏,照实列;没有就写「无」}

## 可能的原因(判断,不是结论)
{只针对上面出现的数;每条用「可能是…」开头}

## 下期改进事项(建议)
{每条写:要做什么 · 盯报告里的哪一项(指标名照取数包) · 建议谁来做;**这里只是建议,还没派**。
 不写目标数(「下期做到 90%」)—— 目标是店长定的,取数包里没有}
```

写数的规矩照工具自带的那几条(取数包规矩 TL67):不心算新数、金额照「写成万」那栏抄、成交率每次都标「最近 4 周」、
期内和存量不混、指标名不自己起。

## 第五步:给他看,等他说话

写完**先给他看**,然后停下。

- 他说「存一下 / 保存」 → `save_report`,存的就是给他看过的那一份正文;回复带上返回的链接和下载。
- 店长说「确认」 → `confirm_report`。**不替他点**;缺必选指标被拒时照实转告。
- 他说「把第 2 条派给 XX」 → 第六步。他什么都没说 → 不存、不确认、不派。

## 第六步:派经营改进(只在他点名要派时)

- **报告要先存过**(要报告号)。没存就先问他要不要存。
- 调 `task_types` 确认「经营改进」的规范,再 `assign_task(type="经营改进", ref_id=报告号, metric=盯的那一项, assignee=..., end=..., note=...)`。
  `metric` 只能是取数包里**真有、当时有数**的指标名 —— 被拒时返回会列出可盯的那几项,照着改一次。
- 一次只派他点名的那几条;没点名的改进事项留在报告里,不顺手派。

## 硬规矩

- **数只从取数包来。** 取数包里没有的数,写「取数包里没有这一项」,不自己算、不估。
- **不许自动存、不许替店长确认、不许自动派任务** —— 三个都必须等用户明说。
- **原因和改进都标成判断 / 建议**,不写成「已安排」「已解决」。
- **已确认的报告不改** —— 要改就再存一版。

## 出错了怎么办

- `store_report` 说**没有登录身份 / 不是店长或总部** → 告诉他经营报告要店长或总部账号,不换别的工具凑。
- 说**这一期还没到** → 照说,问他要不要改看上一期。
- 取数包里有**取不到的项** → 照实写进「取不到的」,报告照写,别因为缺一两项就不出报告。
- `save_report` / `confirm_report` **被拒**(比如缺必选指标、不是最新一版)→ 原样转告原因,不换个说法再试。
- `assign_task` **被拒**(报告不是这家店的、metric 不在报告里、派给的人不在本店)→ 把返回的理由告诉他,问他怎么改,不自己换人换指标。

## 用哪些工具(依赖)

`list_reports` → `store_report` → (他说存)`save_report` → (店长说确认)`confirm_report`
→ (他说派)`task_types` + `assign_task`。全部是这个系统自己的工具,不需要任何外部服务。

## 例子

> 店长:出个上周的周报,顺便列一下下周要改的
>
> 1. 上周 = 10-13 到 10-19。`list_reports` 没有这一期 → `store_report(kind="周")`
> 2. 照结构写:一句话 / 期内(含环比、并排要说清的那几句)/ 上期定的行动 / 存量(截至今天)/ 取不到的 / 可能的原因 / 下期改进(建议)
> 3. 给他看,停下。他说「存一下」→ `save_report`,回链接。
> 4. 他说「第 1 条派给林岚」→ `task_types` → `assign_task(type="经营改进", ref_id=报告号, metric="该催工厂", assignee="林岚", ...)`
