# 通话整理:总结 + 商机研判 + 下一步

## 什么时候用

用户要**某一通**通话的整理结果时用。典型说法:

- 「整理一下 TS-001」「这通电话帮我写个总结」
- 「这通电话里客户想要什么,有没有商机」
- 「跟蔡女士聊完了,下一步怎么跟」(先找到是哪一通)

## 什么时候不用

- **要一张清单**(「最近哪些通话里有商机」)—— 用 `call_opportunity` 不带参数,那一层免费,
  报的时候说清是候选不是结论。不要对清单里每一条都走这个技能。
- **问该不该联系某个客户**(为什么是他、为什么是现在)—— 那是 `revive_list`。
- **没有通话号、也说不出是哪个客户** —— 先问是哪一通,不要猜。

## 为什么要一步一步走

顾问隔三个月被提醒「去找她推月白马面裙」,第一句会问**凭什么**。
答得上来的是那句原话;答不上来,这条提醒和瞎猜没区别,而**顾问被瞎猜坑过一次就再也不看了**。
所以每一步都是在给「凭什么」留证据:原话从原文里抄,推荐从库里给的编号里挑。

## 第一步:拿原料

调 `call_opportunity(call="通话号")`。它返回:原文、客户提到的偏好、每个偏好对得上的在架商品、
**几条全都对得上的**、这位客户名下的方案和订单号,以及规则层的判断。

⚠️ 规则层**分不出「想要」和「随口一提」**,它的「是商机」只是候选。研判在第二步由你读原文来做。

再看「说话人怎么分的」:
- **按声道分的 / 演示数据** → 照常
- **模型按内容分的**(上门 / 到店的单声道录音)→ 照常整理,但总结里**必须写一句**
  「说话人是模型分的,请顾问核对这几句原话是不是客户说的」—— 模型可能把顾问的话标成客户的,
  而顾问当时在场,一眼就能看出来
- **没分出说话人** → 不判商机(JSON 里 `商机` 写 false),总结里照实说「这通录音分不清谁说的,判不了」

## 第二步:读原文,判是不是商机

**是商机**要同时满足:客户自己说出了一个具体的偏好(颜色 / 形制 / 纹样 / 场合……),
而且是**想要**,不是随口一提。

- 「齐胸襦裙听起来不错啊,但我先不急着定」—— 随口一提,**不是**
- 「随便看看」「帮朋友问问」—— 没有具体偏好,**不是**
- 「我想要月白色的,上次来没现货」—— **是**
- 顾问说的「我们进了一批红色的」**不算客户的偏好**,哪怕客户没反对

## 第三步:列诉求,每条带原话

每条诉求写成 维度 + 值 + 原话。维度只用这几个:
形制、面料、工艺、颜色、配饰、版型、纹样、场合、预算、工期、尺码、性别。

**不在这 12 个里的(气质、风格、审美、活动日期……)写进总结,不进 JSON** —— 它们上新时匹配不了。
场合的值用工具给的「场合只能写」里的词(婚礼婚服、日常通勤……)。
值只写那个东西本身(「缠枝」),**不加括号注释**(「缠枝(客户在考虑)」上新时匹配不上)。

**一个东西带着颜色就拆成两条**:「豆绿色云肩」= 颜色「绿」+ 配饰「云肩」(同一句原话可以用两次)。
配饰的值写分类名(云肩、璎珞、披帛……),「织金云肩」拆成 配饰「云肩」+ 工艺「织金」。

**原话必须从原文里客户说的那几行逐字抄**,一个字都不改。抄不出原话的诉求不要列。

## 第四步:定下一步

看「几条全都对得上的在架商品」:

- **有** → 下一步指向其中一两件(写上对上了哪几条)。客户名下有相关的方案,也可以指向方案接着谈。
- **是空的** → 店里眼下没有她要的那件。下一步写**搁置等什么**(把她要的那几个偏好写成字段,
  键只能是诉求维度,一个键一个值:`{"形制": "马面裙", "配饰": "云肩"}`,不是 `{"马面裙、云肩": …}` 也不是 `{"说明": …}`),
  上新时回捞池会拿它去匹配。**不要拿只对上一半的商品凑数** —— 要月白马面裙的客户,
  推一件月白褙子是在浪费顾问的电话。
- 不是商机 → 下一步可以不写;要写的话写清为什么不用跟(随口一提 / 只是陪朋友来)。

## 硬规矩(不许变通)

1. **原话必须逐字来自客户说的行。** 顾问的话不算,改写过的不算。
   **原话里还得说到那个东西**:诉求是「工艺 = 妆花」,原话里就得有「妆花」。
   顾问说「这件是妆花的」、客户回「哎这个倒是不错」—— 这不是她要妆花,**不要列这条**
   (颜色按色系认:值写「白」,原话说「月白」算说到了)。
   **挑原话时找她自己说出那个名字的那一句**,通常不止一句可选 —— 顾问推荐了一样东西,
   她回「好啊,那个有什么颜色」,这一句里有那样东西的名字才算数;只回「对对对,就是那个」的,
   换一句她自己说出名字的,找不到就不列这条。
2. **下一步只指向工具给出的编号**(商品 / 方案 / 订单)。不许编号,不许指别的客户的方案或订单。
3. **不给成单概率。** 不写「七成能成」「把握 70%」—— 给依据,不给数字。业务定的。
4. **这一步只整理,不写库。** 商机要顾问点头才落库;不要说「已经帮您建好商机」。
5. **回答末尾必须带一段 JSON**,格式见下 —— 系统和评测只读这一段。
6. **判了是商机,JSON 的下一步里至少一条要有 `指向` 或 `搁置等`。** 「确认尺码、推进成交」这种话可以写在
   `做什么` 里,但它要落到一件东西上(指向那件商品 / 那个方案),或者写清在等什么 —— 光有一句话,
   上新时回捞池拿不到东西去匹配,顾问隔三个月也不知道当初要推的是哪件。

## 出错了怎么办

| 情况 | 怎么办 |
|---|---|
| 工具说范围里没有这通电话 | 照实说「你能看的范围里没有这通」(可能号写错、或不归你看),**不要换个号猜** |
| 原文里说话人没标(分不清谁说的) | 不判商机,说明是数据问题;JSON 里 `商机` 写 false,并在总结里说清「判不了」 |
| 客户提到的偏好工具一个都没认出来,但原文里明显有 | 照原文列诉求(原话照抄),下一步写搁置等什么或「请顾问确认」,**别编商品号** |
| 「几条全都对得上的」为空 | 写搁置等什么(见第四步),不要凑数 |
| **原文里顾问当场拿出了货、客户说「就是这个」,但「几条全都对得上的」是空的** | 两边对不上:可能是库存数据没跟上,也可能顾问拿的那件其实差一点。**照实写出对不上**,下一步写「请顾问核实店里那件的商品号」,JSON 里写 `搁置等`(她要的那几个偏好)—— **不要信原文去编一个商品号,也不要挑一件只对上一半的凑数** |
| 客户说了预算或折扣数字 | 那是她的原话,可以作为「预算」诉求照抄;**你自己不要说任何成单的百分比** |

## 用哪些工具

`call_opportunity(call=…)`(原料,必调)· `get_scheme`(客户名下的方案详情,需要时)·
`get_order`(客户的订单,需要时)· `get_stock`(某件商品的现货,需要时)。

## 例子

总结写三五句给人看,然后附 JSON:

> 蔡女士来看马面裙,明确要月白色、素雅的,说上次来没现货。店里在架的月白款有 27 款、马面裙 10 款,
> 但**同时是月白又是马面裙的一条都没有**。建议先搁置,上新月白马面裙时再联系她。

```json
{"商机": true,
 "诉求": [{"维度": "颜色", "值": "白", "原话": "我想要月白色的,就是特别素雅那种,上次我来的时候您们没有现货。"},
          {"维度": "形制", "值": "马面裙", "原话": "对对对,我想来看看马面裙,就是那种……"}],
 "下一步": [{"做什么": "上新月白马面裙时联系她", "搁置等": {"颜色": "白", "形制": "马面裙"}}]}
```

有货时下一步写成:
`{"做什么": "约她来试这条", "指向": [{"类": "商品", "id": "lxys_…", "对上": {"颜色": "白", "形制": "马面裙"}}]}`
(`指向` 是列表,每项必须有 `类` 和 `id`;`类` 只用 商品 / 方案 / 订单 / 版型;
`对上` 写成 {维度: 值},只写真对上的那几条)
