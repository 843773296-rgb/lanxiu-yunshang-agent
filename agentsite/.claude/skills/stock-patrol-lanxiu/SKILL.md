# 标品库存巡检

> **澜绣云裳自有技能**(2026-11-06 用户拍:「把这份第三方技能优化为我的技能,然后删除原来的内容」)。
> 正文是我们自己的,不留第三方的任何框架、门槛和外部依赖。
>
> ⚠️ **它为什么是纯只读的**:这件事天生是**批量**的 —— 巡一次出十几条。
> 而批量场景正撞在这个项目已知的那条上:
> > **派错了和派对了,在库里长得一模一样;等发现的时候,顾问已经去做了。**
>
> 所以这个技能**不挂任何写口**。清单照旧给全,要派任务走原来派任务那条路、一条一条过 ——
> 代价是多一步手工,换来的是「这个技能永远不可能动到任何东西」从**结构**上成立,
> 而不是靠正文里一句「用户说派才派」。那句话只是约定:模型不问就写,没有任何东西会拦。
>
> ⚠️ **门槛一条都不许加回来**。这份正文里**没有**安全库存天数、周转红线、保本投入产出比、
> 「低于就砍」这类数 —— 不是忘了写,是**门店一次都没拍过板**,写进来就等于让一个
> 我们自己编的数替门店做决定。档位和补货点一律照 `stock_alert` 已拍过板的口径。
> 这件事有判据盯着:`agentsite/skill_body_check.py`(正文改了就红一次,红的时候要重新过一遍审查)。

## 什么时候用

要把**成品库存从头过一遍、分出要处理的**时:

- 「巡一遍库存,看看有什么要处理的」
- 「哪些货快断了 / 该补货了?」
- 「有没有看着有货其实发不出的?」
- 「哪些款压着卖不动?」

## 什么时候不用

- **问某一个商品 / 规格还有没有货** —— 直接 `get_stock(sku=…)` 或 `get_stock(spu=…)`,答**可用**件数
- **问面料还有多少米、能不能换现货面料赶工** —— 那是 `get_stock(material=…)` / `get_stock(craft=…)`,面料库存是另一摊
- **要求改库存数、调拨、下采购单** —— 本系统没有这些写口;补多少是采购的决定
- **要求把巡检结果派下去** —— 这个技能不派;把清单给用户,由他走派任务那条路一条条过
- **问销量排行** —— 用 `sales_rank`

## 用哪些工具(两个,都是只读)

- `stock_alert()` —— 四档全给;`stock_alert(scope="发不出" / "断货" / "快没了" / "卖不动")` 只要一档
- `get_stock(sku=…)` / `get_stock(spu=…)` —— 核对某一条的明细

**除这两个以外不调任何工具。** 尤其不调派任务 / 分派 / 改派那一类 —— 见上面那段。

## 第一步:取全量

调 `stock_alert()`,先记下返回头部的三样:**统计区间**、**在算的 SKU 有多少**、停用的几个不算。
报告第一句就写「这次巡了 N 个在售 SKU,销量数据从 X 到 Y」—— 看的人得知道这是全部还是一部分。

## 第二步:按四档过,每档说清找谁

| 档 | 是什么 | 该找谁 / 做什么 |
|---|---|---|
| **发不出** | 在手有货,但全被订单占用 —— 库存表上看着没问题 | **最先报**。说清是哪几张单锁着、是不是待付款一直没付,建议催付或释放;不是补货问题 |
| **断货** | 在手和可用都是 0 | 看它卖不卖得动:卖得动的建议交采购,一件没卖过的不必补 |
| **快没了** | 可用很少而且卖得动 | 按可售天数从急到缓;**该不该补看「补货点」**,补多少交采购 |
| **卖不动** | 有货、一件没卖过 | 只提醒,不建议改价、不建议下架 —— 那是商品运营的决定 |

另看「到了补货点的」那一栏:可用件数不少、但已经到补货点的也要报。

## 第三步:每条带上「凭什么」

每条写:SKU、商品、**可用**(不是在手)、可售天数、**这个天数按多少数据算的**(几天里几笔)。

- 「12 天(上架 20 天、3 笔)」和「12 天(上架 300 天、90 笔)」分量完全不同,**两样一起写**
- 可售天数是 **0** 的,照工具说清是「已经卖空了」还是别的
- 工具说「算不出」的,**原样写算不出和原因**(一件没卖过、只卖过一笔),不换算法凑数

## 第四步:出清单 + 建议

按「发不出 → 快没了 / 到补货点 → 断货 → 卖不动」排。每档最多列前几条,**写清这一档一共多少条、列了几条**。
末尾给建议(「建议今天催这 3 张单释放」「建议把这 5 个 SKU 交采购看补货」),**写成建议,不写成已安排**。

收尾那句话要写清**这件事还没被办**,例如:
「以上是清单和建议,**我没有派任何任务** —— 要派的话你在系统里逐条派,或者告诉我你要派哪几条、我把内容整理给你。」

## 硬规矩

1. **说「有货」只看可用 = 在手 − 已占用**,不看在手
2. **算不出的不许说成 0 天**,也不许退回成「低于 N 件就预警」—— 本系统明确不用固定件数当补货阈值
3. **补多少件不说**:补货点回答「什么时候该补」,数量是采购的决定
4. **只读**:不改库存、不改价、不下架、**不派任务**
5. **不完整不报成完整**:工具只返回了一部分(某一档报错、被截断)时,写清少了哪部分
6. **不引入任何没拍过板的阈值**(安全库存天数、周转天数红线、保本线之类);档位和补货点只照 `stock_alert` 的口径

## 出错了怎么办

- **`stock_alert` 报错** → 照实说这次巡检没做成,**不拿 `get_stock` 逐个查去凑一份「全量」**
- **只有一部分档返回了** → 报已有的档,并写「X 档没取到,这不是全部」
- **数据看着不对**(可用是负数、已占用大于在手)→ **停下来把那几条原样列给用户**,问是不是库存流水没记全,不替它修正
- **没有订单数据**(统计区间写「没有订单数据」)→ 只报发不出 / 断货两档(这两档不靠销量),快没了 / 卖不动写「没有销量数据,判不了」

## 例子(示例)

问:「巡一遍库存,看看有什么要处理的。」(下面只是格式示意,**真答时一律照工具返回**)

1. `stock_alert()` → 在算的 SKU N 个,统计区间 X → Y
2. 发不出 3 条:「某 SKU 在手 4、已占用 4、可用 0 —— 建议查占用它的订单是否待付款」
3. 快没了 / 到补货点 6 条(列前 5,写「共 6 条」),每条带可售天数和「几天里几笔」
4. 卖不动 40 条:只报总数和压得最久的几条,说明只是提醒
5. 收尾:「以上是清单,**我没有派任何任务**;要派的话逐条派,或者告诉我派哪几条。」
