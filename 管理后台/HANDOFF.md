## 这一轮(09-27)最该被记住的三条

**① 「我手敲 curl 验过」不算验过。**
`docs/实现进度.md` 第一版跑出来说:工作流和智能体那 12 条接口里**只有 2 条被自动化
测试打过**。其余 10 条我确实验过 —— **但是手敲的**:不留痕、不可重跑、换机器就没了。
我在提交信息里写过「整条链在真库上走通」,那句是真的,**但没人能再跑一遍它**。

> **一次没留下可重跑证据的验证,和没验证之间的差别,只存在于验的人脑子里。**

补成 44 条断言之后,**第一次跑就抓到一个真 500**:`GET /execution-runs` 列表,
`:w` 的类型 PostgreSQL 推断不出来(`AmbiguousParameter`,要 `cast(:w as text)`)。
它活下来的原因:**我只测了详情、没测不带参数的列表** ——
列表是最容易被当成「不用测」的接口,它看起来只是把详情少显示几个字段。

**② 「验过」这个词要做硬:运行时记账,不是扫测试文件。**
扫文件会把「被注释提到」「拼在没执行的分支里」也算成验过 —— **判据比它声称的弱**。
现在是中间件记 FastAPI **实际匹配到的路由模板**(`AIMC_TRACE_ROUTES`),
`make progress` 带记账跑测试再读账。棘轮写死在 实现 24 / 验过 23,只许涨。
⚠️ 但**打过一次不等于断言对** —— 报告正文写着这句:它回答「有没有被碰过」,
不回答「对不对」。而**没有账本时报「这不叫通过,叫没查」,不报「0 条验过」**。

**③ 换个位置就等于做了一次「从零」。**
搬进澜绣仓库建 venv 第一步就炸:**`requirements.lock` 里没有 fastapi 和 uvicorn** ——
而这个后台是 FastAPI 跑的。旧目录的 `.venv` 能跑,是因为当初有人 ad-hoc 装过,
**而 lock 从没记上**。在旧位置永远发现不了:那里的 venv 一直在。
和「本地留着历次产物、CI 每次从零」是同一族。

顺带一个小坑:修那个 500 时我把说明写成 `text()` 里的 `--` SQL 注释,
而注释里有中文冒号 → **SQLAlchemy 把 `:那份报告不问` 当成了绑定参数名**。
`text()` 里的 `--` 对它不透明,它只认 `:name` 这个词法。
**SQL 字符串里不许出现 `:` 开头的自然语言。**

## 上一轮(09-26)最该被记住的五条判据

它们不在 git diff 里 —— diff 只显示「判据长什么样」,不显示「为什么不是另一种写法」。

**① 变量可用性靠支配关系,不靠在图里找名字。**
规格 §7.2 明写「不能仅检查字符串里有没有出现某个变量名」。那条禁令防的图是:
条件分支一路有翻译节点、一路没有,下游读翻译的输出。**那个节点存在**,
所以按名字找的校验器说合法;跑中文样例时下游读到一个不存在的字段,
而画布上两条线都连着。正确判据在图论里有名字:m 支配 n = 从入口到 n 的每条路径都必经 m。
「引用尚未生成的变量」和「只在某一分支有值的变量被必填使用」**是同一个式子**。
落点 `runtime/validator.支配集()`。

**② 逻辑哈希按位置剥非语义字段,不按名字剥;密钥扫描反方向,全树深扫。**
第一版在整棵树上按键名剥 `layout/x/y/name`,冒烟当场撞到:`config` 里恰好叫 `x`
的业务字段改了**哈希不变** —— 那一版和上一版在发布清单上是同一份内容。
两个判据方向相反是故意的:剥错了是静默(改了逻辑哈希没变),
扫错了是吵闹(拒绝冻结)。**判据往哪边偏,要看偏错了的代价朝哪边。**

**③ 图校验的判据是集合相等,不是「至少报了这一条」。**
后者放过**多报**,而多报的代价不比少报小:人会去修一个没坏的地方,改完还是红,
然后学会忽略校验器。这条判据当场抓到两件事 ——
一个空的 loop 容器校验器一个字没说(漏报,因为它只遍历「有节点的作用域」);
开始节点上那个假超时被报了两条(多报)。**多报是「至少一条」那种判据永远抓不到的。**

**④ 节点通用字段的「不适用」双向对账。**
规格 §6:「不能出现全节点通用却不生效的设置」。判据不能问「你声明了哪些不适用」
(自说自话),所以每个节点单独声明「会不会发一次能超时的外部调用」,然后两边都查。
登记时就抛 —— 错法活不过 import。

**⑤ 期望值不许从被测实现算出来。**
条件真值表(52 条)和图夹具(17 张)的期望都是**手写在 JSON 里的**;
执行测试里「模型被调了几次」由 **mock 那一侧**数,不听执行器自报。
附录 C.3 原话:「真值来源:独立人工预期,不由编译器生成」。

**② 报错指错方向(第 N 次)。**
`prompt_versions` 缺 `(project_id, key, version_no)` 唯一约束,于是我一段写死
`version_no=1` 的演示数据造出「同一个 key 两个 v1」,库里完全合法。
抓到它的是一条**测别的事情**的断言(它拿「版本条数+1」当「最大版本号+1」的替身)。
报出来的理由是「版本号没前进一格」,真相是「演示数据里有两个 v1」。
**一堆地方在隐含依赖某个不变量时,就该把那个不变量钉成约束。**

**③ 少算一层 dirname(第二次)。**
`landing.py` 算仓库根少写了一层,落点核对报「validator.py 不存在」而文件明明在。

现在报错打绝对路径 + 一条 assert 直接钉住仓库根。

**④ 改唯一约束会打红调用点 —— 那是好事。**
`ON CONFLICT (event_key)` 在 PostgreSQL 里必须**精确匹配**一个唯一约束,
约束一改语句当场编译不过。反过来想:要是「**加**一条复合约束而**留着**单列那条」,
worker 一个字都不用改,而跨项目撞键那个漏一点没修好。

## 试过并否决的(09-26 那一轮)

**① 给生产代码加一个「跳过校验」的开关,好让测试能测执行器那道第二闸。**
「把密钥绑进模型节点」这张图过不了编译器(校验器先拦了),所以测不到执行器里
`取值()` 对 secret 的拒绝。否决理由:**那个开关会活下来,而且会有人用它。**
改成把判据拆两条:①校验器拦住那张图 ②`取值()` 这个单元自己抛 ——
而它防的正是「绕过校验直接构造出来的计划」。

**② 把 Run Coordinator 标成「已落地」,因为创建/排队/事件确实有了。**
否决:暂停继续取消、检查点恢复、人工等待释放租约、核实外部状态都还没有,
那几件是它职责的大头。**把「一部分做了」记成「落地了」,是落点表最容易失效的方式。**

**③ `_policy` 后缀保持 TEXT。**
编排域里 `retry_policy` / `confirmation_policy` / `idempotency_strategy` 全是结构化对象,
所以把后缀翻成 JSONB。两个老字段(`retention_policy` / `data_egress_policy`)
靠「显式优先于后缀」保住 TEXT,**并且有一条断言专门钉这件事** ——
删掉那两行不会报错,只会让库里两列悄悄变成 JSONB。

**④ 审批工具动作默认给管理员。**
否决:那等于「能配这个 Agent 的人能批准它要做的事」,人工闸只拦手滑不拦配置错误。
代价说清了:一个没拿到专项授权的管理员**建不出审核者** —— 这是有意的,
它逼着第一个审核者由一条留在审计里的显式授权产生。

## 试过并否决的(上一轮,别重做)

- **让 FastAPI 从 handler 反推 OpenAPI** —— 否决。那样**契约变成实现的影子**:
  handler 漏了一个鉴权、OpenAPI 跟着漏,而它看起来仍然是一份完整的契约。
  契约在前,代码在后(规格 §17.4 第 1 步也是这个顺序)。
- **给字段类型一个 TEXT 兜底** —— 否决。一张全是 TEXT 的表能建起来、能跑、看着正常,
  直到有人往 `amount` 里写了字符串,或者 `created_at` 按字典序排。认不出就抛。
- **前端手写一份 interface** —— 否决。等于把契约抄第三遍,而**漂的时候编译还是过的**。
- **React + TS + Vite + AntD**(规格默认)—— 这一轮**记录在案地偏离**了:
  API 已经是契约边界,前端换成 React 只需重写 `apps/web/`;把预算花在 build 工具链上
  换来的是更少的可验证功能。**不是说规格错了,是这一轮的取舍。**
- **「项目级实体都带 project_id」当判据** —— 同源谬误:`project_id` 正是依据
  「范围==项目级」加上去的,把表改成组织级它就从被检查的集合里消失,**永远不会红**。
  改成从另一头判:不按项目隔离的要写明理由 + 数量棘轮 + 点名几张必须在项目范围内。
- **把豁免/例外写在检查脚本里** —— 否决。藏在检查里的豁免是**看不见的知识**:
  读实体的人不知道它被放过了。改成登记表上的显式标记(`内容寻址`)。
- **在生成的文档里写 git 短哈希** —— 否决。每次提交后文档立刻又"脏",
  而**一个永远脏的生成文件会训练人忽略「脏」**。
- **端到端断言「存出 v1」** —— 否决。第二次跑就红(内容没变、服务端正确返 409),
  而**第二次跑的红和真的坏了在输出上一样**。改成「版本号前进一格」+ 变更说明带随机后缀。
- **攻击测试断言「跑完某张表是空的」** —— 否决。那假设了空库,灌演示数据后它变红,
  **而报的理由是「攻击测试没还原」,完全指错方向**。改成跑前拍数、跑后对比。
- **worker 取任务用「先 SELECT 看有没有人占,再 UPDATE 占上」** —— 否决,
  中间的窗口让两个 worker 同时通过检查。一条条件 UPDATE
  (`WHERE 租约空了 or 已过期` + `FOR UPDATE SKIP LOCKED`)把两件事合成一件。
- **只用租约、不要心跳** —— 否决。一个卡死但租约没到期的 worker 让任务
  **看起来正常**,而「正在跑」和「卡住了」在状态上一模一样。
  反过来只用心跳也不行:两个 worker 能同时改同一条。**这是两件事。**
- **认不出的错误码当瞬时故障重试** —— 否决。未知不等于瞬时故障,
  而把未知当瞬时故障会让一个必然失败的任务反复烧钱。默认**不重试**。
- **退避不加抖动** —— 否决。同一批一起失败的任务会在同一时刻一起重试,
  **它们本来就是被同一个故障打倒的,于是又一起打过去**。
- **API 建任务时写一条「开始」事件** —— 否决。到那一刻一个模型都没调,
  而事件流上出现两个「开始」(API 一个、worker 一个)之后,
  **读的人分不清哪个是真起点**,「从提交到真的开跑等了多久」就算不出来了。
  改成「已受理」。

## 两条贯穿的纪律(违反了检查会红)

**① 「不知道」必须能表达,而且不许用 0 代替。**
费用 `amount_known` / 评分 `value_known` / 列表 `total` 允许 null /
训练的「状态待核实」**不是终态**(把查不到显示成失败,会让人去重跑一个还在烧 GPU 的任务)。

**② 「结构性保证」必须被攻击过。**
规格说跨项目引用靠数据库约束挡住 —— 而**一条从没被攻击过的「结构性保证」,
实际上仍然只是约定**。`tests/integration/test_project_isolation.py` 做 5 次真实攻击,
外加**一条正向对照**(否则"全被拒"可能只证明了"什么都写不进去")。
这一轮它逮到两个真漏:`traces` 没登记依赖 → 外键一个都没建;
项目级表**根本没有指向 projects 的外键** → 编一个不存在的 project_id 能直接写进去。

## 三处我自己栽过、容易再栽的(上一轮)

**① 空判据。** `ok3 or "不许从" in 说3` —— 两种情况都为真,**永远不会红**。
写完一条断言先问:**它在什么情况下会红?** 答不出来就是空的。

**② 往 `sys.exit()` 后面追加断言。** 加了两节,一条都没跑 ——
而**它们不跑的时候,总数看起来只是「没变」**。`tests/e2e/test_api_flow.py`
的汇总前留了记号。

**③ 测试把「当前实现」当成「该有的行为」。** 旧断言假设 API 同步返回结果,
改成真异步之后它们红了,**而报的理由是「脱敏没生效」,真相是「还没跑」** ——
实现往对的方向改了,测试反而指错方向。

## 环境上的坑

- **pgvector 是 brew 装的**(0.8.6),不是镜像自带。`make doctor` 会验。
- **Docker 守护进程没跑,而且没有 `docker compose` 子命令** —— 所以不用 Compose,
  用原生 PG + Redis(Redis 要手起:`redis-server --daemonize yes`)。
- **对象存储用文件系统适配器**(没 Compose 起不了 MinIO)。接口不变。
- 依赖装在 `.venv`(不进版本库),锁在 `requirements.lock`。
