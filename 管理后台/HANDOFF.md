### ① ⚠️ 仓库级地雷:**两个 `adapters.py`,谁先 import 谁赢**

    services/api/app/contract/adapters.py   适配器契约登记

`knowledge_api.py` 先加载,所以服务进程里 `sys.modules["adapters"]` 是知识层那份。

表现是 `AttributeError: module 'adapters' has no attribute '找'`,
而**报错的地方离真因很远**:我单独跑同一段代码是好的
(独立进程里 sys.path 顺序不同),**只在服务里炸**。

> **「同一段代码在两个进程里 import 到不同的模块」,而两边都不报导入错误。**

`connections_api.py` 用 `importlib` 按路径显式加载绕开了。

真修法是给其中一个换名字(或改成包内相对导入),但那要动 3 处现有引用。

### ② ⚠️ 一道防泄漏的检查,会拦住「谈论泄漏」的那句话

判据第一版返回的是**字段名**(那几个英文凭据词),于是错误体里出现了凭据类词,
**`errors.泄密检查` 把整个响应判成泄漏 → 500**。今天第二次。

它分不出「这里有一个凭据」和「这里在说凭据这件事」——**也确实分不出**。
所以该改的是调用方:判据改成**只报位置**(「顶层第 4 个字段」)。
那个请求体是调用方自己写的,位置对他够用。
→ **凡是要写进错误体的文案,别用那几个英文词。**

### ③ 三条设计,别写回去

- **明文当场拒,不是收下后忽略** ——「明文一旦进过请求体,

- **`config_hash` 不含密钥**:换密钥不算换配置;而混进去会让**哈希本身成为侧信道**。
- **列表只给形状,不做截断** —— 截到前几个字符,那几个字符仍然是原文。

## 🧭 2026-09-28 夜 · 应用与发布八条(71/70)—— 整条链终于有终点了

前面几块管的是「有哪些版本」,而**发布清单是它们的「合起来」**,
环境指针回答「**哪一份正在服务**」。没有这一块,前面所有版本管理都停在
「我们存了很多版本」,而**「上周二在跑哪一版」答不出来**。

### 四条硬规矩,各自靠什么成立(这张表是这一块的全部)

| 规矩 | 靠什么 |
|---|---|
| 清单里全是确切版本,不许「用最新的那个」 | **表结构**:每项依赖都是一列版本 id,`latest` 没地方放 |
| 生产只认审核过的清单 | 判据,而且判的是「审的是不是**这一份**」 |
| 指针变更原子 | **事务 + 乐观锁**,不是判据 |
| 回滚是一次新的部署动作 | 只动指针 + 新记一行,**历史清单一个字不改** |

第一条最值得抄:**能用约束表达的不要用判据表达** ——
判据只在有人调用时生效,而一个放不下「最新」的列,任何时候都放不下。

### 三条别写回去的设计

- **「审过」不是布尔**,存的是 `审的哈希`。只存 `approved=true` 的话,
  **改完再发**这条路就是通的,而且不报错。
- **回滚不许改历史** —— 改了的话,「上周二在跑哪一版」会变成现在这一版,
  而那正是回滚之后最需要问的问题。
- **按环境执行不收调用方传的版本号**(422 `VERSION_NOT_ACCEPTED`);
  没绑定的环境**不回落到最新**(422 `NO_BINDING`)——
  静默用最新的话,「跑的是哪一版」取决于谁最后发了个新版本。

## 🧭 2026-09-28 夜 · 微调训练链七条做完(63/62)

### ① 骨架是规格开篇第 4 条,记住这一句就够了

> **训练完成仅代表得到产物;须经过登记、兼容检查、评测、部署与发布才能服务用户。**

四个各不相同的状态:**训练完成 → 有产物 → 产物可用(校验过)→ 在服务用户(部署了)**。
**把任意两个合成一个,界面上看起来一切正常** —— 一个没校验过的产物会显示成「可以用了」。
所以三道闸分别守三个边界,而不是一道「训练成功了吗」。

`mock` 的判断是**三值**的:True / False / **None(说不清)**,而 **None 也拒部署** ——
**未知不是「不是」**。而且它**从训练任务推,不当参数收**:
允许登记产物时自己声明「我不是 mock」,等于把铁律交给调用方自觉。

### ② 三个真 bug,两个是端到端第一次跑抓到的

**一、连点两次取消,系统就自己宣布「已取消」。**
`直接取消` 写成「状态机允许走到『已取消』就走」,而「取消请求中 → 已取消」
那条边**只该由后台确认时走**。
⚠️ **同一条判断我在 `runctl.py` 里写过(两次提交之前),换到这个模块又漏了。**
> **教训不会自动跟着代码走 —— 它只跟着「被写成判据的地方」走。**

**二、「被拦」的审计被拒绝本身回滚掉了。**
部署被闸拦住时,我在事务里 `_审计(...)` 然后当场 `raise` ——
那个异常把同一个事务里的审计行**一起回滚了**。
两件事各自都对,凑在一起的结果是**审计消失**。
> **拒绝的记录,不能由拒绝本身回滚掉。** 留痕先落库,抛错留到事务外。
> (提交训练那条恰好躲过了 —— 它的 raise 本来就在事务外,而那是巧合不是设计。)

**三、一个人都不能提交训练。** `提交真实训练` 只有 trainer / 被授权的 admin,
而 demo 项目里**一个 trainer 都没有** —— 又一次「拦得住但没有放行入口」,
而它在检查上是绿的。`tools/seed_training.py` 第一件事就是补人。

`for update` 在这里本来就多余:同一个构建不会被两个 Worker 同时处理,

别的来源不该被迁移代填一个版本号:**填错的版本号比空的更糟**,

## 上一轮(09-26)最该被记住的五条判据

它们不在 git diff 里 —— diff 只显示「判据长什么样」,不显示「为什么不是另一种写法」。

**① 变量可用性靠支配关系,不靠在图里找名字。**
规格 §7.2 明写「不能仅检查字符串里有没有出现某个变量名」。那条禁令防的图是:
条件分支一路有翻译节点、一路没有,下游读翻译的输出。**那个节点存在**,
所以按名字找的校验器说合法;跑中文样例时下游读到一个不存在的字段,
而画布上两条线都连着。正确判据在图论里有名字:m 支配 n = 从入口到 n 的每条路径都必经 m。
「引用尚未生成的变量」和「只在某一分支有值的变量被必填使用」**是同一个式子**。
落点 `runtime/validator.支配集()`。

**② 逻辑哈希按位置剥非语义字段,不按名字剥;密钥扫描反方向,全树深扫。**
第一版在整棵树上按键名剥 `layout/x/y/name`,冒烟当场撞到:`config` 里恰好叫 `x`
的业务字段改了**哈希不变** —— 那一版和上一版在发布清单上是同一份内容。
两个判据方向相反是故意的:剥错了是静默(改了逻辑哈希没变),
扫错了是吵闹(拒绝冻结)。**判据往哪边偏,要看偏错了的代价朝哪边。**

**③ 图校验的判据是集合相等,不是「至少报了这一条」。**
后者放过**多报**,而多报的代价不比少报小:人会去修一个没坏的地方,改完还是红,
然后学会忽略校验器。这条判据当场抓到两件事 ——
一个空的 loop 容器校验器一个字没说(漏报,因为它只遍历「有节点的作用域」);
开始节点上那个假超时被报了两条(多报)。**多报是「至少一条」那种判据永远抓不到的。**

**④ 节点通用字段的「不适用」双向对账。**
规格 §6:「不能出现全节点通用却不生效的设置」。判据不能问「你声明了哪些不适用」

#### 三件和原计划不一样的(别以后当成漏做)

**① 接口是四条,不是规格写的两条。**
规格那两条假设 S3 兼容对象存储 —— 「上传地址」是**预签名 URL**,后端不碰字节。
首版是文件系统适配器(README 早就登记过这条偏离),而**文件系统没有预签名 URL**,
所以必须自己有个接收端 `PUT /uploads/{id}/bytes`,否则「服务端算哈希」没有字节可算。
另加 `GET /uploads` 给界面列「传过什么、哪些没过」。

两条都**登记进了 `contract/endpoints.py`**,不是偷偷加 ——
没登记的接口不会出现在任何清单里,于是「接 S3 时要删掉它」没有任何地方记着。
⚠️ 接 S3 的时候:删掉 PUT 那条、`上传地址` 换成预签名 URL、
`complete` 改从 `storage.读出` 拿字节(**接口不用动**)。

**② 校验是「真的调一次解析器」,不是自己判断格式。**
自己发明一套「像不像文本」的判断,两套判断迟早不一致:
判松了 → 坏文件在库里写着「已校验」,建索引时炸,而**错误指向解析器**;
判严了 → 用户手里一份正常资料传不上来,且没办法绕过。
「这份字节能不能用」只有**真正的消费者**答得准。
代价:校验要花解析的时间(几十毫秒),而且**解析器版本变了结论可能变**,
所以结论里记了解析器版本。

**③ 校验没过返回 200 + `通过=false`,不是 4xx。**
请求本身成功了(我们确实校验了、并把结论存下来了)。判成 4xx 前端会当
「请求出错」去重试,而重试一万次结论都一样 —— **一个坏文件不是一次失败的请求**。

#### 顺带补掉的一个状态机的洞

`已放弃`(要了地址没传)原来**到不了** —— 契约里写着这一档,而没有任何代码能推到它。
**一档到不了的状态比少一档更糟**:以后有人查「放弃了多少」,查出来永远是 0,
他会当成「没人放弃过」。现在有 `tools/abandon_stale_uploads.py`(默认 dry-run,
判断在 `upload_rules.该放弃吗()`,纯函数所以边界能测)。

#### 这一块栽的三个坑(两个是同一族的第 N 次)

**① `:st is null` 缺 cast** —— PostgreSQL 从 `IS NULL` 推不出参数类型。
今天这一族的**第三次**(前两次是 `jsonb_build_object`)。
⚠️ **`tools/sql_lint.py` 早就有这条规则,是我写完没跑它**,等服务报 500 才发现。
教训不是「要加规则」,是**写完 SQL 就跑一次体检,别等接口报错**。

**② 把 `:st` 的说明写进了 SQL 注释** —— `text()` 对 `--` 不透明,注释里的 `:st`
又被当成一个绑定参数。这是同一天第二次,两次都是 sql_lint 抓出来的。
说明一律写在 **Python 注释**里。

**③ 咬合测试自己替被测对象补作业。** `支持的后缀 = PS.支持的后缀` 是**导入时快照**,
而我的咬合同时改了 `PS` 和 `UR` 两边,于是它绿了 —— 它证明的是「我改得对」,
不是「代码对」。改法:`支持的后缀()` 改成**每次调用都问解析器**,
咬合只改解析器那一边。验过:改回快照那一版,红 2 处。

- **「项目级实体都带 project_id」当判据** —— 同源谬误:`project_id` 正是依据
  「范围==项目级」加上去的,把表改成组织级它就从被检查的集合里消失,**永远不会红**。
  改成从另一头判:不按项目隔离的要写明理由 + 数量棘轮 + 点名几张必须在项目范围内。
- **把豁免/例外写在检查脚本里** —— 否决。藏在检查里的豁免是**看不见的知识**:
  读实体的人不知道它被放过了。改成登记表上的显式标记(`内容寻址`)。
- **在生成的文档里写 git 短哈希** —— 否决。每次提交后文档立刻又"脏",
  而**一个永远脏的生成文件会训练人忽略「脏」**。
- **端到端断言「存出 v1」** —— 否决。第二次跑就红(内容没变、服务端正确返 409),
  而**第二次跑的红和真的坏了在输出上一样**。改成「版本号前进一格」+ 变更说明带随机后缀。
- **攻击测试断言「跑完某张表是空的」** —— 否决。那假设了空库,灌演示数据后它变红,
  **而报的理由是「攻击测试没还原」,完全指错方向**。改成跑前拍数、跑后对比。
- **worker 取任务用「先 SELECT 看有没有人占,再 UPDATE 占上」** —— 否决,
  中间的窗口让两个 worker 同时通过检查。一条条件 UPDATE
  (`WHERE 租约空了 or 已过期` + `FOR UPDATE SKIP LOCKED`)把两件事合成一件。
- **只用租约、不要心跳** —— 否决。一个卡死但租约没到期的 worker 让任务
  **看起来正常**,而「正在跑」和「卡住了」在状态上一模一样。
  反过来只用心跳也不行:两个 worker 能同时改同一条。**这是两件事。**
- **认不出的错误码当瞬时故障重试** —— 否决。未知不等于瞬时故障,
  而把未知当瞬时故障会让一个必然失败的任务反复烧钱。默认**不重试**。
- **退避不加抖动** —— 否决。同一批一起失败的任务会在同一时刻一起重试,
  **它们本来就是被同一个故障打倒的,于是又一起打过去**。
- **API 建任务时写一条「开始」事件** —— 否决。到那一刻一个模型都没调,
  而事件流上出现两个「开始」(API 一个、worker 一个)之后,
  **读的人分不清哪个是真起点**,「从提交到真的开跑等了多久」就算不出来了。
  改成「已受理」。

## 两条贯穿的纪律(违反了检查会红)

**① 「不知道」必须能表达,而且不许用 0 代替。**
费用 `amount_known` / 评分 `value_known` / 列表 `total` 允许 null /
训练的「状态待核实」**不是终态**(把查不到显示成失败,会让人去重跑一个还在烧 GPU 的任务)。

**② 「结构性保证」必须被攻击过。**
规格说跨项目引用靠数据库约束挡住 —— 而**一条从没被攻击过的「结构性保证」,
实际上仍然只是约定**。`tests/integration/test_project_isolation.py` 做 5 次真实攻击,
外加**一条正向对照**(否则"全被拒"可能只证明了"什么都写不进去")。
这一轮它逮到两个真漏:`traces` 没登记依赖 → 外键一个都没建;
项目级表**根本没有指向 projects 的外键** → 编一个不存在的 project_id 能直接写进去。

## 三处我自己栽过、容易再栽的(上一轮)

**① 空判据。** `ok3 or "不许从" in 说3` —— 两种情况都为真,**永远不会红**。
写完一条断言先问:**它在什么情况下会红?** 答不出来就是空的。

**② 往 `sys.exit()` 后面追加断言。** 加了两节,一条都没跑 ——
而**它们不跑的时候,总数看起来只是「没变」**。`tests/e2e/test_api_flow.py`
的汇总前留了记号。

**③ 测试把「当前实现」当成「该有的行为」。** 旧断言假设 API 同步返回结果,
改成真异步之后它们红了,**而报的理由是「脱敏没生效」,真相是「还没跑」** ——
实现往对的方向改了,测试反而指错方向。

## 环境上的坑

- **pgvector 是 brew 装的**(0.8.6),不是镜像自带。`make doctor` 会验。
- **Docker 守护进程没跑,而且没有 `docker compose` 子命令** —— 所以不用 Compose,
  用原生 PG + Redis(Redis 要手起:`redis-server --daemonize yes`)。
- **对象存储用文件系统适配器**(没 Compose 起不了 MinIO)。接口不变。
- 依赖装在 `.venv`(不进版本库),锁在 `requirements.lock`。
