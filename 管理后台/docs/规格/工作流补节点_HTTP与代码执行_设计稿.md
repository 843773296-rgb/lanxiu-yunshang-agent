# 工作流补节点:HTTP 请求与代码执行 · 设计稿(待拍板,未实现)

> 2026-11-12。来由:用户 10-26 拍「workflow 直接复刻 dify」「代码执行放进隔离沙箱」。
> 同一批里「列表操作」「文档提取器」两个**纯内部、无安全面**的节点已经实现;
> 这两个节点**一个会出网、一个会跑用户写的代码**,每一个都开了一扇新门,所以**只出设计稿,不写代码**。

| 现在有的 | 在哪 | 和这两个节点的关系 |

| 编辑器菜单 | `apps/web/wf_canvas.js` | 两个节点现在置灰,写着「还没做」 |

## 1. HTTP 请求节点

**用户感觉得到什么**:流程里加一步「去调某个外部接口」(查物流、发企业微信、拉天气),不用找研发写工具。
**锁死什么**:一旦允许流程配置者自己填地址,后台就有了一条「从服务器内部发请求」的通道 —— 这正是 SSRF 的入口。

### 决定 H1:能访问哪些地址(出网白名单)

| 选项 | 说法 | 代价 |
|---|---|---|
| A. 只能选**已登记的工具连接**(复用「允许的端点」),节点里不许手填地址 | 配置者从下拉选「物流查询(已登记)」,只能拼路径和参数 | 加一个新地址要找管理员先登记;最安全,和现有工具连接同一套 |
| B. 项目级域名白名单,节点里手填地址,但域名必须在白名单里 | 管理员维护一张域名表,配置者自由拼 URL | 灵活;白名单粒度是域名,同域名下所有路径都能打 |
| C. 不限地址,只拦内网 | 和 Dify 默认行为接近 | 任何配置者都能让服务器去访问任意外网地址,出了事查不到「本该能访问什么」 |

**推荐 A**:规格要求「执行域名和最终目标检查」,而「允许的端点」已经是一张必填白名单,复用它不另立第二份。

### 决定 H2:SSRF 怎么防(和 H1 叠加,不是二选一)

不管 H1 选哪个,下面三条**建议都做**(这是规格 §17.4 的最低线,不算可选项):
① **解析后的 IP** 落在内网 / 回环 / 链路本地 / 云元数据地址段一律拒(不只看域名字符串 —— 一个指向 127.0.0.1 的外网域名能绕过字符串检查);
② **重定向每一跳重新检查**,或者干脆不跟随重定向;
③ 发请求用的就是检查过的那个 IP(防 DNS 第二次解析换了地址)。

真正要拍的是**重定向**:

| 选项 | 代价 |
|---|---|
| A. 不跟随重定向,收到 3xx 这一步失败并显示跳去哪 | 少数接口靠重定向工作,会用不了 |
| B. 跟随,最多 N 跳,每跳都按 ① 重查 | 实现复杂一点;每跳都是一次新的检查点 |

**推荐 A**(先严后松;真遇到靠重定向的接口再开 B)。

### 决定 H3:密钥怎么给

| 选项 | 说法 | 代价 |
|---|---|---|
| A. 密钥挂在**工具连接**上(H1-A 的配套),节点只选连接,请求头由 `secretref.py` 在发送那一刻加上 | 配置者看不到也碰不到密钥 | 换密钥只改一处;节点里没有任何地方能写密钥 |
| B. 节点里选「密钥引用」填进某个请求头 | 灵活 | 配置者可以把密钥填进 URL 查询串、请求体 —— 那些地方会进运行记录和日志 |
| C. 允许在节点里直接填明文 | — | 违反红线「API key 不进仓库 / 不进库」,**不建议列为选项**,写在这里只是说明为什么排除 |

**推荐 A**。另外不管选哪个:运行记录里**请求头一律打码**,响应体按现有打码规则过一遍再存。

### 决定 H4:超时与大小上限

| 项 | 选项 | 推荐 |
|---|---|---|
| 单次超时 | 5 秒 / 15 秒 / 30 秒(可在节点里往小调,不能往大调) | 15 秒;节点登记成「调用外部」,超时 / 重试三件套自动生效 |
| 响应体上限 | 1 MB / 5 MB(和上传上限对齐) / 10 MB | 1 MB,超过这一步失败(不截断后假装完整) |
| 重试 | 只重试读请求(GET) / 读写都重试但写要幂等键 | 只重试 GET;POST 这类写操作不自动重试(规格 §8:超时不代表对方没做事) |

### 决定 H5:谁能配

| 选项 | 代价 |
|---|---|
| A. 能编辑工作流的人都能加 HTTP 节点,但只能选已登记连接(配合 H1-A) | 登记连接这一步已经是管理员把关 |
| B. 只有「配置密钥与预算」权限的人能加 | 业务配置者想用得找管理员 |
| C. 能加,但含 HTTP 节点的版本**发布前要管理员审核** | 多一道审批流程 |

**推荐 A**(把关放在「登记连接」那一步,不放在每次加节点)。

### 决定 H6:写操作(POST/PUT/DELETE)算不算「业务写入」

| 选项 | 代价 |
|---|---|
| A. 一期只开 GET(只读),写操作还是走「业务动作」那条有人工核对的路 | 发企业微信这类需求暂时做不了 |
| B. 开写操作,但必须先过一个人工核对节点 | 和现有「写入前人工核对」规矩一致 |
| C. 开写操作,不强制核对 | 一条配错的流程可以批量写外部系统,没人拦 |

**推荐 A**,真要写再上 B。

## 2. 代码执行节点

**用户感觉得到什么**:规则拼不出来的数据处理(复杂换算、正则抽取)可以写一小段 Python / JS。
**锁死什么**:这是整个后台**第一处执行用户写的代码**。选错沙箱,等于把 Worker 的权限(库连接、模型密钥、对象存储)交给每一个能编辑流程的人。

### 决定 C1:沙箱选型(最贵的一条)

| 选项 | 隔离边界 | 本机现状 | 代价 |
|---|---|---|---|
| A. **独立容器**(Docker / gVisor),每次执行起一个无网络、只读根文件系统、限 CPU / 内存的容器 | 进程 + 文件系统 + 网络命名空间;gVisor 再加一层系统调用拦截 | 本机有 docker 命令,但 README 登记过「Docker 守护进程没跑、没有 docker compose 子命令」—— 要先把运行时起起来并定成常驻 | 冷启动几百毫秒;隔离最可靠,也是 Dify 自己 sandbox 的路数 |
| B. **WebAssembly 解释器**(如 Pyodide / QuickJS-wasm),在 Worker 里跑但只给内存,不给文件和网络 | wasm 内存沙箱,宿主不暴露任何系统接口就什么都摸不到 | 不用装系统级东西 | 只能用纯 Python / JS 标准库的子集,第三方包基本没有;启动快 |
| C. 子进程 + 系统限制(seccomp / macOS sandbox-exec + 资源限制) | 同一台机器上的另一个进程 | 现成 | **最弱**:macOS 的 sandbox-exec 已被苹果标为弃用,Linux 上 seccomp 规则写漏一条就是逃逸;不建议生产用 |

**推荐 A(上线环境)+ 开发期允许 B 先跑通**:规格写的是「隔离沙箱」,C 那种同机子进程撑不起这个词。
⚠️ A 需要部署机上有常驻的容器运行时 —— 这是一个运维决定,也是一笔真实成本。

### 决定 C2:沙箱里能碰什么(隔离边界)

建议**全部默认关**,要开逐项拍:

| 能力 | 建议 | 理由 |
|---|---|---|
| 网络 | 关 | 要出网就用 HTTP 节点(有白名单);代码里出网等于绕过 H1 |
| 文件系统 | 只给一个临时目录,跑完删 | 读不到 Worker 的任何文件(密钥文件、对象存储) |
| 环境变量 | 一个都不传 | Worker 的环境变量里有库连接串 |
| 输入 | 只给「用到的数据」里选的那几项(JSON 进) | 和其他节点同一套绑定,校验器照样查支配关系 |
| 输出 | 必须是 JSON、必须符合这一步声明的输出 Schema,否则这一步失败 | 不把一段解析不了的打印输出当结果往下传 |

### 决定 C3:资源配额

| 项 | 选项 | 推荐 |
|---|---|---|
| 运行时长 | 1 秒 / 5 秒 / 10 秒 | 5 秒,超时强杀、这一步失败 |
| 内存 | 64 MB / 128 MB / 256 MB | 128 MB |
| 输出大小 | 64 KB / 1 MB | 1 MB |
| 并发 | 每个项目同时最多几个沙箱:1 / 4 | 4(防一条流程的循环把机器占满) |

### 决定 C4:语言

| 选项 | 代价 |
|---|---|
| A. 只开 Python | 和后台技术栈一致;配置者多半更熟 |
| B. Python + JavaScript(Dify 两种都有) | 两套沙箱镜像、两套测试 |

**推荐 A**。

### 决定 C5:谁能加 / 谁能改

菜单上现在写的是「只有管理员能加」—— 这是之前随手写的提示,**还没被拍过**,这里正式列出来:

| 选项 | 代价 |
|---|---|
| A. 只有管理员能加和改代码节点;别人能看、能跑 | 最稳;业务配置者要改一行代码得找管理员 |
| B. 能编辑流程的人都能写,但含代码节点的版本**发布到生产前要管理员审核代码** | 规格 §17.4 那句「审核」就落在这里 |
| C. 都能写,不审核 | 等于把沙箱当唯一防线 |

**推荐 B**(审核点放在发布,和现有发布流程同一个地方)。

### 决定 C6:先不做、用别的顶上,行不行

写在最后,因为它可能让上面五条都不用拍:
「规则拼不出来」的那些处理,有一部分可以**加白名单转换**(字段转换里多加几种操作、列表操作多加几种规则)覆盖,不需要开代码。
建议在拍 C1 之前,先列出**澜绣现在的流程里到底哪一步非写代码不可** —— 如果一个都没有,代码执行节点可以继续置灰。

| # | 决定 | 推荐 |
