## 1. 场景、目标和范围

在企业办公 Agent 接入多种文档、搜索、日历和协作能力后，AI 产品经理及技术运营需要决定每个任务能用哪些工具，并能查明为什么选错、漏选或加载过多。该模块提供工具目录、可复用工具组和筛选策略，让工作人员先试跑、对比证据，再把合适版本绑定到应用；日常提问由系统自动筛选和执行。

| 六要素 | 本文定义 |
|---|---|
| 场景 | 企业办公 Agent 跨文档、知识库、日历等应用执行任务 |
| 使用岗位 | AI 产品经理、工具维护者、测试人员、发布者、连接管理员 |
| 痛点 | 工具边界混淆；重要工具未进入模型输入；工具说明占用上下文；出错后无法定位原因 |
| 解决方式 | 管理可用能力，按任务提供合适工具，保留选择证据，允许在范围内补找 |
| 输入 | 当前任务、必要历史、应用版本、请求者身份、工具目录、筛选策略和调用预算 |
| 输出 | 本轮候选及实际加载工具、可追溯执行结果、失败原因、评测对比与版本记录 |

目标是让任务在既定权限、质量、时延和成本要求内完成。工具数量越少并不必然越好；选中正确工具也不等于任务完成。

首版拟实现固定工具组和关键词工具检索、运行内补搜、服务端校验、调试与评测。语义检索及供应商原生延迟加载作为可独立启用的扩展，必须有真实适配器和能力探测结果。本文不新建通用聊天产品、不重写全部 Workflow/RAG。

## 3. 先分清工具的不同状态

| 概念 | 定义 | 谁决定 |
|---|---|---|
| 已登记 | 工具及其执行适配器存在于目录 | 工具维护者及服务端 |
| Agent 允许范围 | 此 Agent 版本允许使用的确切工具版本集合 | 配置及发布流程 |
| 当前可用 | 在允许范围内，且连接、用户权限和当前范围允许 | 服务端在本次运行判断 |
| 本轮候选 | 为当前任务召回、排序得到的工具 | 筛选程序 |
| 实际加载 | 工具定义已经按 API 契约进入本次模型输入 | 模型适配器/运行时 |
| 实际调用 | 模型发出调用请求，网关验证并执行 | 模型提议，服务端执行 |

集合原则：新加载的工具与当前可执行能力不得超出 Agent 允许范围和当前有效授权。权限撤销不会抹除模型此前已见过的说明，历史加载记录应保留，但服务端必须阻止后续执行。工具检索入口是受控的运行时内置能力，只能发现上述范围内可披露的工具。

“本轮未加载”不等于“无权限”；“筛选得分高”不授予权限。服务端不能只靠前端隐藏按钮、Skill 文字或模型自我判断守边界。

Skill 可指导发现和使用流程；MCP 是工具发现与调用的标准接入方式；Hook 可在宿主支持的节点运行检查。筛选、加载及校验必须有实际代码消费者，不能通过勾选这些名称冒充实现。

### 4.1 组件与存储

| 组件 | 职责 | 用户能感受到什么 | 代价或限制 |
|---|---|---|---|
| 工具目录 | 工具说明、参数、返回契约、连接和确切版本 | 工具用途可辨认，可维护 | 说明及适配器都需维护 |
| 工具组 | 将稳定搭配的工具保存成版本 | 少量配置即可覆盖固定任务 | 分组可能遗漏跨应用任务 |
| 筛选策略 | 指定路由、搜索、预算、补搜和失败行为 | 选择行为可调整、可回退 | 策略必须评测 |
| 工具检索索引 | 为已审核版本建立关键词及可选向量索引 | 描述不同也能找到相关工具 | 索引版本、中文分词和失效管理 |
| 运行内加载器 | 将选中定义交给模型，并维持名称到版本映射 | 只加载当前需要的能力 | 必须适配具体模型 API |
| 工具网关 | 每次执行前校验授权、参数和副作用要求 | 选错或越界时明确停止 | 不同工具需要不同执行校验 |
| 筛选实验室 | 比较候选、实际输入、调用和结果 | 能定位选错发生在哪一步 | 真模型/真工具调试产生费用 |
| 评测与发布 | 同题对比、关键场景门槛、版本绑定 | 修改有依据且可以回滚 | 数据及基线维护 |

数据库复用现有 PostgreSQL。首版关键词索引可在现有服务内实现，冻结分词器与检索实现版本；不因示例有多个工具就强行新增搜索集群。语义检索扩展优先复用既有向量基础设施，但工具索引与知识文档索引必须是不同对象、不同命名空间。

Redis 如已有，可缓存候选 ID；数据库和实时授权仍是真值。缓存丢失只影响效率，不能放宽权限或改变已冻结版本。页面必须区分索引已构建、服务健康、当前用户可用。

### 4.2 首版方案选择

| 方案 | 适合 | 优点 | 代价 | 本文安排 |
|---|---|---|---|---|
| 固定工具组 | 应用入口和任务范围稳定 | 可解释、无额外模型路由调用 | 跨组能力需补搜 | 首版支持 |
| 关键词工具检索 | 说明和术语较规范 | 易调试、无需 Embedding 费用 | 同义表达与中文分词影响召回 | 首版支持，保留补搜 |
| 混合检索 | 工具多、表达跨度大 | 可测试改善语义召回 | 向量构建、排序和额外运维 | 后续按同题结果启用 |
| 供应商原生工具搜索 | 连接实际支持该协议 | 可复用延迟加载能力 | 平台能力、用量与事件需适配 | 独立扩展，不做默认假设 |

筛选语句可由执行任务的 Agent 直接产生，不强制单独调用“路由大模型”。只有实验证明额外分类有价值时，才启用独立路由节点；它的成本和延迟计入整条任务。

## 5. 工具入库、变更与索引流程

### 5.1 手工注册

选择已有连接和经登记的执行适配器 → 填工具说明、参数及返回契约 → 校验 → 在测试环境连接检查 → 保存草稿 → 冻结工具版本 → 纳入工具组/Agent 允许范围 → 构建匹配索引 → 试跑与发布。

注册表单不接受任意服务端执行代码。密钥只用 secret_ref，前端不回显密钥。说明、参数、执行映射、风险及服务端绑定的变化均必须进入版本差异。

### 5.2 MCP 发现导入

连接管理员点击“发现工具” → 后台分页拉取工具定义 → 与现有版本比对 → 展示新增/变更/移除候选 → 维护者审核适用边界及参数 → 生成本地草稿。

发现结果是外部输入，不自动成为生产工具，不自动扩展 Agent 权限。工具说明中的任意指令不能改变系统规则。服务端下架或连接停用通过可用状态及时阻止执行，不能等重新建索引后才生效。

MCP 提供工具列表和调用协议；具体展示、筛选和授权仍由宿主实现。[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)

### 5.3 索引快照

索引输入只包含允许用于检索的工具名称、说明、标签、参数解释和审核后的示例，不含密钥及服务端私有参数值。快照记录工具版本清单、内容哈希、分词/Embedding 版本、构建状态和构建日志。

新索引先构建和校验，成功后原子切换活动指针。构建失败保留兼容的旧快照；不得把半成品标成就绪。工具版本与索引不匹配时拒绝静默替换，可采用已配置的固定工具组回退；没有可用回退则明确无法筛选。

## 6. 一次任务怎样执行

示例输入：“在公司知识库里找到设计规范，告诉我按钮尺寸要求。”工具数量是教学示例，不代表当前项目的真实规模。

| 步骤 | 执行者 | 输入 | 实际动作 | 输出及后续 |
|---|---|---|---|---|
| 确定运行配置 | 服务端 | 已认证身份、Agent 发布版本 | 固定策略版本、工具允许范围、预算和目录快照 | 运行配置快照 |
| 理解目标 | Agent 或固定入口规则 | 问题、相关历史及来源限制 | 得到查内部文档并读取依据的需求 | 用于工具筛选的查询 |
| 判断可用范围 | 服务端 | 身份、允许范围、连接状态、任务限制 | 排除无权、停用或不符合已确认范围的工具 | 可披露、可候选集合 |
| 查找工具 | 筛选程序 | “内部文档搜索、读取正文” | 按组或检索工具目录，记录匹配证据 | 候选及可解释的匹配原因 |
| 整理候选 | 加载器 | 候选、版本映射、配套关系、预算 | 去重、解决同名冲突、选择配套工具、核对总预算 | 本轮加载清单 |
| 提供定义 | 模型适配器 | 选中版本的名称/用途/输入结构 | 按实际 API 协议装配工具定义 | 可核查的模型实际输入 |
| 查文档 | Agent + 网关 | 搜索词“设计规范 按钮尺寸” | 调用内部搜索；返回文档标识及摘要 | Agent 判断是否需要正文 |
| 读正文 | Agent + 网关 | 搜索结果中的有效文档标识 | 校验对象权限后读取 | 原文、版本、出处 |
| 完成 | Agent + 结果校验 | 原文证据及问题 | 生成答案，检查引用和必要要求 | 成功、部分完成或未完成 |

“搜索工具”查的是能力目录；“搜索内部文档”查的是用户资料。界面应使用不同名称，避免把两次检索的耗时和失败混在一起。

### 6.1 有效范围与任务范围

- 权限来自认证和服务端策略，不能接受模型传入的用户身份作为授权真值。
- 明确要求仅查内部资料时，外网工具不因相似度高而进入候选。模糊任务类别只用于排序偏好，不宜直接变成永久排除条件。
- 筛选时查权，实际调用时再次查权。运行中撤销权限必须对后续执行生效。
- 模型只看到可披露的候选；调试人员也只能查看其有权查看的目录。普通角色不能通过“排除原因”看到其他项目的工具名称。
- Agent 工具允许范围是版本化上限。补搜只能在该上限和当前有效授权内进行。

### 6.2 检索与排序

首版关键词检索使用版本化分词和规范化，支持中文名称、英文标识、别名和适用标签。检索器返回原始得分、匹配字段及分词器版本；得分不展示成概率或“准确率”。

固定工具组直接解析确切版本。关键词模式检索工具说明，并允许匹配不同的正确工具组合。混合模式分别召回关键词与向量候选，再使用公开、可复算的融合方法；分数不直接相加，具体规则见附录 A。

未知任务不硬塞入某个组：保留工具检索入口，必要时澄清任务对象。明确限制与不确定的意图判断分别记录。

### 6.3 加载策略与调用校验

首版采用“运行内追加加载”：常驻工具和发现入口先进入上下文，后续发现的定义加入活动集合。已加载工具在本次 Run 内保持稳定映射；不通过任意删改历史工具消息来省 Token。

每轮控制初次候选数量、单次新增定义预算和活动工具总预算。工具定义不可截断成无效 Schema；必须完整保留必填参数及边界。放不下必要定义时返回预算不足，不能假装已经加载。

“初次候选上限”统计检索器选出的主候选，不包含另行补入的配套工具；页面同时显示配套数量和实际活动总量。所有配套定义均计入 Token 预算，不能利用配套关系绕过总预算。上限不要求每次填满，匹配不足时允许更少或为空。

服务端维护模型工具名 → 确切工具版本 → 执行适配器的映射。不同连接同名工具采用稳定命名空间或冻结的别名；同一模型可见名称不得指向不确定版本。

当前代码构造的是固定定义列表。实施时区分运行允许范围与本轮实际加载清单；校验调用属于已授权且已加载的版本。模型请求未加载的合法工具时可返回“请先发现该能力”，不能根据它编造的名字临时执行。

工具发现产生的“可调用引用”应在加载完成后才交给执行模型；一次响应并列产生发现及未加载调用时，按协议序列处理，禁止提前执行。

供应商原生延迟加载只在适配器确认支持时开启。以 Claude 为例，延迟工具仍可随请求提交服务端，但仅在发现后进入模型上下文；“发送定义数”和“上下文实际加载数”必须分栏记录。没有供应商证据时后者显示未知，不能凭请求大小推算。[Claude 工具搜索](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)

### 6.4 补搜、停止与故障

| 条件 | 处理 | 禁止行为 |
|---|---|---|
| 候选为空 | 在授权范围内改写能力查询或扩大相关类别 | 自动放开权限、自动允许外网 |
| 找到搜索但缺少读取 | 依据当前任务补搜读取工具 | 因配套关系自动执行读取 |
| 发现扫描文档需要 OCR | 继续发现允许范围内的解析能力 | 把支持文字读取等同支持识图 |
| 当前工具执行成功但资料为空 | 进入资料检索排查，可改资料查询 | 无依据断言工具目录没有能力 |
| 工具目录服务不可用 | 尝试已配置、同范围的固定工具组；否则返回不可用 | 将失败伪装成无搜索结果 |
| 权限撤销/连接停用 | 网关阻止后续动作，说明当前限制 | 使用运行开始时的旧权限继续 |
| 补搜无进展 | 达到上限或重复相同搜索和相同结果时停止，解释缺口 | 无限制重复查找或扩大预算 |
| 写工具超时 | 沿用执行账本核查实际状态 | 再搜索同类工具并重复写入 |
| 用户改需求 | 更新任务范围及候选，权限仍取当前交集 | 因新范围自动增加 Agent 允许工具 |

“候选为空”“权限不足”“目录故障”“定义超预算”“工具执行失败”“资料无结果”必须是不同错误码和用户文案。

### 7.1 统一布局与按钮规则

- 顶部：面包屑、名称、状态、当前查看版本；右侧主操作。环境信息始终可见，生产标签不能只靠颜色。
- 列表：搜索和筛选在表格上方；主操作右上；行内只保留“查看/编辑”等高频入口，其余放“更多”。
- 编辑：内容区表单；底部固定操作条，从左到右是校验状态、取消、保存草稿、保存为新版本。最后一项为主按钮。
- 详情：页签区展示配置、版本、引用、评测及运行证据；“编辑草稿”与“创建发布单”分开。
- 调试：参数在左，过程与结果在右；主按钮随当前模式命名为“预览筛选”或“运行测试”，运行中变“停止”。
- 无权限时提供原因；能力未接入显示“未配置/不支持”，不能给一个点击后仅 Toast 成功的按钮。
- 只读角色可看有权证据；不存在默认“管理员能代替所有用户调用”的隐含通道。
- 可输入字段有标签、帮助、校验错误和键盘焦点；表格状态用文字，错误可定位字段。窄屏上下排列，固定底栏不得遮挡内容。

### 8.3 编辑字段与约束

| 字段 | 输入形式 | 必填及校验 | 人工如何调整 |
|---|---|---|---|
| 显示名称/模型工具名 | 文本 | 名称唯一性按项目及模型可见别名检查；遵守适配器名称限制 | 改用途时同步检查搜索别名 |
| 功能说明 | 多行文本 | 必填，明确做什么、输入是什么、结果是什么 | 根据错选案例改描述 |
| 适用/不适用场景 | 场景条目 | 不能仅写“各种任务” | 增加易混淆的正反例 |
| 分类与别名 | 可搜索标签 | 只能使用登记分类；别名进入索引 | 补公司常用术语 |
| 输入/输出 Schema | 表单及高级 JSON | 只接受当前执行器支持的关键字；未知关键字拒绝保存为版本 | 简化或扩展执行器后再启用 |
| 参数样例 | JSON 编辑器 | 必须符合 Schema，样例不含真实密钥 | 添加典型输入，不用样例授予权限 |
| 连接与执行映射 | 下拉选择 | 只选当前项目允许的已登记适配器 | 连接改动提示受影响引用 |
| 服务端绑定 | 管理员配置区 | 模型不得覆盖身份、固定库范围等字段 | 更改进入版本差异与权限审查 |
| 操作类型 | 只读/写入等既有枚举 | 与适配器真实能力一致 | 从读变写必须新版本 |
| 配套工具 | 工具版本选择器 | 检查循环、同名冲突及授权交集 | 推荐关系不自动执行 |

现有网关为有限 Schema 校验实现。首版不能默认任意 JSON Schema 都被支持；界面必须用真实能力清单校验，不能静默忽略约束。

## 9. 工具组列表与详情

工具组是维护者保存的能力组合，例如“内部资料查询”包含搜索与读取。工具组本身不授予用户权限。

### 9.1 列表

顶部搜索名称，筛选应用范围、负责人、状态。表格列为名称、用途、成员数量、最新版本、生产引用、最近评测、负责人及更新时间。右上主按钮“新建工具组”；行内“查看”，更多“复制为草稿/查看引用/归档”。

### 9.2 详情与编辑

左侧显示组名称、用途和适用任务；中央成员表；右侧显示权限冲突、未就绪连接、定义 Token 估算和配套关系问题。

| 成员字段 | 行为 |
|---|---|
| 工具及确切版本 | 用选择器添加；显示版本和风险，不能写“永远最新” |
| 加载角色 | 常驻、按需；常驻仍必须在 Agent 允许范围内 |
| 必要/推荐 | 必要工具不可用时明确组不满足要求；推荐工具可按预算省略 |
| 推荐配套 | 展示关系和原因；共享配套去重 |
| 顺序偏好 | 仅影响稳定排列和预算选择，不规定模型必须按此执行 |
| 有效性 | 启用、连接、Schema、同名冲突、索引版本等检查 |

成员区顶部“添加工具”；行内“调整版本/移除”。底栏“取消 / 保存草稿 / 保存为新版本”。“测试此工具组”在保存后打开实验室并带入快照；不能把未保存表单当生产版本。

组详情页签：成员、适用任务、版本、引用、评测。归档只阻止新引用，不静默删除历史证据；撤销使用另走即时停用，必须说明对运行中的影响。

字段必须写明哪个运行组件消费。只读展示项不得伪装成可修改开关。

| 配置项 | 控件 | 设计初值/规则 | 实际消费者 |
|---|---|---|---|
| 策略名称、用途、负责人 | 文本/人员选择 | 必填 | 管理与审计 |

| 中文分词/别名版本 | 版本选择 | 与索引绑定；改动需重建 | 索引器 |
| 初次候选上限 | 正整数 | 5，设计初值，需评测 | 候选裁剪 |
| 单次新增定义预算 | Token 数 | 4000，设计初值；计入配套及包装 | 加载器 |
| 活动工具总预算 | Token 数 | 12000，设计初值；保留发现入口 | 上下文构造 |
| 排序方案 | 可选项 | 首版关键词；语义模式需配置 Embedding | 排序器 |
| 配套加载 | 单选 | 必要配套完整加入；推荐配套按预算 | 依赖解析器 |
| 最大补搜次数 | 非负整数 | 2，设计初值，不含首次发现 | 运行协调器 |

### 10.3 配置与生产生效

保存草稿只保存当前编辑。保存为新版本完成服务端校验并冻结配置；不会自动改变生产。策略版本必须由 Agent/应用发布清单引用，绑定同时记录工具组、目录和模型适配器版本。

“版本 Diff”至少包含候选范围、任务限制、允许工具、常驻工具、模式、预算、补搜、回退及连接变化。新增工具权限与单纯加载策略调整分别标识。

正在运行的任务固定其策略快照；紧急权限撤销和停用通过实时网关阻止后续动作。回滚只改变新 Run 的版本绑定，不能恢复已经撤销的授权。

### 11.1 输入和人工控制

### 11.2 结果页签

| 页签 | 必须呈现 |
|---|---|
| 候选与排除 | 工具名称/版本、权限过滤、匹配字段、原始分数、配套原因、未加载原因 |

| 用量与延迟 | 工具搜索、模型、业务接口分别耗时；实际/估算/未知分开；失败和补搜计入 |
| 配置差异 | 固定版本与本次临时覆盖；一键定位原字段 |

试跑结束提供“保存为评测案例”“基于本次参数建草稿”“导出脱敏报告”“打开完整 Trace”。不提供直接“应用到生产”按钮。

“停止”发送取消请求，显示取消中；已有外部副作用按账本核查。重跑创建新运行，不覆盖旧证据；写工具只能在隔离环境或满足现有确认规则时重跑。

## 12. 筛选运行详情与诊断

运行详情复用现有 Run/Trace，通过子路由或页签展示筛选部分，不能再造一套没有父运行的日志。

页头展示任务摘要、实际运行模式、Agent/策略/目录版本、请求时间、执行状态和任务达标状态。右侧操作是“在实验室复现”“导出脱敏记录”；生产记录不提供直接重放写动作。

| 阶段 | 证据字段 | 支持的定位 |
|---|---|---|
| 输入 | 任务原文、相关历史引用、明确约束、配置版本 | 是否理解错对象或遗漏条件 |
| 当前范围 | 允许工具清单哈希、权限检查版本、可披露排除原因 | 是否被正确过滤 |
| 召回与排序 | 查询、检索模式、候选版本、分数、索引快照 | 是否找到正确能力、排序是否合适 |
| 候选整理 | 配套关系、预算测量、去重和排除原因 | 是否被预算或同名冲突挤出 |
| 实际加载 | 提交定义清单、实际可见证据、活动集合 | 是否真正进入模型输入 |
| 模型与网关 | 请求工具名/参数、解析版本、网关判定、执行目标引用 | 模型选错还是程序接错 |
| 结果 | 返回内容、引用、任务校验、最终状态 | 工具成功是否代表任务完成 |

每个事件包含父运行、阶段序号、时间、模式、快照和脱敏规则。只记录可观察的输入、调用和结果，不要求暴露模型隐藏推理。

诊断面板支持人工归因：输入缺条件、权限配置、工具漏召回、排序/预算、定义未加载、模型选错、映射错误、接口异常、资料无结果。自动建议只能标“待核实”，不可自动把原因归到模型能力。

### 14.4 状态与一致性

| 对象 | 状态/转换 | 规则 |
|---|---|---|
| 草稿与版本 | 草稿 → 校验 → 冻结 | 草稿可并发编辑；冻结版本不可变 |

### A-1 有效工具与对象范围判定
- **用在哪**: 每次工具发现和执行；产品人员在候选原因及拒绝记录中查看
- **解决什么问题**: 防止检索相似度、补搜或前端勾选扩大真实权限
- **输入 → 输出**: 认证身份、Agent 允许版本、当前连接和任务范围 → 可披露候选/拒绝原因
- **怎么算**: 可用集合取 Agent 允许版本、当前身份授权、连接启用及明确任务限制的交集；模糊意图只作排序偏好。执行前重新校验对象范围。规则冲突时拒绝放宽。
- **为什么选它**: 权限过滤优于让模型读完再自行忽略；代价是权限变动与执行时校验。筛选阶段的资格不能替代对象级检查。

### A-2 固定工具组与关键词匹配
- **用在哪**: 工具筛选器；维护者在实验室看匹配字段和得分
- **解决什么问题**: 在允许范围内找到任务所需能力，不把全部定义先交给模型

- **怎么算**: 固定组按版本解析；关键词模式先用冻结的中文分词/别名规则规范化查询和说明，再用 BM25 检索。首版拼接名称、描述、标签和参数解释，不暗设不可见的字段加权；同分按稳定版本标识排序。记录分词器、语料快照和检索实现版本。

### A-3 可选语义召回与排序融合
- **用在哪**: 扩展模式；产品人员比较关键词与混合结果
- **解决什么问题**: 在任务表达和工具术语不同的情况下改善能力召回
- **输入 → 输出**: 同一工具快照的关键词候选、同空间 Embedding 候选 → 融合排序
- **怎么算**: 工具说明预先向量化，查询用兼容 Embedding；两路候选先按工具版本去重，再用 RRF：每个列表贡献 1/(k + rank)，未出现贡献 0，rank 从 1 开始。k 必须为正且进入策略版本；先试设计值 60，再用冻结评测集比较。相同分数采用稳定次序。
- **为什么选它**: RRF 避免直接相加不可比原始分数；单用关键词更简单，单向量可能混淆近义操作。是否保留混合方案取决于任务质量与代价。
- **怎么验证的**: 计划手算小候选列表做判分器对照，再同题对比首轮和重复轮；当前未实现/未跑。
- **局限**: 融合不能找回两路都未召回的工具；跨 Embedding 版本混向量无意义。

### A-4 工具版本去重与配套关系解析
- **用在哪**: 候选整理；工具组详情显示冲突
- **解决什么问题**: 避免同名工具接错版本，避免搜索后缺少读取能力
- **输入 → 输出**: 候选版本、冻结配套边、模型名称规则 → 无歧义候选组
- **怎么算**: 按确切版本去重；名称冲突由冻结别名解决或拒绝。必要配套形成依赖闭包，用图遍历检测循环；共享节点只计一次。无权配套不能自动加入，必要依赖缺失则该候选组不可用。推荐配套可按预算省略。
- **为什么选它**: 显式配套便于稳定任务；纯粹让模型补搜更灵活但增加往返。闭包只加载能力，不执行动作。
- **怎么验证的**: 计划用环、重复依赖、跨项目依赖、缺必要依赖和同名版本对照；未跑。
- **局限**: 人工配套标注可能错误；闭包过大可挤占预算，应返回原因。

### A-5 候选数量与工具定义预算选择
- **用在哪**: 每次模型请求前；策略页和实际加载页显示
- **解决什么问题**: 减少无关定义，同时保留完成当前步骤必需的能力
- **输入 → 输出**: 候选顺序、必要配套、活动集合、Token 计量 → 本轮新增和未加载原因
- **怎么算**: 先预留发现入口及合法常驻工具；按候选排序尝试加入完整依赖组，检查候选上限、单次新增和活动总预算。已有定义不重复计入活动增量。过大组跳过并记录；必需能力仍无法放入则返回预算不足。最后对实际请求整体再做上下文预算检查。
- **为什么选它**: 稳定贪心法容易解释和复现，但不保证全局最优；复杂背包算法只有出现实测损失后再评估。不能只按工具数量近似 Token。
- **怎么验证的**: 计划对边界预算、共享依赖、单工具超限、包装开销和未知计量测试；未跑。
- **局限**: 使用估算时必须标估算并留余量；无法可靠计量的硬上限模式阻止发布，不能用未知等于零。

### A-6 补搜与无进展停止
- **用在哪**: Agent 运行协调器；运行详情显示次数与停止原因
- **解决什么问题**: 弥补首次漏选，又避免无意义反复搜索
- **输入 → 输出**: 能力缺口、已有定义、前次查询结果、次数及时间预算 → 补搜/继续/停止
- **怎么算**: 首次发现不计补搜；后续发现计入最大补搜和总模型回合/时间预算。相同规范化查询、相同目录和相同候选集合反复出现且没有新能力时标无进展；可声明轮询的业务工具沿用既有规则，不混入补搜去重。超限后返回具体缺口。
- **为什么选它**: 有界补搜比一次性截断稳健；无限循环不可控。停止依据需区分工具不足和资料无结果。
- **怎么验证的**: 计划注入读取工具漏选、目录空、重复结果、正常轮询及预算耗尽；两轮模型数据未跑。
- **局限**: 模型可能不主动报告缺口；需结合任务未完成和工具错误证据触发。

### A-7 快照哈希与候选缓存隔离
- **用在哪**: 索引发布、版本记录及可选候选缓存
- **解决什么问题**: 防止工具说明、授权或任务改变后复用旧候选
- **输入 → 输出**: 工具版本、索引器、策略、身份授权指纹、任务约束及能力查询 → 快照/缓存键
- **怎么算**: 用稳定 JSON 规范化后 SHA-256；键含项目、环境、Agent/策略/目录版本、认证主体或等效授权指纹、权限代次和查询/约束。键不包含明文密钥。命中仅复用候选 ID，仍实时复核权限、启停及版本。键输入改变即失效。
- **为什么选它**: 显式版本键易复算，但粒度细降低命中率；首版关闭候选缓存以减少复杂度。
- **怎么验证的**: 计划同键正例及单字段变化负例，注入撤权和目录更新；未跑。
- **局限**: 遗漏身份或约束字段会产生错误复用；哈希不是加密，不能存敏感明文后声称安全。
- **记于**: 2026-09-27 · 最后改于: 2026-09-27

### A-8 评测判定与分组统计
- **用在哪**: 评测报告和发布检查；产品与测试共同核查
- **解决什么问题**: 避免接口返回成功、工具选得少或转人工被误记为任务成功
- **输入 → 输出**: 独立真值、执行轨迹、最终业务状态和用量 → 分组指标与失败清单
- **怎么算**: 成功要求全部必要条件且没有禁止行为。支持多个合法能力组合，不能强制唯一工具路线。成功率=成功任务/执行任务；自主完成率排除人工接管；每成功任务成本=含失败重试的总费用/成功数。比例同时报告分子分母；零分母及未知费用返回未知。P95 用声明的 nearest-rank 口径，并附样本数。
- **为什么选它**: 程序判客观结果，人工按清单复核内容，模型裁判仅辅助；比只看模型自报分数可靠但评测维护更重。
- **怎么验证的**: 计划用人造全错、全对、零样本、替代正确路线及费用缺失对照验证统计；产品评测未跑。
- **局限**: 小样本、题集偏置和裁判漂移仍会误导；两轮不足以替代统计功效与更多重复。
- **记于**: 2026-09-27 · 最后改于: 2026-09-27

### A-9 调用成本与假设估算
- **用在哪**: 实验室用量、模型方案比较
- **解决什么问题**: 把工具选择新增开销和生成节省分开核算
- **输入 → 输出**: 计价版本、实际输入/输出/缓存桶、调用次数与工具费用 → 已知费用及未知项
- **怎么算**: 逐调用按供应商定义的互斥计费桶乘单价再求和；输入、缓存读写不能重复算。路由、发现、补搜、执行模型、Embedding 和业务接口费用分别记。实际缺数据时总费用未知，已知小计单列。附录 D 只计算明确假设的无缓存路由调用。
- **为什么选它**: 显式费用桶方便对账；只看输出 Token 或框架返回的单一费用会漏算。与无筛选方案比较必须包含全部新增调用。

- **局限**: 地区、批处理、特殊模式、订阅和合同价格不在基础单价样例内；不能从假设算例推断真实节省。

### A-10 发布门槛与可比实验判定

- **解决什么问题**: 阻止不完整评测、未知门槛或局部成功被当作上线依据
- **输入 → 输出**: 冻结题集/真值/代码/模型/环境指纹、重复轮报告、指标门槛 → 可比较/不确定/阻止发布

| 工具异常 | 有，对应 C.2：必要配套缺失、配套环、首次漏选后补搜、需要 OCR、目录服务超时、关键词无结果、工具正确但资料为空、计量未知、调用未加载工具、接口映射错误、写调用超时、取消正在筛选、补搜无进展、索引更新失败、Schema 版本不匹配、并发编辑、原生能力不支持 | 未跑 |

| 外部内容干扰 | 有，对应 C.2：工具说明注入、工具结果注入 | 未跑 |

### C.8 指标、门槛和判定责任

| 指标 | 口径 | 门槛如何设 | 当前 |
|---|---|---|---|
| 必要能力可达率 | 存在至少一组合法完成路径的任务中，策略能够提供该路径所需能力的比例；区分首次和补搜后 | 在冻结题集上按关键任务分组设置；有多种路线则接受任一合法组合 | 未测 |
| 不当工具调用率 | 不符合任务/范围的工具请求数除以全部工具请求数；同时报告每任务发生率 | 预先配置；越权执行另作严重违规 | 未测 |
| 端到端任务成功率 | 满足全部必要条件且无禁止行为的任务数除以执行任务数 | 分场景配置，不用统一行业百分比 | 未测 |
| 自主完成率 | 无人工接管且完成任务数除以执行任务数 | 与成功率并排；人工指定候选单列 | 未测 |
| 异常处理正确率 | 正确恢复/停止/转交的异常任务数除以异常任务数 | 异常类型分别设置 | 未测 |
| 严重违规次数 | 越权、信息泄露、重复关键写入等实际发生次数 | 本设计硬约束：出现即阻止相应发布 | 未测 |
| P95 完成时长 | 全任务时长按声明分位数算法统计；附数量、模式和环境 | 应用负责人预先设置 | 未测 |
| 每成功任务成本 | 全部任务费用含失败/补搜/重试，除以成功数 | 业务与预算负责人预先设置；缺成本不能写零 | 未测 |
| 工具定义用量 | 实际输入可见定义的 Token 与计量来源；原生延迟加载证据不足则未知 | 作为解释项，与质量和总费用一起看 | 未测 |

程序判客观状态；人工按清单审内容和复杂任务；模型裁判只辅助并先做人工校准。关键场景分别达标，不许总平均覆盖。规则转人工可算处理正确，不算自主完成。保留全部失败证据。

小范围上线后观察实际任务完成、人工纠错、费用和撤权行为；线上新错例进入版本化回归集。变更模型、Prompt、工具、索引或加载策略后重跑受影响场景。

### D.6 成本公式和可核查算例

真实完整任务成本应逐次累加：工具筛选计算 + 可选路由模型 + 工具发现及补搜产生的模型调用 + 执行模型 + 可选 Embedding/重排 + 实际工具/API 费用 + 基础设施。每一项都要标实际、估算或未知。自研目录检索不按模型 Token 收费，仍有服务器成本。

无缓存单次模型费用 =（输入 Token × 输入单价 + 输出 Token × 输出单价）/ 1,000,000。有缓存时按该供应商实际互斥费用桶计算，禁止重复计数。

下面只演示“假设单独新增一次路由模型调用”的预算计算：假设输入 2000 Token、输出 100 Token，无缓存、无批处理折扣、无特殊模式，每月假设 10000 次。用量不是实测，不能拿此表估计整个 Agent 的真实成本。金额由配套脚本 Decimal 计算。

| 模型 | 输入/输出单价 | 真实项目每次用量 | 假设单次路由费用 | 假设每月费用 | 依据 |
|---|---|---|---|---|---|
| Claude Haiku 4.5 | 1 / 5 | 未测 | $ 0.0025 | $ 25.00 | 官方基础单价 × 假设用量；非完整任务成本 |
| Claude Sonnet 5 | 2 / 10 | 未测 | $ 0.0050 | $ 50.00 | 官方基础单价 × 假设用量；非完整任务成本 |
| Claude Opus 5.5 | 4 / 20 | 未测 | $ 0.0100 | $ 100.00 | 官方基础单价 × 假设用量；非完整任务成本 |

敏感性：在上述无缓存、单价和输出量不变的假设下，输入增加只增加输入费用；调用次数翻倍则这部分总费用翻倍。补搜多调模型、重新传入工具定义和缓存变化都可能抵消节省，必须测整条链。

未知维护费不写零；订阅费用和按量 API 费用分开登记。真实样本到位前，完整任务每条成本、每成功任务成本和月度总成本都保持“未测/未知”。
