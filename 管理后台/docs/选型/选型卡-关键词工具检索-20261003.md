## 三、瓶颈不在算法上 —— **两个独立题集在同一个地方失败**

k 从 5 加到 20,在我那 21 题上**一个都没多捞到**(18→18);
换打分法也捞不到。看漏的是什么:

| 问法 | 漏了哪个工具 | 和问法的共同片段 |
|---|---|---|
| 藏青 S 码那件马面裙现在还能发几件? | 查现货 | **一个都没有** |
| O2026090001 这张单现在到哪一步了? | 查订单 | **一个都没有** |
| 周三下午三点,谁能接一个到店量体? | 日程占用 | 只有「一个」(噪音) |
| 阔褶马面裙有 S 码吗?(留出集 T01) | 版型库 / 尺码表 | — |
| 灰缬能做在浅色棉麻上吗?(留出集 T20) | 相容矩阵 | — |

**「订单现在到哪一步了」这一题,两个题集各有一道,而且都漏同一个工具。**
两套独立的题撞同一面墙 —— 那不是巧合:

> **用户问的是业务,工具说明写的是系统。**
> 用户说「还能发几件」「到哪一步了」「谁能接」;
> 工具说明说「查现货」「查订单」「日程占用的格子」。**字面上不重叠。**

> 所以**关键词检索在这里真正检索的是「用户恰好用了工具说明里的词吗」** ——
> 而用户不读工具说明。

(这和这个仓库记了七次的那条是同一个病的产品化版本:
 「一个按词表判『有没有说人话』的判据,真正判的是『用了我这几个词吗』」。)

## 四、三个方案

### 方案 A:关键词 + **业务话别名表**

给每个工具登记一组「用户会怎么问」,一起进检索。

| | |
|---|---|
| **用户感觉得到什么** | 用自己的话问也能命中。别名是**人写的、看得见、能审计的** —— 后台工具目录上一行一行列着 |
| **锁死了什么** | 别名表要养。工具改了说明、业务换了说法,别名跟着漂 —— 要一条判据盯着(和已有那三条同步判据同形状) |
| **代价** | 81 个工具要人过一遍。**而别名从哪来是这个方案的真问题**(见下) |
| **已量到什么** | 只给漏掉的那 3 个工具加别名,我那套从 18/21 → **21/21 @k=5**。⚠️ **这个数是过拟合的** —— 我是拿失败的题反推别名的,等于先看答案再出题。它证明的只有「这条路有效」,证明不了「有效到多少」 |

### 方案 B:关键词 + **独立路由器兜底**

关键词分数低或候选为空时,花**一次小模型调用**专门选工具。
契约里已经有这个开关(`independent_router_enabled`,首版 false)。

| | |
|---|---|
| **用户感觉得到什么** | 业务话也能命中,**而且不用人去写别名** —— 模型本来就跨得过词表 |
| **锁死了什么** | 每条多一次模型调用。而「加一个工具的代价在此后每一次调用上」这条,这个项目实测过(工具从 26 涨到 59,单条成本涨 38%) |
| **代价** | 钱和延迟。而且**兜底本身会失败**,失败时仍要回到固定组 |
| **业界叫什么** | 这是**两段式检索**(便宜的先过一遍,贵的只处理难的)。推荐系统和 RAG 都这么做 |

### 方案 C:纯关键词,接受天花板

| | |
|---|---|
| **用户感觉得到什么** | 四成的问法**选不出工具**(留出集 k=5 实测 59%)。模型拿不到该用的工具,只能靠编或者说查不到 |
| **锁死了什么** | 它会被记成「检索做完了」——而**留出集上 41% 的题模型连调对的机会都没有** |
| **代价** | 把 k 开到 20 能到 82%,但那时候选 20 个、候选集只比按角色的 52 少一半多,**省下的钱没多少** |
| **诚实说** | 这是演示级 |

## 五、我推荐 **A 先做,B 当兜底**,而不是直接上 B

**为什么 A 在前**:别名是**内容问题,不是算法问题**。而内容问题的修法人看得懂、
查得出、改得动 —— 一个模型路由器选错了工具,你查不出它为什么选错。
而且别名正好该住在刚导进后台的那 81 个工具上 —— **那是后台该管的东西**。

**为什么还要 B**:别名表永远补不全。业务每天有新说法,
而**补不全的那部分会静默变成「这个任务没有可用工具」**。
B 的价值不是提高平均召回,是**接住别名没覆盖到的那些**。

**为什么不直接做 B**:
> 一个每条都多花一次模型调用的方案,如果它省下的是一个
> **本来可以用一张别名表解决的问题**,那笔钱是白花的。
> 而两者混在一起上线之后,**分不清是谁在起作用**。

规格 §14.3 给的是 **5**,并且自己写明「**是设计初值,不是实测出来的**」。
现在有实测了,而它**两个题集给出不同的答案**:

所以 k 现在**定不下来** —— 要等别名表立起来、在留出集上重测之后再定。

## 八之四、所以推荐改成:**A 和 B 不是先后,是各管一摊**

## 九之二、两条必须说清的,否则这个数会被误读

### ① 「省下来多少」**没量** —— 所以别把 $0.00109 当净成本

现状是**每一轮**都把 77 个工具的完整定义带给模型(那段文字 22633 字)。
这个项目实测过:工具从 26 涨到 59,单条成本涨 **38%**,
而「加一个工具的代价不在那个工具上,在此后每一次调用上」。

要真算净成本,得量「开路由器之后主调用的 token 降了多少」——
**那要改澜绣的运行代码,这一轮没做**。

> 只报 $0.00109 会把它说成纯支出,而它很可能是净省。
> **但「很可能」不是数据** —— 这一栏现在是空的。

### ② 6 个失败里,**2 个是我的测量造成的,1 个可能是真值过窄**

| 失败 | 真相 |
|---|---|
| R8 / R9 | 真值要 `pattern_queue`,而它**不在我给路由器的目录里** —— 那 4 个版师工具故意不在 `all` 的 77 个里(安全边界)。**在构造上就不可能过** |
| T09 | 题面「客户婚礼在 2026-10-01」,路由器给 `plan_for_event` —— 而那个工具的说明第一句就是「客户说『明年六月毕业礼要穿』时用这个」。真值只列了 `kb_lead`。**可能是真值过窄,不是路由器错** |
| T14 / R3 / R7 | 真的选错了(给了 `check_write` / `week_grid` / `revive_list`) |

> 一道需要的工具根本不在候选池里的题,和一道模型答错的题,**在失败上长得一模一样**。

**我不去改 T09 那条真值** —— 改真值让分数好看是这个仓库明令禁止的。
所以召回报两个:**按原真值 27/31 = 87%**;T09 若按「`plan_for_event` 也算对」则 28/31 = 90%。

### ③ 留出集 B 的真值里有 8 处是**合并前的旧工具名**

`my_tasks` / `team_tasks` / `member_level` / `get_lifecycle` /
`get_member_priority` / `get_task` / `dispatch_pool` / `piece_ratios` —— 都已经不存在了。

**好在每条都至少有一个名字还活着,没有一题是量不了的** —— 但下次用它之前要再核一遍。

## 九之三、结论:**路由器赢,而且赢得不靠花钱**

- 召回 **81%(可答的 87%)> 关键词的任何一档**(54% / 60% / 最高 75%)
- 它救得了关键词**零重叠**那一类 —— 第一题 `阔褶马面裙有 S 码吗?`
  在关键词那边 77 名里一个都没进,路由器一次就给对了
- 带缓存 **$0.00109/条**,≈ V2 跑一整条,是 V3 的 3.8%
- 延迟中位 1.6s。⚠️ 规格 §14.3 的筛选超时初值是 **3000ms** —— **1.6s 在预算内,但只剩一倍余量**

## 九之四、还要你拍的(最后一件)

**开不开独立路由器,以及开成什么形状?**

| 选项 | 什么样 |
|---|---|
| **只开路由器**(不要关键词) | 最简单,87%。代价:每条都多一次调用 + 1.6s |
| **关键词先过,不够再问路由器** | 两段式。关键词 @k=5 能答的 54% 不花钱不耽误;剩下的才问路由器。省钱省延迟,代价是**两条路的分数混在一起,出问题时分不清是谁的** |
| **只开关键词 + 别名** | 不花钱不加延迟,60%。代价:**四成的任务模型拿不到该用的工具** |

我推荐**只开路由器**先跑起来:$0.00109 和 1.6s 在这个项目的尺度里都不贵,
而两段式的「分不清是谁在起作用」是这个项目反复栽过的坑
(「一次动了多维,归不了因」)。**先把一条路跑通、量准,再谈省。**

# 十、第二层评测跑完了,**它推翻了前面的结论**

两轮 × 两臂 × 24 题(`tool_eval` 那套,**带内容判据**,判分器是现成的 `tool_eval.judge` 三轴)。
模型 haiku-4-5,两臂都用 `all` 角色(控制变量:同提示词、同池子,只差工具子集)。

## 十之一、两个方向都是坏的

| | 答对 | 单条成本(去掉第一题) |
|---|---|---|
| 基线(全量 77 个) | **20/24** | $0.0431 |
| 筛选(路由器选的,均 1.4 个) | **18/24** | **$0.0473** |

> **筛选不但没省钱,反而贵了 10%;而答对数掉了 2 题。**

我一整天在防的是「成本降了而答对数掉了」。**结果是成本没降,答对数还掉了。**

## 十之二、⚠️ 但这个差**不显著** —— 11/48 题会自己翻面

`rounds` 报的:**11 题在两轮之间翻了面**,其中

- **轨迹类 5 题** —— 模型这几次**行为不一致**(该调的没调 / 多调了)。
  这类翻面是**真信号**,改判据修不了
- 内容类 6 题 —— 挂在说法上(没提到某个同义词),多半是判据太吃措辞

> **在一个 11/48 题会自己翻面的系统上,「20 vs 18」这个差根本不显著。**

所以**不能说「筛选让答对数掉了」** —— 能说的只有「没看出它有好处」。
(这正是这个项目记着的那条:V1/V3 连跑两轮各掉一题,**而且掉的不是同一题**。)

## 十之三、成本为什么反而涨 —— **第三份成本,我一天前漏了**

| | 出 token | 读缓存 |
|---|---|---|
| 基线 | 1527 | 320767 |
| 筛选 | **1730**(+13%) | **345450**(+8%) |

**筛选臂的输出 token 多 13%,思考 token 多 8%,读缓存也多 8%。**

而输出单价是缓存读的 **50 倍**($5 vs $0.1 每百万):

```
只算输出那一项的差          $0.00102/条
工具定义省下来的(all 角色)   $0.00227/条
→ 输出多出来的那一笔吃掉了省下来的 45%
```

加上读缓存多出来的那部分,**净结果就是涨。**

### 这件事的机制 —— **量过了,不是「多绕几圈」**

我第一反应写的是「工具少了,模型要多绕几圈」。**量完是错的:**

| | 平均来回轮数 | 平均调几个工具 | **重复调同一工具** |
|---|---|---|---|
| 基线(77 个) | 1.25 | 1.92 | **8 次** |
| 筛选(1.4 个) | 1.33(**+0.08,没差**) | **2.21** | **15 次** |

**轮数几乎没变,但「重复调同一个工具」翻了近一倍。**

最刺眼的是 T07(「为什么云锦做同一条裙子比棉麻用布多?」):

    基线:  kb_lookup × 3 + kb_read × 2
    筛选:  kb_lookup × 4 + **kb_read × 7**

> **工具少了,模型不是绕更多圈,而是在同一个工具上反复换参数试** ——
> 因为它手里没有更合适的那一个。

这恰好解释了三个数的全部:
- **轮数不变** —— 同一轮里可以并发调多个
- **输出 +13%** —— 每次重复调都要写一遍参数,还要想(思考 token +8%)
- **读缓存 +8%** —— 工具返回的内容进了上下文,下一次调用要全读一遍

我在第五节写过「筛选省的钱分两份 —— 工具定义,和对应的那条规矩」。
**漏的第三份不是「多绕几圈」,是「在手里那个不太合适的工具上反复试」。**

### ⚠️ 而这件事在召回率上**完全看不见**

第一层说路由器召回 **87%**。而那 87% 里的「命中」包括了
**「给了一个勉强能用的,模型拿它试了 7 次」**。

> **召回判的是「那个工具在不在候选集里」,判不了「它是不是最合适的那一个」。**
> 而一个勉强能用的工具,和一个正合适的工具,**在召回率上长得一模一样。**

## 十之四、所以准入线那条文档要改一个字

`docs/口径/开筛选的准入线-20261003.md` 算的是:

    净 > 0 ⟺ (N − 1.3) × 每个工具平均token × 缓存读单价 > 路由器一次的钱

**那个式子少了一项。** 完整的应该是:

    净 > 0 ⟺ 省下的工具定义 > 路由器一次的钱 + **多绕几圈的代价**

而「多绕几圈的代价」实测约 **$0.0012/条**(输出 +13% 和读缓存 +8% 加起来),
和路由器那一次调用($0.00109)**差不多一样大**。

代回去:线从 **38** 涨到 **≈ 75** —— 也就是说
> **按现在量到的数,只有 `all` 角色(77 个)勉强过线,而它的余量只有 2 个工具。**

⚠️ 这不是说「筛选没用」。它说的是:
**在这个项目现在这个规模和缓存命中率下,筛选的收益被「模型多绕几圈」吃掉了。**

## 十之五、下一件该做什么(我的建议,等业务拍)

三条,按我推荐的顺序:

1. **先查那 11 题为什么翻面**(尤其轨迹类那 5 题)——
   在一个会自己翻面的系统上做 A/B,量什么都不准。
   > 这个项目记着:**不稳定的东西不能当实验对象**(台账里那条自评「半懂」的)
2. **验「多绕几圈」这个机制**:比两臂的 `answer_turns`(来回轮数)。
   如果筛选臂轮数真的多,那这条因果就钉死了;如果不多,那涨的是别的原因
3. **暂时别接执行层** —— 后台配好了、闸装好了,但**数不支持开它**。
   > 一个有实验撑着的「已启用」,和一个有实验**反对**它的「已启用」,
   > 在策略页上长得一模一样。
