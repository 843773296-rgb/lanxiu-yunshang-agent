# 实现进度(逐项)

> **这份是生成的** —— `python3 tools/progress_report.py`。手写的进度表第二天就会漂,
> 而漂的方向永远是「比实际乐观」。

规格 §20:「交付报告逐项写**已实现且验证 / 已实现未验证 / 未实现**,
禁止用『所有页面都有了』代替完整功能验收」。

## 这份报告答的是哪一层(外部审阅 §8.1)

⚠️⚠️ **它只答前两层。** 「交付得了吗」是第六层,这份报告离它差四层 ——
而这四层**不是这里没写出来,是这份报告测不出来**。
写在最前面,因为原来它只有三档,
而**三档里最高那档离「这个功能可以交付了」还差四层,报告上却没有任何地方说这件事**。

| 层 | 这份报告叫它 | 判据 | 这里测得出吗 |
|---|---|---|---|
| **实现存在** | 已实现 | handler/函数/页面在不在 | ✅ 测得出 —— 扫 handler 文件里的路由装饰器 |
| **请求覆盖** | 已覆盖接口 | 测试运行时真的打到了这条路由 | ✅ 测得出 —— 运行时记账(中间件记 FastAPI 实际匹配到的路由模板) |
| **行为验证** | 行为测试通过 | 有明确输入、预期,以及对输出/副作用的断言 | ⬜ **这份报告测不出来** —— 它看得见「这条路被打过」,看不见「打完之后断言了什么」。要测它得让每条接口报出「哪几条断言打的是我」,而现在的记账只记路由 |
| **集成验证** | 集成测试通过(注明替身) | 真库、真 Worker、真版本解析,替身逐项列出 | ⬜ **测不出来** —— 端到端那几份确实跑在真库真 Worker 上,但「这一条用了哪些替身」没有登记在任何机器可读的地方 |
| **真实链路** | 真实联调通过 | 真连接 + 允许的工具跑完任务 | ⬜ **测不出来,而且下面那张表说明它大概率还没发生** ——三个执行入口当前都挂着 mock 适配器 |
| **产品验收** | 该功能验收通过 | 场景、质量、权限、成本、恢复都达到约定 | ⬜ **测不出来** —— 它要人判断,不是脚本能答的 |

> **多维证据不该压成一个无范围的百分比。** 所以下面那张表只报前两层的条数,
> 而且**不给总占比** —— 一个「124 条里 80% 已覆盖接口」读起来像「这个后台做完了 80%」,而它只是第二层。

## 前两层的条数

| 档 | 条数 | 这个数字证明什么 |
|---|---|---|
| 已覆盖接口 | 100 / 124 | 测试运行时**打到过这条路由** —— 不证明打完之后断言了什么 |
| 已实现未覆盖 | 17 / 124 | 有 handler,而**没有任何测试打到过它** |
| 未实现 | 7 / 124 | **连 handler 都没有** —— 这一档最硬 |

### 判据有多硬

| 档 | 判据 | 硬度 |
|---|---|---|
| 未实现 | handler 文件里没有对应的路由装饰器 | **硬** —— 没有 handler 就是真没有 |
| 已实现未覆盖 | 有 handler,测试没打过 | **硬** |
| 已覆盖接口 | 有 handler,而且测试运行时**真的打到了这条路由** | **中**,见下 |

「已覆盖接口」用的是**运行时记账**(中间件记 FastAPI 实际匹配到的路由模板),
不是「在测试文件里搜这条路径的字符串」—— 后者会把「被注释提到」
「拼在没执行的分支里」也算成覆盖,**比它声称的弱**。

⚠️ **而「打过一次」不等于「行为被断言对了」。**
一条被打过、而断言写错了的接口,在这份报告上和真验过的一样。
**这就是 2026-10-03 把这一档从「已实现且验过」改名的原因** ——
那个名字比它的判据强,而名字出现在每一行的 ✅ 旁边,
这段话在正文里只出现一次。

## 执行入口:现在跑的是真模型还是 mock(外部审阅 §5.4)

⚠️ **连接探测成功 ≠ 运行器接通了。** 审阅那句话:
「某个入口支持真实模型,**不等于其他入口也支持**」。
所以按入口逐个报,**不给一个笼统的「已接通真实模型」**。

| 执行入口 | 现在是 | 怎么看出来的 |
|---|---|---|
| Prompt 调试运行 | 🟡 **mock** | `_跑一次prompt` 调 `main._mock生成` |
| Workflow 的 LLM 节点 | 🟡 **mock** | `跑一张图(适配器={"llm": _mock_llm})` |
| 后台 Agent Loop | 🟡 **mock** | `适配器 = {"model": _mock模型}`,只读工具也是 `_mock只读工具` |

⚠️ 这一栏的判据是**扫源码里的 mock 适配器名字**,不是一次运行时核实 ——
所以它会漏掉「换了个名字的 mock」。漏的方向是**把 mock 说成 live**,
那是危险的那一边,所以这里写明判据是扫什么。

> 审阅 §5.4 还要求:**真实调用失败不能静默降级为 mock**,
> 而「真实模型 + 模拟工具」这种混合运行要**逐项显示替换清单**,
> 不能把整个运行标成完全真实。这两条**都还没做**。
