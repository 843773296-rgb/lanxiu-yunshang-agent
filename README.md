## 三条设计上的硬规矩

**① 一份数据只有一处表示。** 实体表、状态机、权限矩阵各只写一次；文档和（将来的）ORM 模型
都从登记表派生。手写第二份的后果不是抄错，是**它会和代码分家，而分家时两边都看着很正常**。

**②' 「结构性保证」必须被攻击过。** 规格说跨项目引用要靠数据库约束挡住 ——
而**一条从没被攻击过的「结构性保证」，实际上仍然只是约定**。
`tests/integration/test_project_isolation.py` 做 5 次真实攻击，每次都必须被拒；
再加**一条正向对照**，否则"全被拒"可能只证明了"什么都写不进去"。

这一轮攻击逮到两个真漏：`traces` 没登记依赖 → `application_id` **一个外键都没建**；
项目级表**根本没有指向 `projects` 的外键** → 编一个不存在的 project_id 能直接写进去。
后者意味着"跨项目引用在数据库层不成立"这句话，对大部分表**根本不成立**，
而表建得好好的，什么都看不出来。

**② 每条检查都咬合过。** 故意把被检查的东西改坏，确认检查真的会红，再改回来。
**没红过的检查等于没有。** 本轮咬合逮到两个真问题：
- 「项目级实体都带 project_id」是**同源谬误** —— `project_id` 正是依据「范围==项目级」
  加上去的，所以把一张表改成组织级之后它直接从被检查的集合里消失，**这条检查永远不会红**。
  改成从另一头判：不按项目隔离的都要写明理由 + 数量棘轮锁死。
- `范围理由` 守卫写了、但**返回值里没带这个键** —— 检查读到的永远是 None，
  而守卫看起来「已经在拦了」。**「写好了」和「接上了」是两回事。**

**②'' `alembic check` 当门禁。** 它抓到过一次真漂移：`project_id` 在库里是 NOT NULL
（进了复合主键），而契约说可空。根因是我的主键判据写成了"字段里出现 project_id"
而不是按**范围**判——于是 `memberships`（组织级、按设计允许 project_id 为空）也被
拖进了复合主键。**判据"恰好长这样"而不是按含义，是这一类错的共同形状。**

**③ 「不知道」必须能表达出来，而且不许用 0 代替。**
- 费用 `amount_known=False` → 前端显示「未知」，不显示 0。
- 评分 `value_known=False` → 「没打分」不等于「打了 0 分」。
- 训练任务的「状态待核实」**不是终态** —— 把查不到供应商状态显示成「已失败」，
  会让人去重跑一个**可能还在烧 GPU** 的任务。
- 列表 `total` 未知时是 `null`，**不是 0**（0 会被读成"一条都没有"）。
- 字段类型认不出来就**抛**，不给 TEXT 兜底：一张全是 TEXT 的表能建起来、能跑、
  看着完全正常，直到有人往 `amount` 里写了字符串，或者 `created_at` 按字典序排。
- 发布闸对**没标 `execution_mode`** 的产物也挡——**未知不等于安全**：
  一个没标模式的产物，最可能的情况正是"它是 mock 但没人标"。

## 记录在案的偏离

规格说「遇到非阻塞选择按文档默认值实施，并记录调整理由」。以下三处按本机实际调整：

| 规格默认 | 本仓库 | 理由 |
|---|---|---|
| Compose 起 PG / Redis / 对象存储 | **原生服务** + `make doctor` 探测 | 本机 Docker 守护进程没跑，且没有 `docker compose` 子命令。基础服务本机已有（PG 17.10 常驻、Redis 8.10.1 手起） |
| S3 兼容对象存储 | **文件系统适配器**（`OBJECT_STORE_KIND=filesystem`） | 没有 Compose 就起不了 MinIO。适配器接口保持一致，接 S3 时只换实现 |
| pgvector 由镜像自带 | `brew install pgvector`（已装 0.8.6） | 原生 PG 装扩展；`make doctor` 会验它在不在 |
| 前端 React + TS + Vite + Ant Design | **无构建步骤的原生 HTML/JS**（`apps/web/`） | API 已经是契约边界，前端换成 React 只需重写 `apps/web/`；把预算花在 build 工具链上换来的是更少的可验证功能。**这不是默认方案，是取舍** |
| Celery + Redis Worker | **异步接口形态已就绪，执行是同步的** | 接口返回 202 + 任务信封、任务/事件都落库，所以接真 Worker 时前端不用改；但现在**没有租约、没有重试、没有 Outbox** |

这三处都**不影响**规格要求的行为，只影响本机怎么把服务起起来。接 Compose 的项目按规格默认走。

## 怎么亲眼看见那几条边界

起 `make dev` 之后，顶栏可以切身份（U001–U005）——这几个身份是**为了让边界能被看见**才配的：

| 切到 | 看什么 |
|---|---|
| **U003**（查看者） | 能看列表，**建 Prompt 会被 403 拒绝**，而错误里写着找谁授权 |
| **U005**（只在 B 项目） | 切到 A 项目会 **404**——不是 403：**不确认「这个项目存在但你没权限」**，那句话本身就是信息 |
| **U002 → U004** | 同一次运行，U002 看到「原文已脱敏」，U004 有专项授权**看得到实际发送给模型的内容** |
| 任意身份 | 开两个标签同时编一条草稿：后保存的那个拿到 **409**，并且给「刷新看最新的」，**不覆盖** |
