## 选型卡:退款「余额不足、补足后仍失败」怎么算答对

**场景**:财务人工任务里一张退押金的单。前几次退款渠道都回「商户账户余额不足」;财务充了值,再退一次,**还是失败,而这次回的是另一个原因**(比如「原支付渠道已注销」)。研判助手要说出卡在哪、下一步怎么办。

**现状数据**:库里「余额不足」那几张单(如 D2019)三次都是同一个回码,没有一张是「补足后换了原因」的 —— 这一类现在一张都没有,要照 D2019 克隆一张、在最后补一次换了回码的失败。判分器现在对「余额不足」只认「余额不足」这四个字。

| | A(推荐)按最后一次失败定因 | B 新开一类「补足后仍失败」 | C 两个原因都报出来就算对 |
|---|---|---|---|
| 怎么算对 | 说出**最后那次**失败的原因(例:渠道已注销)**并且**说清「余额已经补足、不是卡点了」 | 只要说「补足后仍失败、转人工查渠道」 | 既提余额不足、又提后来的原因,下一步对就算对 |
| 财务看到什么 | 直接知道现在卡在哪,下一步是对的(改走线下打款) | 只知道「还是不行」,要自己去翻轨迹 | 两个原因并列,可能还以为要再充值 |
| 错的时候错成什么样 | 模型照旧说「请充值」→ 判错(这正是要抓的) | 抓不到「停在旧原因上」这个错 | 「请再充值 + 渠道注销」也判对 —— 会放过照着旧原因去做的答复 |
| 出处 | 排障惯例:**以最近一次报错为准**,前面的报错已经被处理过了 | 我的建议,不是惯例 | 我的建议 |
| 代价 | 判分器要新加一支:认「最后的原因」+ 认「余额不是卡点」的说法(不枚举词,查结构) | 最省事,但等于不考定因 | 中等,但判据偏宽 |

**参数(要你定的只有一个)**:「补足了」凭什么认 —— 推荐**看退款轨迹里回码变了**(余额不足之后出现别的回码就算补足过),不另造一笔充值流水。出处:拍脑袋的,依据是轨迹里本来就有回码、不用新加数据。

**怎么验**:照 D2019 克隆 3 张(1 张进示例池、2 张评测),判分器先过人造对照(说「请充值」的要判错、说「渠道注销、余额已不是问题」的要判对),真跑之后把原话钉回对照。
