# 考试记录


## 2026-09-04 · 架构题

**题**:把 `backend/api.py` 那 19 个函数直接搬进 `agentsite/sdk.py`,省掉 MCP 这一层,
系统能不能照跑?会失去什么?

**学员答**:能跑,但会不稳定 —— MCP 是一套完整的接口规范,负责跨系统的信息流转;
没有 MCP 就没有规范,agent 就会不稳定。

**判定:半对。**

- ✅ 「能跑」——对。
- ✅ 「MCP 是规范、负责跨系统信息流转」——对,而且抓到了重点。
- ❌ **「没有 MCP 就没有规范 → agent 不稳定」——因果链不成立。**
  ① 工具的规范来自 **JSON Schema**(每个工具的 `inputSchema`),不来自 MCP 的传输层;
  ② SDK 里「搬进去」的标准做法是 `@tool` + `create_sdk_mcp_server`,
     那是**进程内 MCP**,不是没有 MCP。schema 还在,稳定性不变。
  真正的差别是 **stdio 子进程 vs 进程内**,不是「有 MCP vs 没 MCP」。

**真正失去的四样**:进程隔离(只读保证从结构退化成纪律)· 可挂进 Claude Code ·
通道等价测试失去对象 · 权限没法按服务收。

**薄弱点**:把「协议」和「约束的来源」混为一谈。
建议回炉:MCP 到底管什么、不管什么。

## 2026-09-04 · 找茬题:MCP 管什么

**题**:mcp/protocol.py 这 90 行,七件事里哪些管、哪些不管。

**学员答**:1234567 都管。

**判定:3 对 / 1 半对 / 3 错。**

| # | 事 | 真相 | 学员 |
|---|---|---|---|
| 1 | 报工具清单与参数说明 | ✅ 管(tools/list) | ✅ |
| 2 | 校验参数对不对 | ⚠️ 协议不管,靠 Python 抛 TypeError 兜 | ❌ |
| 3 | 权限(该不该让它调) | ❌ 在 sdk.py 的 allowed_tools | ❌ |
| 4 | 真正查数据库 | ❌ 在 backend/api.py | ❌ |
| 5 | 报错不崩 | ✅ 管(包成 isError) | ✅ |
| 6 | 保证只读 | ❌ MCP 不知道工具是读是写 | ❌ |
| 7 | 让 Claude Code 也能挂 | ✅ 管(标准协议) | ✅ |

**错的三条是同一个错**:把「经过 MCP 的东西」当成「MCP 负责的东西」。
和上一题(以为去掉 MCP 就没规范)是同一个薄弱点的两个面。

**证据**:`grep -c "allowed|permission|readonly|validate" mcp/protocol.py` = **0**;
`grep -c "INSERT|UPDATE|DELETE" backend/api.py` = **0**(只读靠这个,不靠 MCP)。

## 2026-09-08 · 决策题:63% 的「可以做」

**题**:相容矩阵 1274 格的「可以」是没人验证过的(只是没命中禁止规则)。
A 改成未定义 / B 保持「可以」但标注没依据 / C 从矩阵里删掉。选哪个?

**学员答**:选 A —— 没核实就不该给结论,要从业务出发;
**并自己补了「生成待处理文件丢给运营核实后再返回数据」**;
C 也行但下次还要再导入,更依赖线下。

**判定:对,而且补的那半句是这道题真正的好答案。**

- ✅ 抓到了「偏错的代价不对称」:说「可以」赔工期料钱,说「待核实」多打个电话
- ✅ **「待处理文件回流」是让 A 站得住的关键** —— 没有它,A 就是个永远停在「不知道」的系统
- ✅ 对 C 的判断准:删掉之后「这一格没录」和「根本没这个工艺」就分不开了
- ❌ **漏掉一个代价**:实测顾问常问的 56 个组合里 30% 落在这一档,
  每问三次就有一次「待核实」→ 顾问会开始凭经验答 →
  **风险从系统里被赶到人身上,而且从此看不见**
- ⚠️ 量级问题没提:1274 格核不完(一天 10 格要 4 个月),必须**按需触发**

**已按 A + 回流实现**(2026-09-08)。

## 2026-09-08 · 评测题:怎么知道顾问开始绕开系统

**题**:上线两周,①评测集分数 ②待核实队列 ③记录仪,哪个最先露出「顾问在绕开」?

**学员答**:选 ②(解决的消失、没解决的保留);①和③看不出来,
「记录仪看有没有人问,没人问也看不出来」。

**判定:半对,但错的那半很值钱。**

- ✅ **独立识别出「一个指标变好,可能是因为它测的那件事根本没发生」** —— 这是本题核心
- ❌ **陷阱安错了地方**:那是 ② 的陷阱不是 ① 的。
  队列变空有两种解释 —— 都核完了 / 没人问了,**数字上长得一模一样**
- ❌ **③ 判反了**:记录仪要看的不是单条记录是**趋势**(每天调用量、人均频次),
  它比 ② 早,因为②要等队列被核完才显异常,③在第一周就掉
- ❌ **① 失效的真正原因没说到**:评测测的是**模型的回答**,不是**人的行为**。
  改成「待核实」之后评测分数**只会更高** —— 满分,而且没有一个顾问在用

**薄弱点**:质量指标(答得对不对)和采纳指标(人还用不用)没分开。
**越保守的改动,这两个越容易脱钩。**

## 2026-09-09 · 假数据工厂 4 题(决策题,不考实现)

| # | 题 | 判断 | 理由 | 备注 |
|---|---|---|---|---|
| 1 | 「让模型直接生成 10 万条」该不该同意 | ✅ | ⚠️ | 自己想到「数据组合 ≠ 有效数据,系统有自己的规范」—— **含金量高于题目**,但归到了错的选项上(那是绕过业务层的代价,不是产规则的代价);另提出「多个 agent 合作」,已用实例反驳(两个 agent 面对同一份表结构会互相印证同一个错) |
| 2 | 「没主键的表默认不灌」删掉会怎样 | ✅ 会污染 | ⚠️ | 缺「为什么是硬规矩而不是警告」——不可逆的事不能靠"用户看没看警告"把关 |
| 3 | 5 条差集能不能当作全部业务规则 | ✅ 不能 | ❌ | 理由缺席。而这道题考的就是理由:每条都是真的,所以看起来完整;没撞到的**不留痕迹** |
| 4 | 「认出率 93%、0 违规」第一句该问什么 | ✅ 问缺口 | ⚠️ | 问了「没认出的 7%」——而认出率是报告里**唯一自带分母**的数字。真正没分母的是「0 条违规」(断言只有 34 条,另一个库上是 341 条) |

**模式:直觉四道全对,四道的「为什么」都不完整。** 结论对能过原题,说得出机制才迁移得到变体 ——
第 4 题就是第 3 题的变体,他带着直觉去了但没带着机制,于是问到了错的数字上。

**最该回炉:「分母」。** 建议跑「讲讲 分母」。
次之:「不可逆的操作不能只靠警告」「加 agent 加的是意见,加工具加的是事实」。
