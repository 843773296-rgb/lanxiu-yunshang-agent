## 二、本版最重要的一件事:你最硬的那条主张曾经是破的

### 发生了什么

跑三代对比时,V3 的一条轨迹长这样:

```
['ToolSearch', 'Bash', 'Agent', 'ToolSearch', 'get_deposit', ...]
```

**模型自己去开了 Bash 和子智能体。**

### 为什么

`allowed_tools` 管的是「**哪些工具不用逐次批准**」,**不是「只有这些工具存在」**。
配上 `permission_mode="bypassPermissions"` 之后,
Claude Code 的内置工具(Bash / Read / Write / Edit / Task / WebFetch)**一样在场、一样能用**。

### 为什么它一直没被发现

**因为 DeepSeek 那边的模型碰巧没去用。**

> **「模型没用」和「模型不能用」是两回事。安全边界不能建在前者上。**
>
> 这一条比这个 bug 本身重要得多。你这个项目里所有「只读」的说法 ——
> 19 个工具零写接口、truth 表不可查 —— 靠的都是**结构上做不到**,
> 而这一处靠的是**模型碰巧没想到**。它们看起来一样,可靠性差一个量级。

### 怎么修的

两道锁,少一道都不该过:

1. **配置**:`sdk.py` 加 `disallowed_tools`,封死 Bash / Write / Edit / Task 等
2. **运行时**:`guards.py` 的 `PreToolUse` Hook 拦下所有不以 `mcp__` 开头的工具

为什么要两道:**配置能被人删掉、能被改错**,而这条保证太硬,不能只靠一处守着。
`skills_check.py` 加了静态检查(删掉配置立刻红)。

## 三、你的 AI 架构在哪一代

**判定:第三代 Harness(本地支),而且是少见的「三代同仓可比」状态。**

### 1. 三代都在,而且跑同一套评测

大多数项目升代时把旧的删了,从此只能引用别人的数字 ——
而别人的数字是别人的任务、别人的模型、别人的提示词。

**你手上有三套能跑的实现、同一批工具、同一份真值、同一把判分尺子。**

### 2. 对比结果(Claude Haiku,6 条工单)

| 代 | 是什么 | 判对 | 调用/条 | 耗时/条 | **每条工单成本** |
|---|---|---|---|---|---|
| V1 | 手写工具调用循环 | 5/6 | 5.0 | 12.7s | $0.021 |
| **V2** | 工作流编排(路径写死) | **6/6** | **1.0** | **2.9s** | **$0.0012** |
| V3 | Agent Harness | 5/6 | 2.5 | 25.8s | $0.044 |

**V2 比 V3 便宜 36 倍、快 9 倍。** 纯规则模式更极端:**0 次调用、$0、40 条工单 40/40**。

### 3. 但这张表不能读成「二代赢了」——三条限定

**① 这是在 V2 的甜点区测的。** 查数据发现这两类工单的判定**本身就能写死**:
退款真因 ↔ 渠道返回码 6 对 6 零交叉;客户合并真因 ↔ 字段相同性零交叉。
换成工艺顾问问答那种「客户问什么不可枚举」的活,**V2 一条都接不了**。

**② V2 的高分有一部分是「看得少」。** 规则只读三个字段,V1/V3 读完整档案 ——
**看得多就会看到矛盾**。本版那个数据 bug 就是 V1/V3 发现的,V2 压根没走到那儿。**那不是优点。**

**③ V2 的准确率上限 = 规则表的完备度。** 咬合验证:删掉一条规则(TIMEOUT),
24 条里立刻 4 条落到模型兜底。渠道明天加个新返回码,V2 就判不了,而 V3 会自己去查。

### 4. 所以结论是分工,不是选边

| 任务 | 特征 | 交给 |
|---|---|---|
| 退款定因 / 客户合并 | 判定规则已知、高频、要审计 | **V2** |
| 工艺顾问问答 | 客户问什么不可枚举 | **V3** |
| 规则表覆盖不到的工单 | 新返回码、新字段组合 | **V3 兜底** |
| V1 | —— | **对照组**,留着是为了让「升代值不值」有自己的数据 |

### 一个数字仍然在骗你(而且更夸张了)


## 五、评测与检查:本版加了三样

### 1. 钉死的锚点(抓同源谬误)

你的检查里绝大多数**期望值是从被测对象里算出来的**:

```
tool_eval 的锚点   = api.kb_size(...) 现算
guards_test 的数据 = api.kb_bom(...) 现算
parity 比两条通道  = 但两条通道共用同一份实现
```

这买到的是「抗数据漂移,评测不会烂在原地」,**代价正好是抗不住实现错误** ——
`api.py` 算错了,锚点跟着错,**全绿**。

`knowledge/pinned_check.py` 补了 **8 条人从 md 手抄、故意不现算**的锚点。
咬合验证:把推档算错(文档一个字没动),推导器自测**绿**,钉死的锚点**红 2 条**。

### 2. 中文否定与子串统一(七次踩坑收成一处)

原来**四个文件四份词表**(18/20/12/11 个词),每次踩坑只补一份,别的三份继续错。

收进 `agent/textmatch.py`,**七个踩过的坑各钉一条用例**,共 14 条进 CI。

换的过程里挖出一条更深的规则:**中文否定不跨标点**。
「判为同名**不**同人**,**建议不合并」里那个「不」隔着逗号,不是对后面的否定 ——
按字数开窗会扫到它,V2 文本判分从 40/40 掉到 32/40。改成扫到标点为止就回来了。

## 六、本版最该带走的一课:模型答错的四种可能

跑三代对比,**花在跑模型上不到一美元,花在排查上的时间是它的五倍**。
而四次排查,**没有一次的结论是「模型不行」**:

| # | 表面现象 | 真实原因 |
|---|---|---|
| ① | V1 只有 1/6(历史 18/20) | **测量错了** —— 该判结构化结果,我判了自由文本 |
| ② | BP-02 三代全错 | **数据错了** —— 8 对「同一人」里 7 对性别/省市自相矛盾 |
| ③ | 「说对了却判错」 | **诊断脚本错了** —— 「**不**建议合并」含「建议合并」子串 |
| ④ | 模型不会判重复客户 | **没告诉它标准** —— 0/2 → 给了标准 → 2/2 |

第 ④ 条最值钱。模型拒绝合并的理由是:

> 同名、同生日、地址一致「**可能是巧合或亲属关系,不足以认定同一主体**」

**这个谨慎在业务上甚至是对的** —— 合并客户档案是破坏性操作。是我们没告诉它本店的标准。

把标准写进三代的提示词之后:**V1 2/6→5/6,V3 1/6→5/6,BP-02 三条全部翻正。**

> 所以 **V2 在这上面 100%,不是因为工作流架构好,是因为标准写下来了。**

### 排查顺序

```
① 先怀疑测量  → ② 再怀疑数据  → ③ 再怀疑真值
  → ④ 再看有没有给标准  → ⑤ 最后才怀疑模型
```

**直接跳到第 ⑤ 步,结论会是「换个模型试试」—— 而那解决不了上面任何一个。**

## 七、建议你接下来学什么

### 1. 给「工具只读」这条主张做一次完整的边界审计(半天)

本版抓到的那个洞提醒了一件事:**你有很多「保证」,但没有一份清单说明每条保证靠什么成立。**

建议列一张表,每条保证写清楚:靠**结构**(做不到)还是靠**约定**(不该做)?

| 保证 | 靠什么 | 有没有检查守着 |
|---|---|---|
| 19 个工具零写接口 | 结构(代码里没有写语句) | ✅ |
| truth 表不可查 | 结构 + 检查 | ✅ |
| 内置工具不可用 | **配置 + Hook**(本版新加) | ✅ |
| 智能体不改业务数据 | ? | ? |

> 学的是什么:**安全不是「我们不会那么做」,是「那么做会失败」。**
> 一条靠约定守着的保证,迟早会被一个想帮忙的模型绕过去。

一手出处:Anthropic Agent SDK 的权限模型文档
(https://docs.claude.com/en/api/agent-sdk/overview)—— `allowed_tools` /
`disallowed_tools` / `permission_mode` / `can_use_tool` 四者的关系值得读一遍。

### 2. 把识图接进顾问助手(一天)

你已经把模型开关铺好了。下一步是真的接一张图:
「客户发来一张照片,这是什么形制、什么面料?」

做了能学会三件现在碰不到的事:
- **多模态的成本结构** —— 图片 token 比文字贵得多,而且**不能缓存**
- **图片进不进日志** —— 记录仪现在默认不记正文,图片更敏感,这是一道产品决策
- **视觉判断的置信度怎么给** —— 「看起来像香云纱」和「查到的是香云纱」是两回事,
  你的九项体检里现在没有一项管这个

一手出处:Anthropic Vision 文档(https://docs.claude.com/en/docs/build-with-claude/vision)。
