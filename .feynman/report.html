三、你的 prompt 在哪、怎么拼的

位置与成分

agentsite/sdk.py 里两段系统提示词:SYS_KB 1469 字符(11 条铁律)、

SYS_TASK 363 字符(5 条铁律)。全部是固定内容,不随请求变。

动态部分只有两处:

  • 用户的问题
  • UserPromptSubmit Hook 注入的今天日期(guards.py:290)

拼接顺序:对的,而且这一版有实测

固定在前、动态在后,是能命中缓存的顺序。实测数据(triage 表):

缓存命中率 93%

这个数意味着:重复调用时,那 1469 字符的系统提示词和 19 个工具的说明书

基本都走缓存价,而不是原价。

但你有一个数一直在骗你

agentsite/sdk.py 里 cost_of() 那段注释写着实测:

SDK 返回的 total_cost_usd:$0.213
按 DeepSeek 实价算:$0.0089
差 24 倍。

原因是 Agent SDK 的成本是 Claude Code CLI 按 Claude 的价目表算的,

而你把 ANTHROPIC_BASE_URL 指到了 DeepSeek —— CLI 并不知道真实价格。

你自己发现并修了这个(改成按 DeepSeek 价目表重算,含高峰/平峰分时)。

这条值得单独记住:SDK 给你的数字,和你的实际账单是两回事。
任何跨供应商的场景都要先验证一次再用。

四、检索与评测现状

a. 检索:仍然没有用 RAG,而这仍然是对的

你的知识库 165 条工艺 + 2025 格矩阵,全部走结构化查询(SQL + 规则推导),

一个向量都没有。

这一版更进一步证明了这个选择:相容矩阵从 273 格扩到 2025 格,

向量检索能告诉你「哪几条最像」,它没法告诉你「妆花不能用在纱上,依据是 R2」。

五、建议你接下来学什么

1. 把记录仪补到三代那条路径上(半天,必做)

这是本版唯一的退化环,也是最容易补的。

现在 agent/trace.py 只被 agent/v1.py 用。

agentsite/sdk.py 的 run() 已经拿到了 usage、cost_usd、seconds、

guard_violations、answer_turns —— 数据都在手上,只差写一行进 jsonl。

补完之后你能回答现在答不了的三个问题:

  • 顾问助手这两天一共花了多少钱?(现在只有研判和评测有账,对话没有)
  • 哪次调用最慢?为什么?
  • 体检打回率随时间是升是降?
学的是什么:可观测性不会自动跟着架构走。
换一代架构,记录仪要重新接一次 —— 而它不报错,只会安静地停在那一天。

一手出处:Anthropic 官方 Agent SDK 文档的 hooks 一节

(https://docs.claude.com/en/api/agent-sdk/overview)——

PostToolUse 和 Stop 拿到的入参里就有你要记的大部分字段。

2. 把 V2 补上,或者写清楚为什么不补(一天)

你的迭代之路缺中间一段。两条路都可以,但要选一条:

  • 补:用 LangGraph 或 Dify 把「查矩阵 → 查版型 → 算料 → 算工期」写成固定流程, 跑同一套 24 题评测,量出三代的成本/耗时/通过率对照表。
  • 不补:在报告里写清楚「为什么这个业务不适合写死流程」, 用你手上的真实轨迹举证 —— 比如报价单那次调了 7 个工具, 而调用顺序是模型看了前一步结果才决定的,写死流程做不到。
我的建议是补一个最小的。不是为了用它,是为了让「不选它」这句话有证据。
面试时「我试过,不合适,数据在这」比「我判断不合适」强一个量级。

一手出处:LangGraph 官方文档的 StateGraph 一节

(https://langchain-ai.github.io/langgraph/)。

3. 跑一次一代 vs 三代的横向对比(半天)

你手上有两套能跑的实现、同一批工具、同一套评测集。这个对比只有你能做,

因为大多数项目升代时把旧的删了。

量三个数:通过率 / 单次成本 / 单次耗时。

学的是什么:代际选择不是信仰,是一张对照表。
而且你很可能会发现——三代不是每一项都赢,简单问题上一代更便宜更快。
知道自己在哪些场景上亏,才谈得上会用。

附:这个项目做得好的地方

  1. 知识写 md,结论靠推。 2025 格矩阵里 2009 格是推出来的, 改一条规则对全部生效;手写的话改一条只对一条。
  2. 每个检查都做过咬合测试。 改宽 MCP 自测那次,你特意把工具改坏验证它还会红。 一个从没红过的检查,和没有检查是一样的。
  3. 踩的坑都写进了代码注释和检查里。 局部变量遮蔽、运算符优先级、 否定判断(栽过六次)、SDK 成本不可信、设置源污染 —— 每一条都留下了一个不会再犯的检查。
  4. 敢把自己的账不平摊开讲。 get_order 会自查金额勾稽并把对不上的直接标出来。 一个系统敢这么做,才值得信。
