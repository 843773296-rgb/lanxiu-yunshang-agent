# 汉服工艺知识库

给「定制业务协同助手」用的领域知识层。解决的是同一个痛点:
**客户顾问和运营同学不懂汉服**——客人问「香云纱能不能做妆花」「明制马面裙配什么颜色不出错」,
顾问答不上来,只能去问工艺师傅,一来一回两三天,单子就凉了。

## 三级来源标注(全库统一,不许含糊)

每一条知识都必须带一个来源等级。**这是这个库最重要的规矩** ——
知识库最怕的不是内容少,是**真假混在一起而读的人分不出来**。

| 标记 | 含义 | 能不能对客户说 |
|---|---|---|
| `public` | 公开可查,给得出链接(非遗名录、博物馆、标准文件) | 能,可溯源 |
| `scale` | 公开资料里的**量级**,不是本企业实测数据 | 能,但要说明「行业量级,非我司承诺」 |
| `demo` | **演示数据**,为跑通流程虚构 | **不能**。真实项目必须由工艺负责人逐条替换 |

> 本库现阶段:形制、配饰、颜色搭配、工期成本、相容矩阵中的**组合约束**基本为 `demo`;
> 非遗技艺、面料特性中有公开出处的标 `public`。
> **组合约束(什么工艺能上什么面料)属于企业 know-how,没有公开来源,全部是 demo。**

## 和 `craft` 表的关系

后台 `craft` / `craft_combo` 两张表是这个库的**运行时子集**(现有 12 条 + 16 条组合),
供 `kb_search` 工具和知识库页面直接查询。本库是全集,编码互通:

- 表里有的,本库一定有,且编码一致(`KF01` 缂丝、`MT01` 香云纱、`XZ01` 唐制齐胸襦裙……)
- 本库有而表里没有的,是待入库内容
- **同一条知识在两处的来源等级必须一致**,不一致以本库为准

同步方向:`knowledge/*.md`(人维护)→ `backend/seed.py` 的 `CRAFTS` / `COMBO`(机器读)。

## 怎么用

现在是给人看的资料。接入智能体后的定位:

1. **检索层** —— 顾问问「香云纱能不能做妆花」,助手从 `06-相容矩阵.md` 取到「不可」和理由
2. **约束层** —— 客户选了不兼容的组合,下单前拦住,而不是等工艺师傅打回来
3. **报价层** —— 从 `07-工期与成本.md` 估出工期和成本档,给客户一个有依据的区间

**注意第 2 条不是靠提示词求模型记住,而是要做成硬约束** ——
参见 `本期交付说明.md` 关于「Tool 与 Hook 分工」的部分。
